# ADR-003：RenderPlan 图层路径顺序语义

## 状态

已采用，适用于当前技术验证协议和后续 Photoshop 执行适配器。

## 日期

2026-08-23

## 背景

PSD 审计工具生成的图层路径按同级图层的 PSD 底部到顶部顺序编号。Photoshop UXP DOM 的 `document.layers` 和组内 `layers` 则按顶部到底部暴露。`0.2.0` 直接把审计路径 `2` 当作 UXP 数组下标，实机因此选中非智能对象并在变更前安全中止。

图层路径属于渲染器中立 `RenderPlan` 的跨适配器契约。如果路径的顺序语义依靠某个执行器猜测，同一计划会在 UXP、JSX 或未来独立 PSD 适配器中指向不同图层，存在误改固定图层的风险。

## 决策

1. `RenderPlan` 中每个校准目标必须显式携带 `target.layer_path_order`。
2. 当前 PSD 审计路径的规范值为 `psd_bottom_to_top`；`layer_path` 的每一段都按其同级集合从底部到顶部编号。
3. UXP 适配器在每一级使用 `uxpIndex = collection.length - 1 - psdIndex` 转换后再进入下一层。
4. 执行器遇到缺失或不支持的顺序语义必须拒绝计划，不得猜测或默认按本地数组下标执行。
5. 变更前继续校验预期图层类型、可见性、注册框和结构证据。图层名称只作为审计交叉检查；名称不匹配时安全中止，不以名称单独建立绑定。
6. 以后增加图层唯一 ID 或结构签名时，只能增强绑定证据，不得静默改变已有路径的顺序含义。

## 影响

- `0.2.0` 及更早未声明 `layer_path_order` 的变更计划不得继续用于执行；需要重新生成或迁移。
- 路径顺序成为协议数据，而不是 UXP 私有实现细节，因此仍保持 `RenderPlan` 的渲染器中立边界。
- 单框 `0.2.1` 会记录 PSD 下标、转换后的 UXP 下标、图层 ID、名称和类型，便于复现实机差异。
- 该修复只解决目标图层解析，不代表智能对象替换、变换、JPG/PSD 导出或视觉结果已经通过。
