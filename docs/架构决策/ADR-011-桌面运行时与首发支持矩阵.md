# ADR-011：桌面运行时与首发支持矩阵

## 状态

已批准并冻结架构方向；代表机和客户机验证仍由 `UI-01`、`INSTALL-01` 完成。本文不把未执行的兼容性测试写成通过。

## 日期

2026-08-27

## 背景

V1 需要一个能稳定承载 Windows 文件系统、长任务界面、UI Automation、凭据、进程控制和高保真桌面界面的运行时。产品首发范围已经收窄为 Windows 11 x64 与 Photoshop 2025 `26.8.1`，但不能用版本字符串代替逐机能力探针。

## 决策

1. 桌面端采用 WPF，目标运行时为 `.NET 10 x64` 自包含部署。
2. V1 首发支持矩阵只包含 Windows 11 x64 与 Photoshop 2025 `26.8.1`；客户机必须记录完整 Photoshop 构建号并通过安装、权限、UXP bridge、单框替换、ICC、断线和恢复探针。
3. Windows 10、Photoshop 2022/2023/2024、其他 Photoshop 补丁构建和非官方精简/修改安装不属于 V1 首发承诺。未来扩展必须补齐同等级证据并更新产品基线及 ADR。
4. WPF Presentation 只能依赖 Application ports 和只读投影；Domain 不得引用 WPF、Photoshop、UXP、HTTP 或 SQLite 类型。
5. 阶段 0 验证门包括：`.NET 10` 启动、100%/125% DPI、中文 IME、键盘与 UIA、1100x760 窄窗、当前用户安装、单实例和 Photoshop 连接。任一关键门失败时暂停发布，不通过降低 UI 或数据要求收口。

## 候选与取舍

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| WPF + .NET 10 | Windows 原生能力、文件/进程/UIA 成熟，LTS 生命周期适合新 V1 | 高保真控件和窄窗需要自建验证 | **采用** |
| WPF + .NET 8 | 现有依赖迁移成本较低 | 新项目生命周期更短，形成运行时迁移债务 | 仅在 .NET 10 关键依赖验证失败时重新评估 |
| WinUI 3 | 视觉 API 新 | 外部目录、部署、UXP/Photoshop 集成和兼容矩阵复杂 | 不作为 V1 默认运行时 |

## 影响

- 需要把 .NET 10、Windows 11、Photoshop 精确构建和 UXP manifest/protocol 版本写入诊断与安装 manifest。
- 不提供运行时自动降级或把未探针通过的 Photoshop 标为可生产。
- WPF 只负责桌面交互，不承载 AI 规则和 Photoshop 执行动作。

## 退出条件

只有在出现可重复的 .NET 10 关键阻断，并形成新的 ADR、保留相同产品验收标准时，才可重新评估运行时。任何未验证即交付均不允许。
