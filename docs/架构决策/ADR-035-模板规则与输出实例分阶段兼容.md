# ADR-035：模板规则与输出实例分阶段兼容

日期：2026-09-28；更新：2026-09-30。状态：TPL-02 E3 正式生产接入已有源码及离线验证；未关闭真实F或TPL-02整项。当前版本/证据见本文末节与本轮报告。下文 B/E0/E1/E2 是分阶段历史约束，不表示当前生产入口仍未接通。

## 原因与范围

## 2026-09-30 E3 实施决策（实施中，不代表验收）

- 范围：TPL02-P01/P02/R06/D02/S01/UI06。沿用正式批次、AI 持久化事实、E0/E1/E2、Coordinator、Bridge 和文件提交/公开发布；不创建第二执行协议。真实 AI、Photoshop、插件安装与正式数据库升级不在本次操作范围。
- 新规则批次使用显式版本化模板上下文，与旧 `BatchTemplateSnapshot` 分流；旧 Create/Replace 的 `TPL_RULE_INSTANCE_PIPELINE_REQUIRED` 保持。生产授权必须来自仓储中的批次、款式、已提交修订和登记素材，调用方 Scope 不是授权。全规则集合展开，不通过伪造旧快照裁剪规则。
- E0/E1 的身份、摘要、首次冻结 CAS 和 CommandId 字节含义不变。另行冻结生产准备证据（几何、人工版本、尺码来源/数据/校准/栅格），恢复只消费冻结正文；已冻结批次事实变化拒绝，要求新批次，不静默重冻。
- 单页 RenderPlan 保持 `render-plan/v1`，实例扩展由 `template/page-instance-identity-v1` 显式协商。Schema、.NET 和 JS 必须验证同一实例/来源页/槽/框/素材闭合；无字段但声明能力及有字段但未声明均拒绝。旧执行端在投递前拒绝，不解释配方循环。
- 来源 PageId 不改，PageInstanceId 独立。计划、journal、Bridge 记录、checkpoint、manifest、发布和结果页须核对实例及计划摘要；attempt 仅用于明确失败后的本实例重试。ExecutionId 只由原 broker 创建并先持久化，恢复按既有幂等键查询，不重新分配。
- 新持久化格式必须显式识别，旧格式不补写实例字段或改变摘要；未知版本拒绝。SQLite 仅从当前 v23 追加 migration，不改历史 SQL/checksum，不操作用户正式库。文件与 SQLite 仍走 Verified/marker/Committed 的可恢复双提交，而非伪跨介质事务。
- 已确认业务红实例保留占位；能力缺口、篡改和资源完整性错误不能降级为红页。全批分析/准备完成前不启队列；CanContinue 不是执行授权。零输出区分空展开、业务阻断、取消和系统故障，CompletedWithIssues 必须有独立核验成功输出。
- 公开名称保持页码/页面名/必要变体名，重复实例增加稳定可读序号；内部技术身份不替代用户命名。Committed 独立核验后跳过；Unknown 只查询；公开提交失败只恢复发布。源文件、旧输出、配对/认证/租约和单通道边界保持。
- 实际落地的版本、迁移、调用链和未完成项以本次验证记录为准；本节是编辑前决策，不因条目存在宣称 E3、F、TPL-02 或 INSTALL-01 已完成。

依据 TPL-02 §4～7，图片框数不等于颜色数，同 PSD 可产生多个输出实例。旧 `GenerationMode` / `VariantCapacity`、自由文本和单个 `OutputVariantId` 无法完整表达新规则，不能仅删校验或把所有页面锁成一种颜色。本决策延续 ADR-010/012/018/031/034，不改其已冻结历史含义。

### 2026-10-07：正文首次填写候选框（用户批准）

结构/可见像素准入的尚未填规则目标可提前预留稳定 alias，但 alias 不等于生产 `FrameBinding`，不保存空规则或占位资产。预留复用原命令 writer/CAS，以无 applied/inverse 的系统收据保存，不成为用户撤销步骤；已提交修订不预留新目标。原参考学习的目标身份算法保持，已有绑定/旧身份不重写。

文字 AI 可以回填已声明候选的选图要求；未明确目标须澄清。首次登记的 layer/path/signature/layout 全由 Application 的当前 PSD 检查事实构造，与描述/可选编排补丁一次事务提交；AI 不提供坐标或资产。接口中的新目标补丁必须匹配当前合格候选，既有 writer/undo 只移除该次添加且拒绝覆盖后续手工修改。Prompt v3 分离缓存，结果 Schema/迁移/RenderPlan/Bridge/E 身份不变；未知请求仍被原持久化预算门阻止重投。证据见 `docs/验证/TPL-02-正文首次填写真实候选框-20261007.md`。

- `TemplateRevision` / `TemplatePage` / `FrameBinding` 继续拥有页面、图层证据、布局和开放式选图语义。新规则只引用 `PageId` / `FrameId`，不复制描述、PSD 内容或源图片。
- `TemplateRuleSet` 拥有条件分支、配方、颜色槽和框到颜色槽的绑定。框语义仍来自对应 `FrameBinding.SelectionRequirement`。同色正反两个框引用同一槽，不把两框算成两个颜色。
- 本切片输入既有修订，输出不可变演算结果。新类型暂未挂入修订存储，不自动把旧备注/容量转为新规则。不存在新规则的旧模板继续走原链路。
- 卡片规则、总规则、总览以后共同编辑/读取该聚合。显示别名和视图状态不进入执行事实；原话/来源不是可绕过校验的第二执行规则。

## B1 有界表达与演算

- 条件：颜色数量闭区间 + 任意/奇数/偶数。每次演算必须恰好命中一个分支；未覆盖和重叠均诊断，不隐含优先级。
- 配方：每款一次，或将显式范围（全部颜色/仅副色）按分配槽数分组。配方数组为输出顺序；分配槽顺序为组内颜色顺序。
- 槽来源：主色、唯一副色、当前分组分配。多个副色遇“唯一副色”返回歧义，不取第一个；明确遍历副色时使用分组分配槽。模板规则不绑定某款瞬时 `VariantId`。
- 分组只消费已冻结的颜色顺序，把主色置前，其余保留输入顺序；不随机、不重新按颜色名排序。分组不确定、主色缺失/无效、重复颜色 ID 均阻断。
- 不足一组不能悄悄丢颜色；显式预计次数与计算次数冲突时阻断。覆盖无重复约束按颜色槽计算，不按框数计算。
- 规则错误返回带分支/配方/页面/框身份的诊断，整个演算不返回伪可执行的部分计划。缺素材的逐实例隔离属于 E 的选图阶段，不以此全局规则错误替代。
- 动态尺码配方可以无颜色槽且每款一次；模板规则验证不接收目标款素材。它不证明尺码模板结构已校准，也不生成/猜测尺码数据；继续由既有模板结构和生产尺码链分别验证。
- 演算结果只含逻辑实例键、页引用、颜色分配和由绑定派生的框颜色要求，不含 `AssetId`、可投递 RenderPlan 或随机执行 ID。
- 总展开上限为 10,000 个实例，超出明确诊断且不返回截断计划；这是内存/循环安全门，不是已验收的工作台或出图性能承诺。

## 逻辑实例与执行身份

`(冻结规则快照, BranchId, RecipeId, RepetitionIndex)` 唯一定位一次配方展开；同 PSD 不同配方或重复次数不得相互覆盖。领域键不是全局执行 ID，也不是 `OutputVariantId`。批次/款式/冻结快照/真实资产/计划 digest 的绑定由 E 在持久化时形成。

当前 checkpoint 使用 `(task_id, style_id, page_id, output_variant_id, attempt)`。多色拼版不能给 `output_variant_id` 填虚构颜色，同 PSD 多实例不能复用此键。E 接入前必须逐项审计并设计版本化实例映射，覆盖账本、manifest、文件名、计数、预览和发布；完成前保持新规则不可进入旧出图入口。renderer-neutral 单页 RenderPlan 不承载循环或自然语言，旧执行/Unknown/Committed 恢复规则不变。

## B2 原始落地约束（2026-09-28；当前代码证据见任务 §13）

1. 每修订一份版本化规则载荷，补丁同时携带 `CommandId` / `ExpectedDraftVersion`，由既有 writer 事务写规则、框变化、alias、版本和命令结果。CommandId 同内容幂等，异内容冲突；总确认绑定 DraftVersion 与完整 RuleDigest。
2. 页面/框 alias 单调分配、删除保留失效身份、不复用；排序不重编号。人类 @ 引用先解析为稳定 ID，AI 不允许任意 ID 或扩大目标范围。撤销是新版本补丁，不回拨版本号。
3. 权威规则 JSON 必须严格字段/枚举/数量/版本校验。引用影响查询投影同事务维护；不建与规则 JSON 独立可编辑的镜像。旧 schema 不存入新规则，新客户端不从 Notes 猜规则。
4. 业务 digest 覆盖结构绑定、选图语义、条件、配方和顺序；不含窗口尺寸、滚动、alias 展示、绝对路径。新规则使用显式新摘要版本，不回写旧 revision/snapshot/manifest 摘要。
5. 设计时迁移基线为 v21；2026-09-30 当前工作树已有 B2 v22。后续只能追加并复核实际最新编号，不先预留或修改旧 migration/checksum。隔离数据库副本测试事务失败、CAS、升级中断及重启；E0 不修改 migration 或触碰正式库。
6. `template-package/v1/v2` 不加入新规则且不借 Notes 偷运。新规则包需新版本、严格 schema、规则/框/alias 引用完整重映射、新本地身份及旧客户端明确拒绝。精确合同与兼容测试完成前，不开放新规则导出/另存为。

### E3 实例人工选图补充决定（2026-09-30，实施前）

正式 AI 复核页的选图先读取真实批次/修订/已落库分析，显示明确实例列表，再保存 `(PageInstanceId, SourcePageId, Branch/Recipe/Repetition, FrameId)` 人工锁；不得将旧框级锁复制到多个实例。追加 v26 保存版本化、带摘要的实例选图状态，使用款级 revision CAS；绑定未覆盖前事实摘要，分析事实变化须拒绝并新建批次，不重新解释旧锁。E3 证据冻结事务复核人工选图 revision；冻结后仓储层也拒绝改变锁。E0/E1 的身份、摘要与命令含义不变。选择预览不冻结、不建计划、不生成尺码栅格；正式生成仍由原 workflow 收口。UI 必须明确确认具体实例，结果页继续只消费已冻结计划。

E3 journal v4 另持久化每款 `InstanceSets`，保存 E2 结果的显式 schema、完整成员 BatchPlanDigest 与批次 InputFactsDigest。登记和读取从冻结事实重算核对；追加 attempt 不改首次集合摘要，后续计划按既有事实等价/attempt ancestry 验证。集合摘要不反向写入单页计划，避免“集合摘要包含 PlanDigest，而计划又包含集合摘要”的循环；Bridge/提交以单页 PlanDigest 和完整实例 provenance 连接这一登记根。

## 2026-09-30 E0：确定性实例投影与 Application 预检

### 范围与输入边界

- `TemplateInstanceProjector.Project` 为纯函数式 Application 入口，复用 B1 求值器、B2 严格载荷与 `BusinessDigest`。没有仓储、AI、文件访问、时钟、随机 ID、生产 DI/UI 调用或渲染依赖。
- 输入为 `TemplateInstanceProjectionRequest`：`TemplateInstanceScope` + 已提交 `TemplateRevision` + 不可变 `TemplateInstanceInputFacts`。规则唯一来源仍是 `Revision.RuleWorkspace.Rules`，不能另传一份规则覆盖修订。
- Scope 的 `BatchId/StyleId/SnapshotId/RevisionId/RuleDigest` 是调用方提供的 E0 预检作用域。E0 核对 ID、Committed 状态、正版本规则载荷，以及 scope/revision/重算业务摘要三方一致；**不声称该 SnapshotId 已存在于数据库或已获生产授权**。它不是 `BatchTemplateSnapshot`，也不经 `Restore` 绕门。全规则集演算，不引入未定义的选页裁剪。
- Facts 包含正版本号、明确冻结颜色顺序/主色/分组确定性、既有 `SourceAssetMetadata`、颜色到资产集合、`(FrameId, VariantId) → AssetId` 的已选证据，以及实例级人工覆盖。无资产的已知颜色允许空集合；不会把缺图颜色从规则输入中删掉。
- E0 不调用 AI、不重新排序候选、不从“正面/反面/副色”文本猜语义。上游提供的每框已选证据仍须由后续生产适配验证来源；E0 只核对引用、款式与颜色归属。图像内容准确率、磁盘实际存在性、参考素材隔离、布局几何及模板结构的生产校验不由本合同替代。

### 输出与身份

- `TemplateInstanceProjection` 保存 `PageInstanceId`、Batch/Style/Snapshot/Revision ID、RuleDigest、InputFactsDigest、SourcePageId、TemplateResourceId、BranchId、RecipeId、RepetitionIndex、Order、槽→VariantId、框→槽→VariantId/最终 AssetId/SelectionRevision、状态及带框/颜色/资产的阻断原因。
- 所有集合使用 `ImmutableArray`；不复制框选图语义的权威定义。多 PSD 由 SourcePageId→TemplateResourceId 追溯；同 PSD 不同页面/配方/重复位置各自产生实例。`Order` 与 `RepetitionIndex` 从 0 开始，输出顺序严格沿用配方数组顺序及其重复顺序，不按源页面、颜色名或 alias 再排序。
- `PageInstanceId = instance_ + SHA256(固定命名字段 JSON 的 UTF-8 字节)`，保留完整 64 位十六进制摘要。前像包含 `template-instance-identity/v1`、BatchId、StyleId、SnapshotId、RevisionId、RuleDigest、冻结颜色事实摘要、SourcePageId、BranchId、RecipeId、RepetitionIndex。命名字段编码避免分隔符拼接歧义；不使用随机数、时钟、alias 或 OutputVariantId。
- 颜色摘要使用 `template-instance-colors/v1` + 原始冻结颜色序列/主色/分组状态。颜色顺序改变属于新事实，不能在恢复中自行重排。
- `InputFactsDigest` 使用 `template-instance-input/v1`，覆盖 Facts.Version、颜色事实、资产 ID/所属款/hash/长度/尺寸/格式/MIME/可读性、颜色资产成员、选图以及实例人工覆盖和 SelectionRevision。无序集合按 ordinal 稳定排序后编码，保留有业务含义的颜色顺序；不含源路径、文件显示名和 alias。
- **逻辑身份与选图事实分离**：补图、选择变化、人工覆盖变化改变 InputFactsDigest，不重分配同一冻结逻辑位置的 PageInstanceId。RuleDigest、作用域或颜色事实变化则生成不同身份。E0 ID 不是 plan/idempotency/bridge execution ID；E1 必须持久化并验证事实绑定，不能凭同一逻辑 ID 覆盖执行内容，也不能在恢复时重新生成身份替换已有记录。

### 预检规则和 fail-closed

1. 规则冲突、未覆盖、颜色未解析、无效主色等复用求值器诊断，结果为 `Rejected`，Instances 为空且不返回有效 InputFactsDigest；不泄漏先前成功展开的部分实例。
2. 重复资产/选图/人工目标、跨款库存、未知引用、颜色资产多重归属、过期实例或非法覆盖版本属于输入合同错误，同样整组拒绝，不去重猜测或忽略迟到覆盖。
3. 缺少 `(FrameId, VariantId)` 选图只产生对应实例的 `TPL_INSTANCE_SELECTION_MISSING`；不会取主色/第一个副色回填。正常实例保留，业务阻断实例不消失。
4. 人工覆盖必须命中 `(SourcePageId, BranchId, RecipeId, RepetitionIndex, FrameId)`，且 SelectionRevision > 0。覆盖优先于默认证据；如果不属于实例颜色，阻断该实例并返回 `TPL_INSTANCE_ASSET_VARIANT_MISMATCH`，不悄悄退回默认图。无效选图的输出 AssetId 为空，原请求资产保留在诊断中。
5. 正反框分别使用各自 FrameId 的已选证据，但颜色均来自同一已分配槽；不能跨实例共享一个人工锁定。多色同页仍按各自槽绑定，不伪造单一输出颜色。
6. 合法零次循环返回 `Empty` + 有效事实摘要，与 `Rejected`、全部实例 `BusinessBlocked` 分开。不得由空列表推断任务完成。
7. 普通页通过仅为 `AssetBindingsSatisfied`，**不是 CanGenerate/ReadyToRender**；动态尺码实例始终带 `TPL_INSTANCE_SIZE_VALIDATION_REQUIRED`，在无其他错误时为 `RequiresProductionValidation`，不猜尺码、生成栅格或宣称校准完成。
8. E0 对颜色/资产/成员关系/选图/覆盖输入做 10,000 项级内存准入；规则沿用既有严格载荷上限和求值器 10,000 实例门。这不是 200 款或生产吞吐验收承诺。

### E2 第二段纠正：业务红页隔离与完整成员 v2（2026-09-30）

- `IntegrityError` 是诊断默认分类：E1 正文/摘要、规则/事实摘要、身份或资源内容冲突、跨 Batch/Style/Revision、漏冻结成员、传入素材/绑定与冻结事实不一致、未知原因和无法安全分类的错误仍整批 `Blocked`。Plans 为空，BatchPlanDigest/InputFactsDigest 为 null，CanContinue/HasCompleteMembership 均为 false；可返回已验证正文中的已知成员，但不宣称其为完整可信集合。
