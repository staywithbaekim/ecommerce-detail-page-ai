# ADR-036：真实像素图片位与执行能力兼容

日期：2026-10-11。状态：用户批准实施；独立像素图片位首链路已有源码、离线回归及真实 PSD 只读检测证据，真实 Photoshop 输出与完整通用验收开放。

## 原因

商品图片位不能由“是否智能对象”单独决定。任务依据为 TPL-02 真实图片位补充任务书；客户流程不增加转换模板、画框或逐层确认。用户明确拒绝 JPG-only 新增临时验证 PSD，以及生产重新解析模板找框。

## 最小决策

- 在既有绑定增加 `TemplateLayerKind.Pixel`，保留原始图层身份、路径和最终显示窗口。像素候选依赖可见合成贡献与有界照片内容证据，不按文件名、图层名、固定 ID 或坐标判断。
- 当前内容证据是保守摄影纹理启发式，不等于业务商品语义已闭合；合并文字背景、多区域、多层组合及蒙版仍需单独验证。
- `RenderPlan` 仍 renderer-neutral。Pixel 只在 `ordinary_set`、显式 placement 与 `image-layer/replace-v1` 同时存在时准入，不向合同传递 Photoshop 命令。
- 正式 UXP 按保存路径定位指定像素层，在受控内存文档内准备可替换内容并复用既有替换/定位。原始文件不修改；剪贴或其他保护关系不能闭合就失败，不扩大允许差异掩盖破坏。
- JPG-only 复用现有目标检查和 JPG 导出，不导出验证 PSD、不全量重读非目标描述符。客户主动选择 PSD 输出时沿用既有独立结构/内容验证，仅允许指定 Pixel 目标转换为已嵌入实际照片的智能对象。

## 兼容与缓存

- SQLite 无新迁移；binding JSON 仅 Pixel 写入可选 Kind，旧 SmartObject 默认值与身份语义不变。已冻结规则/快照、计划、checkpoint、manifest 不重写。
- `psd-inspection/v1` 增加可选 `raster_image` 证据。旧响应仍可读取，但不能授权像素替换。工作台/导入复用阶段发现缺失证据时，在应用自有 PSD 上升级一次，不在生产触发。
- 缓存升级只补齐旧像素层的派生像素证据；事务比较预期资源，保护 ResourceId、路径、hash/长度、结构、创建时间、原预览及已有更强 content evidence。digest 大小写/`sha256:` 表示差异不冒充内容变化。并发同结果可复用，不同结果拒绝覆盖。未包含新证据的旧 worker 明确失败，不重复循环解析。
- 只有含 Pixel 绑定的模板包采用 `template-package/v4`。旧 v1/v2/v3 保持读取；SmartObject 导出仍为 v3，剥离新增 raster 证据以保持冻结 schema。Pixel 包不能降级为 v3。
- Bridge 只有含 Pixel 目标的批次声明新能力；旧 base/instance 能力组合和认证 golden 保持，旧适配器不得被当作支持 Pixel。

## 验证边界

### 2026-10-12：覆盖栈兼容补充（实施中）

K08实机返回证明，只替换栈顶Pixel会令同窗口下方原零贡献照片重新露出。准备阶段将连续下方、同显式剪贴基底、覆盖窗口、具有嵌入照片身份且原仅0/1px贡献的旧层写入既有SupersededLayers；独立图片、调整/装饰、链接、蒙版或未闭合证据不折叠。应用层作映射，UXP只执行声明的可见性变化。

原Pixel计划schema明确要求superseded_layers为空，不能仅改adapter绕过。最小演进为 `image-layer/covered-stack-v1`：只有Pixel带非空旧层的计划/批次要求该能力，同时保留replace-v1/absolute-placement；新adapter明确声明支持，缺能力旧adapter在认证/计划准入即拒绝。仍使用render-plan/v1的既有旧层字段，无新命令、SQLite迁移、AI结果、checkpoint/manifest/bridge wire字段；旧无栈Pixel与SmartObject/instance组合不变。既有冻结修订/Unknown计划不改，不为JPG-only增加验证PSD。必须同步schema、builder、validator、批次能力协商与adapter并验证；此补充不关闭残留/完整实机门。

详细客户样本检测与耗时记录保留在本机受控材料中，不纳入共享提交。构建、fixture、真实 PSD 检测都不代替 Photoshop/视觉/性能验收。参考学习的像素照片对应关系不能伪造为嵌入文件 hash 完全匹配，仍待接通；本 ADR 不宣称任意 PSD 自动无损替换。
