# ADR-005：替换栈逐层结构契约

## 状态

已采用，适用于整款 RenderPlan 和后续模板校准数据。

## 日期

2026-08-24

## 背景

真实 PSD 中，同一图片框可能由多个重叠智能对象形成替换栈。此前 RenderPlan 只记录 `superseded_paths`，UXP 适配器把所有下层智能对象统一假定为剪贴层。

`G-详情-01.psd` 的同哈希本地结构报告和 Photoshop `0.4.4` 实机预检共同证明：目标 `front_main` 位于路径 `3`，被覆盖的下层智能对象位于路径 `2`，两者都可见且 `clipping: false`。统一要求下层图层 `clipping: true` 会把正确模板误判为结构损坏。直接删除剪贴检查又会失去对其他复杂模板的保护。

## 决策

1. 整款 RenderPlan 使用 `target.superseded_layers`，每个下层替换栈图层独立记录 `layer_path`、`layer_path_order`、`expected_kind`、`expected_visible` 和 `expected_clipping`。
2. UXP 适配器必须在首个图片替换前逐层解析并核对这些字段。路径、类型、可见性或剪贴状态任一不符即安全中止，并返回期望值和实际值。
3. 整款模式拒绝旧的纯路径 `superseded_paths`，避免路径列表与结构期望并存时产生冲突。已经关闭验证的单框和四框夹具可继续由兼容层把旧路径解释为“可见剪贴智能对象”，不回写其历史协议。
4. 第一组整款样本共记录 14 个下层替换栈图层。只有 `G-详情-01.frame-3` 的路径 `2` 明确为非剪贴；其余 13 个继续明确要求剪贴。
5. 图层名称仍只用于审计交叉检查，不用于决定是否为商品替换位。
6. 结构合同来自模板校准和只读结构证据，不由执行器按模板名称猜测。

## 影响

- 该变更没有放宽安全门控，而是把统一假设改为逐模板、逐图层的确定性校准。
- 新模板校准数据必须携带完整替换栈结构；未来 UXP、JSX 或独立 PSD 适配器读取同一合同。
- `0.4.5` 是首个采用该合同的整款验证构建。`0.4.4` 及更早整款计划不再继续执行。
- 结构不一致仍发生在任何替换前，因此不会为了兼容模板而冒险修改固定内容。
