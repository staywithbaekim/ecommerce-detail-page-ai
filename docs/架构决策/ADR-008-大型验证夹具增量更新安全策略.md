# ADR-008：大型验证夹具增量更新安全策略

## 状态

已采用。

## 日期

2026-08-24

## 背景

TV-13 `0.4.7` 增量更新已经完成插件、计划和校验文件复制后，更新器为了让目录名匹配插件版本而移动整个约 421 MB 的整款 fixture。旧 CHECK/VERIFY 窗口仍占用 fixture，Windows 在移动过程中拒绝删除源目录，留下 `0.4.6` 与 `0.4.7` 两个部分目录。受保护的模板、源图和人工参考未被修改，但交付步骤产生了没有业务价值的恢复成本。

## 决策

1. 增量更新不得移动或重命名包含 PSD、源图或人工参考的 fixture 根目录；目录名不作为实际插件版本依据。
2. 包修订号与插件版本分离。`0.4.7.1` 表示更新器修订，插件、面板和 evidence 版本仍为已验证的 `0.4.7`。
3. 更新器必须接受正常旧版本和已经写入部分新文件的状态，重复运行后收敛到同一结果。
4. 只允许写入明确列出的插件文件、TV-13 计划/校验文件和 README；不得写入 `template`、`source` 或 `reference`。
5. 更新前后对 `template`、`source`、`reference` 全树比较相对路径、长度和 SHA-256。
6. TV-13 输出目录非空时拒绝更新并保留原内容，不自动清理未知文件。
7. manifest 最后写入并作为提交标记；失败提示只承诺输入未删除或覆盖，不虚构完整事务回滚。

## 验证

- `0.4.7.1` 在完整 `0.4.6` 上原地升级通过，根目录名保持不变。
- 对完整结果重复执行通过。
- 模拟插件已被移动、fixture 已含 TV-13 文件的半更新状态后恢复通过。
- 非空输出目录被拒绝，哨兵文件保持。
- 三个受保护目录全树哈希在所有路径中保持不变。
- ZIP 不含 PSD/JPG/PNG，Windows PowerShell 5.1 语法和 ZIP 回环通过。

## 影响

- TV-13 实机 evidence 已由插件 `0.4.7` 完成，不需要为了更新器修复重新执行 Photoshop 测试。
- 后续大型 fixture 的小型更新包沿用原地、白名单、可重复执行的交付方式。
- 版本显示以 manifest、自动 evidence 和诊断记录为准，不再通过大目录重命名表达版本。
