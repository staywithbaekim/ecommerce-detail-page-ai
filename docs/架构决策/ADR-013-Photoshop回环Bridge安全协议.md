# ADR-013：Photoshop 回环 bridge 安全协议

## 状态

已批准并冻结 `ps-bridge/v1` 协议边界；UXP 受保护存储、正式 `.ccx` 权限、端口占用和逐机行为仍由 `INSTALL-01`、`RENDER-01` 与 Photoshop 实机验证。

## 日期

2026-08-27

## 背景

桌面端和 UXP 需要在同一台电脑上交换 RenderPlan、进度和恢复查询。仅依赖固定端口、plugin ID 或版本字符串会允许本机其他进程伪造服务，也无法安全处理断线和重复提交。

## 决策

1. bridge 使用仅监听 `127.0.0.1` 的 HTTP；不接受远程网卡、局域网或公网连接。
2. 使用两阶段端口：固定 rendezvous 端口只做发现/握手，延续已验证的 `17842`；握手成功后返回随机高位执行端口，RenderPlan、执行查询、心跳和释放只走该端口。端口占用安全失败，不扫描或连接未知本机服务。
3. 每个安装建立随机 `pairing_secret`：桌面端存 Windows Credential Manager，UXP 端存 Photoshop 受保护存储。共享秘密不得进入代码、manifest、普通文件、模板包、日志或诊断包。
4. 握手挑战使用一次性 32 字节 nonce。UXP 计算 `HMAC-SHA-256(pairing_secret, nonce || session_id || plugin_manifest_version || photoshop_build)`；验证通过后才签发执行会话 token。
5. session token 绑定单任务、单 Photoshop 实例和单 manifest/protocol 版本；默认 15 分钟无活动失效，心跳只可在仍满足绑定条件时续期，绝对最长 8 小时。释放、超时、应用重启、Photoshop/插件实例变化或版本不匹配立即失效。
6. 所有非握手请求携带 `protocol_version、request_id、correlation_id、session_id、token、sent_at、idempotency_key、payload`。普通请求/响应最大 1 MiB，`/plans` 最大 8 MiB，心跳和状态查询最大 256 KiB。超限直接拒绝，不截断解析。
7. `/plans` 只接收已经通过 RenderPlan Schema 的计划和 adapter 私有资源/输出绑定。绑定使用不透明 session handle、用途、内容 hash 和只读属性，不把真实路径或 token 回写 RenderPlan。
8. 事件使用严格递增 `event_seq` 和唯一 `event_id`；重复请求返回同一执行结果，不能因重试再次替换或导出。未知执行结果先查询 `/executions/{id}`，不得盲目重提。
9. 未知 Photoshop 弹窗由桌面端暂停并要求用户处理；bridge 不模拟点击，也不把“连接正常”当作“可生产”。
10. 如果正式 UXP 受保护存储无法可靠建立，唯一回退是 F-01 已批准的一次性、短时有效、使用后失效的人工配对码；不得发布无认证握手。

## 端点边界

2026-09-21 本地资源实现澄清：Windows 打包启动器可能把 LocalAppData 映射到包私有缓存，逻辑路径与文件句柄最终路径不同且没有 reparse point。已打开文件仍优先精确匹配；不一致时，只允许通过已批准父目录的 OS 句柄解析规范父路径，在保持父目录不可删除共享期间要求完整父路径及叶文件名一致，并复核本地路径和所有祖先无 reparse point。不同目录同名文件、不同叶名继续拒绝，长度/hash/用途/会话绑定不变，不使用包路径白名单或根目录替换。校验失败释放此前所有已打开资源；不能确认提交结果时保持 Unknown。见 [原生动态验证](../验证/RENDER-01-S6原生动态尺码流程-20260921.md)。此澄清不改变 wire 合同或授权范围。

| 方法/路径 | 语义 | 超时 | 幂等 |
| --- | --- | ---: | --- |
| `POST /handshake` | nonce 挑战、能力和版本协商 | 5 秒客户端 / 10 秒服务端 | nonce 一次性，失败不重放 |
| `POST /plans` | 提交单页或单款计划 | 10 秒接收；执行异步返回 | `idempotency_key + plan_digest` |
| `GET /executions/{id}` | 断线查询执行状态和事件 | 5 秒 | 只读 |
| `POST /executions/{id}/cancel` | 请求安全边界取消 | 5 秒 | execution 级重复安全 |
| `POST /heartbeat` | 报告宿主、modal 和事件状态 | 5 秒 | event 去重 |
| `POST /release` | 释放会话和锁 | 5 秒 | 重复调用安全 |

## 统一错误结构

```json
{
  "code": "BRIDGE_PROTOCOL_MISMATCH",
  "retryable": false,
  "scope": "session",
  "user_action": "升级配套组件。",
  "details": { "expected": "ps-bridge/v1", "actual": "ps-bridge/v0" }
}
```

`details` 只允许脱敏的 allowlist 字段；不得包含 API Key、认证头、绝对路径、图像字节或 Photoshop 原始异常对象。

## 候选与取舍

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 回环 HTTP + rendezvous/随机执行端口 + HMAC | 延续现有握手证据，状态可查询，跨语言简单 | 必须严格实现 token、nonce 和本机伪造防护 | **采用** |
| 固定单端口 HTTP | 实现简单 | 易被本机进程抢占或伪造，长任务隔离弱 | 不采用 |
| Named Pipe helper | Windows ACL 可细化 | 增加 helper 制品、安装和 UXP 连接边界 | 仅在正式 UXP 权限阻断 HTTP 时重新评估 |

## 影响

- UXP 适配器只执行已校验的计划，不读取 AI 结果、不决定页面状态、不生成业务规则。
- bridge 断线会进入 `BridgeDisconnected`/`RecoveryRequired`，不会自动重复有费用或有副作用的请求。
- 协议版本、插件版本和 Photoshop 构建必须进入握手与诊断，但版本号本身不是认证凭据。

## 退出条件

2026-09-25 D6c实施约束：日常连接仅在已有受保护配对下串行等待固定rendezvous，由桌面显式操作开启监听；无listener可等待，不自动重新配对/改秘密。执行循环保持独立于prepared资源引用的粘性安全标志，claim发送前置不安全，已认证空领取或已确认终态与清理方可复位；未发送任何字节须由载体提供本地类型化证据，不能从错误字符串推断。领取/ACK丢失、MAC/身份/合同/清理错误停止自动等待，Unknown不变。手动暂停/卸载使迟到连接失效，单飞/秘密清零/用户文档阻塞保持；不改协议字段或持久化格式。

Photoshop启动加载使用官方host.data.loadEvent=startup，生命周期使用entrypoints.setup；启动加载、开发reload与正式ccx部署需要分别验证，不能仅由字段存在声称安装通过。插件卸载不作为执行终态依据，仍由桌面保守恢复账本收口。

2026-09-25实机增量：配对开发实例已通过桌面独立连续连接/取消释放；内部CCX在无UDT、面板隐藏的新PS进程中自行初始化通过。11:41经用户明确批准完成安装区重新配对，未读取系统凭据或迁移Developer秘密；隐藏面板独立认证、实际取消释放及双端重启后11:50:28自动3心跳通过。安装态首次生成和正式ID客户部署仍独立保留，详见[D6c记录](../验证/V1-D6c桌面自动连接与本机安装启动验证-20260925.md)。此为新增实机证据，不变更配对/协议合同。双5秒deadline保持本地零字节类型化证据；未知状态禁用连接及偏好恢复，偏好检查不能解除执行不确定状态。

若 UXP 正式权限无法实现受保护配对、回环监听或状态查询，暂停客户交付并形成新 ADR；不得退回无 token 的固定端口通信。

## 2026-09-19 兼容修正与待补合同

RENDER-S1 首轮实测发现，冻结 Schema 的根 `body.oneOf` 会同时匹配合法的握手拒绝与普通拒绝，反而使拒绝消息无效。现将该联合改为 `anyOf`，继续由 `envelope_kind` 条件分支限制精确结构；不新增字段或版本，不改鉴权与执行语义，不涉及持久化迁移。对应正例和 envelope 错配反例已通过。

DTO/校验、Application 提交边界和有界流读取已有离线证据。后续候选已实现桌面监听/UXP 主动连接的挑战、双向证明、领取/ACK、认证事件、GET header 映射及只读资源分块；独立 `ps-adapter/v1` 机器合同存在，精确转录与资源端点见 [传输增补草案 §7/§8](../技术方案/RENDER-S1-UXP主动连接传输增补草案.md)。冻结 `ps-bridge/v1` 字段和 RenderPlan 不变。本增补仍为开发候选，真实 UXP 互操作、受保护秘密分发、输出/恢复等门未通过；本 ADR 不因此视为实现验收，也不据此开放生产入口。

## 2026-09-20 设备配对与动态端口实现增补

设备配对由 Application port 调用现有 session owner 的 factory，显式显示五分钟引介码。该 setup session 一次性消费码，要求 `pairing/protected-storage-v1` 能力及至少三次认证 ready 心跳后才写入 Windows Credential Manager。UXP 只有用户明确选择设备保存后才声明该能力，通过双方认证后写入/读回 secureStorage，再启用心跳。替换旧值先在各自受保护存储备份；一次性探针模式不声明能力、不保存。失败/取消/超时清除展示与内存副本，失败不开放生产可用性。后续已配对设备从受保护存储建立新的任务 session/token，不延用旧执行会话。首次分发和 UI 状态不是页面执行验收。

实测 UXP 8.3.0 使用 secureStorage.length/key(index)，没有 getKeys；按实际 API 兼容后两端受保护读回成功。不能把方法缺失归为网络权限拒绝，也不能退回普通文件。

动态执行端口改为对 127.0.0.1:0 一次 bind，由 Windows 分配临时端口，再严格检查结果在 49152–65535。用户态随机猜端口曾命中 Windows 排除段（57209 位于 57191–57290），报 AccessDenied；安全失败与权限守卫本身不应绕过。本实现不枚举尝试端口、不扫描、不连接未知服务，不改系统保留段/防火墙；固定 rendezvous 17842 被占用仍失败。部署机器若动态范围不符合合同，也失败，不修改系统范围。端口不可预测性不作为认证边界，HMAC、nonce、session/token、Host/Origin 和实例绑定继续提供安全保证。

## 2026-09-21 资源传输取消兼容增补

真实资源下载中取消暴露了租约撤销与下一次读取的竞态：旧客户端将已认证的资源拒绝统一清会话，使明确取消无法回报而进入 Unknown。新增既有错误结构内的 `BRIDGE_CANCEL_PENDING`（HTTP 400、retryable=false、scope=execution、固定本地文案）。Schema 的错误码模式已容纳该扩展，不改 RenderPlan、持久化格式或认证转录。

服务端先验证 session/claim/execution/digest、活动状态及原提交中的资源 handle/range，只对已持久化 CancelRequested 的匹配资源返回该响应；租约保持撤销，绝不重开文件或再传字节。UXP 仅在原 resource_read 路由、状态码、响应 MAC、序号、严格 JSON 和完整固定错误结构均通过后保留会话，用于释放本页新临时文件并回报递增的 execution_cancelled。待取消响应本身不能推进终态。清理或事件回执不确定仍关闭会话并保留 Unknown，不能自动重投。

旧 UXP 不识别该错误时仍按未知结果安全停止；新 UXP 对旧服务端的普通绑定拒绝也保持原行为，不将其推断成取消。不将此前无取消意图的 PSD 上传 400 归因或追认修复。

同日输出上传实测在取消意图持久化后、下一次 PSD 写入前触发相同竞态。现将待取消响应显式扩展到原 `output_write`/`output_seal` 路由与对应 kind。服务端仍先检查 session/claim/execution、running 状态、digest、root handle、artifact、输出种类与长度；write 另验证规范编码、块 hash、范围及最后已接受 offset，seal 只检查完整已接受长度、未 sealed/未 faulted 及摘要格式，不进行封存或宣称整文件 hash 成功。取消后不重开文件、不接收新字节、不签发成功 receipt。UXP 仅对上述三个精确路由/kind 的有效 MAC/序号/HTTP400/固定结构保留会话；释放输出读取句柄和本页临时文件后才能回报取消。伪造字符串、失败的清理或回执仍 Unknown。错误结构和版本不变，旧客户端仍安全停止。

## 2026-09-24 显式认证连接检查增补

设置页通过独立 Application port 使用已有设备秘密建立新的检查 session，不调用重新配对或执行提交。复用原 factory/owner、完整构建与能力匹配、HMAC、nonce 和 loopback 单通道，不改 wire/RenderPlan/SQLite。检查与引介配对共享非等待独占门；已有执行 listener 或其他服务占用固定端口时安全失败，不抢占、不扫描。检查使用只允许空记录的临时内存账本，连断开收口也不生成业务任务或持久化执行文件。

检查最多等待60秒，取消/离页/关闭均撤销检查；释放资源必须完成，不能因为超时跳过会话密钥清零和listener回收。初始30秒实机中跨窗口操作耗时使检查只有两次心跳，正确未报成功，因此延长手动连接余量而不降低认证门。至少三次有效认证心跳且当时宿主ready才是“认证连接检查通过”；三次认证后宿主非ready单独显示，不伪装成认证失败。未经认证的版本/密钥拒绝不能从不可信请求推断具体本机原因，统一报告未完成认证并给出版本/插件/配对的排查入口。

匹配完整构建的历史证据只能在严格认证成功后产生；它证明认证转录匹配批准构建，不证明程序路径、正式宿主选择、逐机渲染/ICC/恢复能力或持续在线。结果在检查owner释放后才发布，进程内历史附带观察时间，重启清空。诊断只被动读取固定状态/时间/有界计数及批准构建匹配白名单，不发起检查、不读取秘密或输出自由文本。真实实机门和错误路径见V1计划D5，未因此关闭SET/RENDER/INSTALL。

### 2026-09-25 生产启动与诊断检查仲裁

最终审查发现只对检查/配对互斥不足：离页取消检查后立即生成仍可与释放中的listener争端口。正式生产必须通过factory的 `StartTaskOwnerAsync` 获取已启动owner；生产可取消同一factory的诊断检查，并等待owner/session/listener完整释放，等待期间不允许新检查/配对插队。活动配对或既有生产不被取消，外部端口占用仍安全失败。取消/启动失败先释放未交付owner，再释放仲裁；factory关闭同时撤销等待。原 `CreateTaskOwner` 只保留隔离工具的未启动owner兼容入口。

这一优先级仅限无页面执行的诊断检查，不扩大抢占权限，不更改wire、RenderPlan、持久化/恢复/Unknown语义或插件。双向真实socket竞争及生产协调器聚焦回归、正式入口修复后检查/取消/释放/重启证据见[D5报告](../验证/V1-D5认证连接检查与诊断实机验证-20260925.md)。

## 2026-09-25 正式宿主选择的OS对端约束（D6b实施中）

D6a证明本机正式UXP的固定握手TCP连接由Photoshop进程持有；完整构建匹配本身不能证明选中的exe实际执行。新增约束必须使用Windows TCP表反向ESTABLISHED四元组及进程查询句柄读取身份，不接受客户端声明的PID或路径。仅处理当前入站127.0.0.1端点，表读取内存有界；无法唯一确定、进程退出或身份读取失败时拒绝，不降级成仅比较构建。

HTTP和WebSocket两种载体在接收/解析认证消息和媒体前统一检查。每个owner使用独立约束：先匹配明确选择的规范本地exe路径，首次匹配后固定PID和启动时刻；后续新TCP连接仍须同一身份。另一进程的无效请求只被拒绝，不改变已认证正确宿主的broker/session；原HMAC、nonce、顺序、完整构建及能力检查不变。此约束不承诺抵御同用户进程注入或任意恶意软件。

第一实现批仅加入可注入约束和Windows读取器，不改变当前正式factory行为；隔离工具可保留无选择构造，但正式DI/factory在后续接入时必须强制选择，不以可选默认值绕过。选择记录须显式保存本机exe规范路径/文件指纹/版本，受控路径原子写入；每次启动owner重验且保持文件身份，活动会话禁止更换。记录损坏、程序更新/移动、无有效选择均显示可操作分因，不修改旧任务/Unknown或SQLite。正式接入、真实PS及错误宿主/重启/失效验收前，不称正式选择已实现。

### 2026-09-25 第二批：强制选择与文件租约

正式DI显式注册并要求同一个PhotoshopHostSelectionService；检查/配对/生产在读取秘密与监听前获取选择租约，无有效选择停止。启用选择的factory拒绝同步未启动owner绕过；生产使用异步启动入口。仅在owner完全释放listener、broker、资源和session之后释放文件身份。诊断被生产取消时同样等待完整释放，不取消正在配对或既有生产。

本机记录settings/photoshop-host-v1.json为严格六字段、版本1、最多16KiB的偏好，不是SQLite业务状态。保存验证真实受支持Photoshop元数据/长度/SHA256；使用同目录独占临时文件、flush和原子发布。会话保持exe读句柄及父目录链，目录以FILE_LIST_DIRECTORY | FILE_READ_ATTRIBUTES（0x81）与不共享delete打开；仅属性访问（0x80）不能证明阻止改名，已由恢复严格断言的原生回归证实并修正。

仅应用自有设置路径允许OS目录映射验证模式：打包启动环境可能把某一LocalAppData目录映射到私有缓存，而逻辑父目录仍指向原目录。不能用文件/父路径字符串拼接检验该目录，也不加入包名或根替换白名单。通过已打开目录句柄取得真实路径，同时锁住全部物理祖先，拒绝任一重解析/非本地卷/二次映射，并在两条目录链持有时重新打开逻辑目录确认仍解析为同一实际目录。宿主exe选择不启用这一设置存储特例；既有资源文件校验未放宽。
