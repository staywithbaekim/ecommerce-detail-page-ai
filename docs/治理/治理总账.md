## 当前基线（第一轮盘点）

- 模板、实例生产、AI 分析、渲染和恢复相关新代码正在形成，但必须验证是否真正复用模板级解析结果，避免每个商品重新解析。

## 第一批风险假设（待代码证据确认）

1. 模板级解析结果与商品级生产输入之间可能没有明确的缓存键、版本和失效策略。
2. 大型 ViewModel、AI 调度器和适配器可能混合 UI、编排、持久化、重试和外部调用职责。
3. SQLite Store 的分片虽然按功能拆开，但表结构、迁移、查询和 JSON 快照可能存在重复或隐式关系。
4. 外部接口调用的错误、超时、重试、幂等和日志边界需要统一检查。
5. 测试数量不能直接证明关键生命周期（模板变更、复用、恢复、失败重试、迁移）已经覆盖。

## 治理顺序

1. 建立架构与数据流事实图，确认实际调用关系和生命周期。
2. 固化问题清单、严重度、证据、影响范围和验收标准。
3. 先修复高收益且低风险的问题：重复解析/重复 IO、明显的查询和状态缺陷、错误处理缺口。
4. 再拆分职责边界和接口适配层；保持公开合同与 renderer-neutral RenderPlan 稳定，除非有明确证据需要变更。
5. 为数据库迁移、缓存复用、任务状态、恢复和关键接口补充可验证测试。
6. 每一批修改后运行聚焦构建/测试、git diff --check，并更新本账与相关验收证据。

## 当前非目标

- 不做与验收无关的全仓库格式化。
- 不因为文件很大就盲目拆文件。
- 不修改用户源 PSD、照片、市场图、人工参考或正式输出。
- 不添加 PRD 排除项：账号、支付、云端模板同步、平台上传等。
- 不提交、推送、发布、安装或合并。
