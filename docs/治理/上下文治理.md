# 项目上下文与文档治理

## 目的

把完整证据与每轮真正需要的工作上下文分开，降低 Codex 新窗口的输入 token 和缓存读取量；不删除 PRD、ADR、验收或历史证据。

## 事实边界

- Codex 会自动注入从用户级目录、仓库根目录到当前工作目录沿途发现的 `AGENTS.md`/兼容指令文件；因此指令文件本身是常驻成本，深层目录指令也可能叠加。
- 普通 `docs/` 文档不是因为存在于仓库就自动全部常驻；它们主要在代理读取文件、工具输出文件内容或长期对话继续携带历史时进入上下文。
- 所以治理重点是压缩常驻指令、限制路由和工具输出、切断长对话历史，而不是删除完整证据。

## 默认上下文预算

- L0 常驻文档包：`AGENTS.md` + `docs/当前任务上下文.md`，目标不超过 8 KB 原始文本。
- 普通任务追加包：目标不超过 25 KB；复杂阶段接管不超过 50 KB。
- 单次工具输出：优先不超过约 4,000 tokens。
- 原始字节数、缓存读取量和文件数量只能作为预警；必须通过新窗口实际接管观察 token 变化。

## 信息分层

| 层 | 内容 | 默认策略 |
| --- | --- | --- |
| L0 | `AGENTS.md`、`docs/当前任务上下文.md` | 常驻短入口 |
| L1 | 活动任务交接、目标源码、直接调用方、受影响测试 | 按任务读取 |
| L2 | PRD 相关章节、ADR、Schema、验收矩阵对应行 | 只有合同/验收问题才读取 |
| L3 | `docs/验证/`、旧交接、历史状态、完整报告 | 只有被引用或需要证据时读取 |

## 历史资料处理

- 完整证据继续保留，不因 token 治理删除。
- 历史资料不属于默认上下文；优先通过索引、关键词、章节和行号定位。
- `tmp/`、构建目录、缓存、生成物和机器日志不进入默认检索；确认没有诊断价值后才可单独清理。

## 检索与工具约束

- 默认排除 `.git/`、`tmp/`、`bin/`、`obj/`、`node_modules/`、`packages/`、缓存和生成物。
- 长文件先定位标题/符号/行号，再读取局部范围；禁止为了“保险”读取完整状态日志、全部验证报告或完整递归 diff。
- 使用 `tools/read-project-context.ps1`：普通路由只输出短入口；任务路由默认输出短交接；详细文件必须带 `-Query` 才读取匹配窗口。
- 使用 `tools/context-cost-audit.ps1 -Route <route>` 查看仓库侧 L0 和路由输出估算；该估算不是模型账单或 Codex UI 遥测。
- 需要重复读取当前上下文时，使用 `-IncludeCurrentContext`；否则避免路由脚本重复输出已经由仓库指令加载的 L0 内容。

## 新窗口工作协议

每个窗口只处理一个明确目标，并在启动提示中写明：

1. 本次目标；
2. 非目标；
3. 允许读取的路由；
4. 验证命令。

完成后只在当前交接中记录改动、验证、证据缺口和下一步，不复制完整过程或历史报告。

## 更新规则

只有当前主线、活动任务、阻塞、验收门、外部依赖、安全边界或下一交接变化时，才更新 `docs/当前任务上下文.md`。一次性修复和测试结果写入对应任务/验证文档。

## 治理完成标准

- 默认入口存在且短；
- 默认路由不展开长文档；
- 历史和生成物不进入默认检索；
- 路由脚本输出有界且不重复 L0；
- 长文档未被删除；
- 既有工作树改动未被重置；
- `git diff --check` 通过；
- 至少用一次真实新窗口任务比较优化前后的上下文成本。
