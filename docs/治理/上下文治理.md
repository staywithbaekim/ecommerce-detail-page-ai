# 项目上下文与文档治理

## 目的

把“可追溯的完整证据”和“代理每轮真正需要的工作上下文”分开，降低 Codex 每次接管任务时的输入 token，同时不牺牲 PRD、ADR、验收和历史证据。

## 当前问题基线（2026-10-05）

- `docs/` 有 221 个文件，约 2.89 MB；其中 `docs/验证/` 有 121 个历史验证文件。
- `docs/当前项目状态.md` 约 292.5 KB/1500 行；`docs/验收矩阵.md` 约 134.8 KB/698 行；TPL-02 活动任务书约 134.1 KB/1071 行。
- 工作树已有其他窗口留下的大量未提交/未跟踪变更，不能通过 reset、clean 或批量删除来“整理”。

这些文件可以继续作为审计资料存在，但不应每次完整注入代理上下文。

## 新的默认入口

`docs/当前任务上下文.md` 是默认项目状态摘要。它只记录当前路由、开放验收门、安全边界、最小阅读路由和检索规则，目标控制在小文档范围内，不承载历史流水账。

`AGENTS.md` 规定代理先读该文件，再按任务类型追加最小文件和章节。项目总览、当前状态、验收矩阵、ADR 和验证报告改为按需读取。

默认预算：普通任务的默认文档包控制在 25 KB 原始文本以内；复杂阶段接管也不超过 50 KB，超出时必须改为章节或行号检索。单次工具输出优先控制在约 4,000 tokens 以内；原始文件字节数不等于模型 token，只作膨胀预警。

## 信息分层

| 层 | 内容 | 默认策略 |
| --- | --- | --- |
| L0 | `AGENTS.md`、`docs/当前任务上下文.md` | 默认读取 |
| L1 | 活动任务书相关章节、目标源码、直接调用方、受影响测试 | 按当前任务读取 |
| L2 | PRD 相关章节、ADR、Schema、验收矩阵对应行 | 发生合同/阶段/验收问题时读取 |
| L3 | `docs/验证/` 报告、旧交接、历史状态 | 只有被引用或需要证据时读取 |

## 历史资料处理

- PRD、ADR、Schema、测试和真实验收报告：保留，不以“过长”为理由删除。
- 旧状态流水账和交接文档：暂不批量删除；先通过 L3 路由隔离。后续只有在引用审计完成后，才移动到归档目录。
- 根目录/忽略目录机器日志、缓存、临时运行记录：不是项目证据；确认无当前诊断价值即可删除。
- 本轮删除的唯一运行日志：`gude-2026-10-03.log`。它未被 Git 跟踪，仅包含一次已过期的 WinHTTP 错误。

## 检索约束

所有仓库搜索和递归枚举默认排除：`.git/`、`tmp/`、`bin/`、`obj/`、`node_modules/`、`packages/`、缓存和生成物。长文件先定位标题/行号，再读取局部范围；禁止为了“保险”把整个状态日志、全部验证报告或完整递归 diff 读入上下文。

仓库提供 `tools/read-project-context.ps1` 作为可重复的有界路由工具：`general` 只输出默认上下文；`tpl02` 默认只输出短交接，只有带 `-Query` 才从详细任务书读取最多 8 个小窗口；`stage` 输出短状态和总览顶部；`validation -Query <ID>` 输出验收矩阵的局部匹配窗口；`architecture` 必须带 `-Query`，否则不枚举 ADR；`render` 只输出短状态和合同路径，不展开 RENDER 任务书。它不会递归读取 `tmp/`、构建目录或全部验证报告，查询结果也有匹配数量上限。

## 更新规则

只有下列信息变化时才更新 `docs/当前任务上下文.md`：当前主线/活动任务、阻塞、验收门、外部依赖、关键安全边界或下一交接。一次性修复和测试结果写入任务/验证文档，不在默认上下文中追加历史段落。

## 验证目标

每次治理变更至少检查：默认入口存在、路由指向正确、默认路由不展开长文档、排除目录规则明确、长文档未被删除、工作树既有改动未被重置、`git diff --check` 通过。token 降幅属于后续实际任务接管时的观测指标，不以文件字节数或缓存读取量直接冒充模型 token 计量。
