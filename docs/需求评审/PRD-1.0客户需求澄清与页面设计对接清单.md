# PRD 1.0 客户需求澄清与页面设计对接清单

## 文档定位

本文件是对已签署 `产品需求文档-电商详情页智能生产系统-PRD-1.0.md` 的产品经理评审，不替代、不静默修改 PRD 1.0。

本轮结论是：技术验证已经证明 UXP/Photoshop 执行通道具备进入 V1 桌面端实现的条件；`AI-01`、`SIZE-01` 现在应直接进入正式纵向实现并在实现过程中验收，不应再建设会被丢弃的孤立验证 Demo。完整产品的端到端 `machine_total` 仍需桌面端接通后验收。因此当前适合正式对接客户，会议目标应从“证明能不能做”转为“确认客户要什么、页面怎么组织、什么结果算合格”。

## 一、对附件清单的判断

用户提供的图片是一份通用 PRD 检查清单，包含：

1. 产品目标和使用场景；
2. 整体页面框架和导航结构；
3. 首页内容结构；
4. 每个模块的用途；
5. 每个模块第一版必要的数据和操作；
6. 首页、今日计划和各模块之间的关系；
7. 本地数据、备份和恢复要求；
8. 第一版必须完成的功能；
9. 第一版暂时不做的功能；
10. 可以实际检查的验收标准。

它是评审维度，不是本项目客户已经确认的新增需求。现有 PRD 已覆盖第 1、4、5、7、8、9、10 项的大部分内容；第 2、3、6 项仍主要停留在功能列表和流程文字，尚未形成客户可确认的页面结构和交互稿。

## 二、总体判断

### 结论

PRD 1.0 作为 V1 产品基线是完整且可执行的，已经明显超过“概念说明”水平；但它还不是可以直接交付客户签字的最终产品规格。缺口集中在四类：

- 客户业务口径没有完全量化；
- 页面信息架构和视觉设计还没有被客户确认；
- AI、尺码表和异常处理的判断边界缺少可执行阈值；
- 试点验收、安装支持和数据责任还没有形成双方责任表。

### 当前状态的准确表述

可以对客户说：

> Photoshop 执行通道已经用真实 PSD、真实素材和受控失败场景完成技术验证，UXP 作为 V1 首版执行适配器具备可行性。现在进入客户需求澄清和页面结构设计阶段。素材 AI 分析、动态尺码表和完整桌面端端到端性能仍会在 V1 MVP 中独立验收。

不应对客户说“整个产品已经全部验收完成”或“95% 页面准确率已经被多款批次证明”。当前验收矩阵的 `AI-01`、`SIZE-01` 仍待正式实现与验收；`TV-14` 只是 UXP 执行通道阶段性性能门，不是完整产品 10 款端到端实测。

## 三、必须先向客户确认的 P0 问题

以下问题若不确认，页面设计和开发都可能返工。每项应有客户明确答案、示例文件或签字记录。

| 主题 | 需要客户确认 | 建议记录形式 |
| --- | --- | --- |
| 真实工作流 | 实际操作者是谁；每天/每周处理多少款；一个款平均多少张素材、多少变体、多少页面；谁负责复核和最终上传 | 一次完整操作访谈 + 3 至 5 款真实批次 |
| 页面范围 | V1 首批到底包含哪些页面；页面顺序、页面名称、是否有尺码页；哪些页面是每款一次、每变体一次或容量组合 | 页面清单表，逐页确认 |
| 页面视觉 | 每页最终画布尺寸、参考人工结果、允许的主体位置/裁切边界、字体/颜色/品牌规范、哪些内容永远固定 | PSD + JPG 金标 + 设计规范附件 |
| 素材语义 | 客户如何区分正面、背面、细节、模特图、平铺图、面料图；同一张图可否复用；变体由颜色、型号还是其他字段区分 | 真实素材标注表 + 例外样本 |
| 尺码表 | 支持的语言、单位、合并单元格、特殊列、模糊/低清图处理；最终表格由谁复核 | 至少 10 张清晰和异常尺码图金标 |
| 输出交付 | JPG 文件名、页码顺序、目录层级、是否保留 PSD、质量/色彩要求、同名目录如何处理 | 输出目录样例 + 客户确认 |
| 质量标准 | “可直接上传”的定义；95% 指页面数还是款式数；严重错误清单；客户接受的黄色问题 | 可打勾验收表 + 金标对照 |
| 异常决策 | 红色问题谁来修复；缺图、冲突尺码表、低分辨率、PSD 失效时是否允许跳过页面；何时允许人工覆盖 AI | 状态决策表 |
| 安装和数据 | Photoshop 版本、管理员权限、网络/代理、AI 数据是否可出本机、数据保留多久、客户是否提供 API Key | 环境盘点表 + 数据处理确认 |
| 试点边界 | 试点客户、试点周期、参与人员、样本量、培训和支持方式、上线/暂停标准 | 试点计划与责任人表 |

## 四、PRD 建议补充或澄清的内容

这些内容建议进入 `PRD 1.1` 或配套规格，不建议继续堆入技术验证报告。

### 1. 补一份“页面与信息架构”章节

PRD 第 20 节只列出了关键界面，没有说明用户从哪里开始、每个页面如何流转。至少要明确：

- 首页是否是“最近任务/新建批次/模板库/异常待处理”的工作台；
- 是否有“今日计划”或待处理清单；它与批次、模板库、结果检查页的关系；
- 主导航的顺序和全局返回规则；
- 新建模板、模板维护、新建批次、生成前检查、渲染进度、结果修复、设置之间的状态流转；
- 关闭窗口、返回、取消、暂停、重试、离开未保存页面时的行为；
- 空状态、首次使用、处理中、无权限、无网络、Photoshop 未连接、失败和恢复状态。

建议产物：一张信息架构图、一张主流程图、每个核心页面一张低保真线框图。

### 2. 补一份“页面模板确认表”

每个客户模板组至少确认以下字段：

- 页面 ID、客户页面名、输出排序、生成方式；
- 画布宽高、方向、色彩空间和 JPG 质量；
- 图片框数量、每个框的业务角色和所属变体位；
- 主体完整/填满/局部细节等布局意图；
- 允许的自动缩放和位移边界；
- 缺少素材时的状态和替代规则；
- 固定文字、装饰、品牌元素和不可修改区域；
- 参考 PSD/JPG 与客户确认人。

这张表是客户语言与内部 `RenderPlan` 之间的产品边界，不能只用图层名称或开发者猜测代替。

### 3. 把绿/黄/红从例子变成决策表

PRD 第 14 节已经定义状态方向，但还缺阈值和人工动作。例如应明确：

- 图片分辨率低于什么条件进入黄色或红色；
- AI Top-1 与 Top-2 分差多小时进入黄色；
- 主体检测不到、多个主体、主体被裁切时分别如何处理；
- 尺码表 OCR/结构解析置信度如何决定颜色；
- 模板绑定缺失时是否允许只跳过当前页；
- 黄色是否默认产出并在结果页集中复核；
- 红色由谁修复、修复后是否重新分析全部素材。

每个状态应有四列：触发条件、是否进入队列、用户可执行动作、是否需要重新分析。

### 4. 补齐 AI-01 与 SIZE-01 的产品验收

技术验证已经明确这两项仍未完成。补充内容应包括：

- 金标样本数量、品类/厂家覆盖、正反例和异常样本；
- 素材角色、变体分组、主变体、尺码表行列的字段定义；
- Top-1 选图准确率、变体分组准确率、尺码表字段准确率；
- 误判必须进入黄色还是红色，哪些错误属于严重错误；
- API 失败、超时、限流、余额不足、离线时的用户体验；
- 压缩图上传尺寸、数据保留时间、客户授权和脱敏要求；
- 单款和单批 AI 成本预算、缓存命中规则和供应商切换规则。

### 5. 明确试点与验收责任

PRD 目前有质量目标，但没有完整的“谁提供什么、谁判定通过”。建议增加：

- 客户提供：模板 PSD、源照片、人工结果、页面规范、尺码表金标；
- 产品方提供：安装配置、模板校准、培训、问题分级和诊断包；
- 客户签收人和最终验收人；
- 试点批次、截止日期、允许的返修次数；
- P0/P1/P2 问题定义和暂停上线条件；
- 需求变更如何进入 PRD 1.x 或后续版本。

### 6. 补充安装、兼容和数据责任的客户版本说明

内部 ADR 可以保留 UXP、ICC、图层路径等实现细节；客户版只需要明确：

- 支持的 Windows 与 Photoshop 版本清单，当前改版 PS2025 仅是验证环境，不自动等于全版本承诺；
- Photoshop 授权由客户负责，产品不代管 Adobe 账号；
- AI 需要网络，网络不可用时任务如何暂停和恢复；
- 原 PSD/高清源图只读，上传 AI 的是压缩分析图；
- API Key 由谁提供、存在哪里、如何更换和撤销；
- 模板、缓存、临时文件和正式输出的存储位置及清理责任。

## 五、建议暂时收敛或移出客户 PRD 的内容

这些内容不是不重要，而是层级不对。它们应留在 ADR、技术规格、验收报告或开发任务中：

- UXP `batchPlay`、`executeAsModal`、session token 和 Document 发布竞态；
- `RenderPlan` 图层路径顺序、替换栈逐层结构和目标名称变化契约；
- JPEG ICC APP2 分段、canonical profile 哈希和后处理实现；
- TV-13 的固定故障注入检查点、插件版本和远程包 SHA-256；
- 阶段性验证包的版本号、远程机器截图和逐次失败修复过程。

PRD 只保留产品承诺，例如“JPG 最终读回验证为 sRGB”“失败不污染正式输出”“可编辑 PSD 可继续修改”；实现证据放到 `docs/验证/` 和 `docs/架构决策/`。

也不建议把“后续候选方向”继续扩展成需求清单。保留一页路线图即可，避免客户误以为独立渲染器、云同步、账号计费、Excel/CSV 尺码表和平台上传属于 V1 承诺。

### 已确认保留在 V1 的功能

根据本轮产品决策，以下能力保留在 V1；它们的实现方式和验收深度仍需在正式技术方案中具体化：自然语言调整通过 API 输出受限结构化动作，从人工结果学习模板通过 API 对照原照片、PSD 和人工 JPG/PSD 生成模板规则，内部商品模型保持通用品类和多种变体，多个 Photoshop 版本作为已验证环境能力处理。它们不应再被默认降级为 P1。

| 功能 | 产品判断 | 建议 |
| --- | --- | --- |
| 自然语言移动/缩放 | API 只负责意图理解并返回受限结构化动作；桌面端负责校验、预览、撤销和生成计划 | 保留在 V1；手动拖拽仍是主交互 |
| 从人工结果自动学习模板 | 原照片、PSD 模板和人工 JPG/PSD 可作为对照输入；已有 UXP 验证显示该路线能一次得到接近正确的排版结果 | 保留在 V1；直接接入正式模板校准链路 |
| 模板包跨电脑迁移 | 是模板规则、内部 PSD 副本和元数据的迁移，不是云同步 | 保留；排在核心生产闭环之后实现 |
| 非服装商品的通用变体界面 | 商品角色由 API 和模板示例决定，不把颜色、正面、背面写死为唯一字段 | 保留通用模型；验收按客户实际品类逐步扩展 |
| 多 Photoshop 版本选择 | 已验证同机安装多个 Photoshop 不妨碍运行，产品需要让用户选择或确认目标宿主 | 保留环境选择和自检，不作为 V1 风险阻断 |

不建议降级的核心闭环是：模板校准、批次扫描、生成前状态、批量渲染、原文件保护、暂停恢复、失败隔离、结果集中检查、单页修复、JPG 和可选可编辑 PSD，以及 AI-01、SIZE-01 的正式实现。动态尺码表既然已纳入 PRD 1.0，就按正式模块实现，不因尚未完成而静默删除。

## 六、现在是否应该和客户对接页面结构与设计

应该，而且这是进入桌面端 UI 之前的必要工作。顺序建议如下：

1. 先拿客户真实批次和人工结果做业务走查，不先展示开发者假设的页面。
2. 确认页面清单、页面顺序、页面角色、变体组合、尺码页和输出规则。
3. 画信息架构和低保真流程，先确认“页面之间怎么走”。
4. 再做关键页面的高保真设计：模板库、新建模板校准器、新建批次、生成前状态、渲染进度、结果检查/修复、尺码表编辑器、设置。
5. 用一批真实样本做可点击原型走查，特别验证拖拽校准、异常修复、暂停恢复和单页重生成。
6. 客户确认后冻结页面 1.0，功能需求的新增或范围变化进入 PRD 1.1/ADR，不在开发中口头追加。

首次客户会议建议准备三份材料：

- 一页产品流程图：模板校准 -> 新建批次 -> 预检 -> 生成 -> 结果修复；
- 一份真实样本页面对照：人工结果、系统计划、预期输出；
- 一份需要客户逐项选择的决策表，而不是只展示技术验证截图。

## 八、客户会议后的必交付物

客户会议结束后，至少应产出：

1. 客户问题确认表：每个 P0 问题有答案、负责人和日期；
2. 页面信息架构图和核心页面线框图；
3. 页面模板确认表和真实样本金标清单；
4. 绿/黄/红状态决策表；
5. AI-01 与 SIZE-01 的产品验收草案；
6. 试点范围、验收人、时间和问题分级；
7. 需要写入 PRD 1.1 的变更摘要；
8. 文档与文件归档清单，明确哪些版本仍可复现、哪些仅保留历史记录。

## 评审结论

PRD 1.0 不需要推倒重写，也不建议继续增加技术实现细节。下一步应先与客户确认页面结构、页面设计和真实金标，再把确认结果以 PRD 1.1、页面规格和验收矩阵的方式固化。现有技术验证文档、样本和失败证据先保留；`tmp/`、外部 Demo 和重复验证包只能在做完可恢复清单后归档或清理。
