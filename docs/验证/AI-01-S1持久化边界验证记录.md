# AI-01 S1 持久化边界验证记录

## 范围与基线

本记录覆盖 AI-01 S1 的领域状态/CAS、SQLite v6 request ledger/session/cache/usage 边界以及 `ai-analysis-state/v1` 文件 manifest 各自的原子 staging/commit/recovery 合同。实现从已合并 INPUT-01 基线 `6b64f70` 继续，治理头为 `4281bff`；不包含火山方舟 provider、Credential Manager、联网、队列/费用阈值、WPF、动态尺码或 Photoshop 批量渲染。

AI 文件协议实际使用：

- `staging/{stage-token}.json` 保存暂存 manifest；
- `staged.marker` 记录 stage token、manifest 引用和 digest；
- `manifest.json` 与 `committed.marker` 构成提交态；
- 当前协议没有单独的 `ready.marker`。marker、stage token、manifest reference、digest 和列表语义均在读写时校验。

SQLite 与文件 manifest 目前各自具备单 writer/原子写入和恢复边界，尚未形成跨资源业务编排事务；不能据此宣称 AI-S1 或 AI-01 整体验收通过。

## 可复现验证

在 Windows 11 x64、.NET 10 环境执行：

```powershell
dotnet test tests/Desktop.Domain.Tests/Desktop.Domain.Tests.csproj --no-restore --verbosity minimal
dotnet test tests/Desktop.Application.Tests/Desktop.Application.Tests.csproj --no-restore --verbosity minimal
dotnet test tests/Desktop.Infrastructure.Tests/Desktop.Infrastructure.Tests.csproj --no-restore --verbosity minimal
dotnet build EcommerceDetailPage.Desktop.slnx --no-restore --verbosity minimal
dotnet test EcommerceDetailPage.Desktop.slnx --no-build --no-restore --verbosity minimal
git diff --check
```

本轮聚焦结果：Domain 40/40、Application 41/41、Infrastructure 61/61。随后完整 solution 重新执行结果为 182/182（Contracts 30、Domain 40、Application 41、Infrastructure 61、Architecture 5、UI 5）；历史 165/165 不覆盖本轮新增测试。

覆盖证据包括：

- 同一 request fingerprint 幂等、规范初始 ledger（Queued/null/时间一致）、SHA-256 指纹和结果引用状态闭合；
- request 状态受控 CAS，Validated→ManualReview/PlanClosed 保留既有结果引用；终态回退、跨阶段跳跃和旧状态覆盖均拒绝；
- session selection revision CAS：同状态递增 revision 的第二次换图可保存，同 revision 偷换、允许集合替换、PlanClosed/TerminalError 回退均拒绝；
- usage/cache 只接受非负计量、费用币种配对、相对 owned reference；usage 必须关联 ledger，cache 必须关联 usage、model config、时间和 ledger result；同 key 不一致 payload 结构化拒绝；
- decimal 费用使用稳定文本保存；损坏 ledger/cache/usage 的时间、enum、decimal、引用在读取时映射为 `InvalidDataException`；
- manifest staged/committed 重启读取、A/B stage 回滚隔离、伪造 token/reference/digest/列表拒绝，以及 marker 写失败后的应用自有 stage 清理。
