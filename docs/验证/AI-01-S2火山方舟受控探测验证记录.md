## 请求与结果

- 端点：`https://ark.cn-beijing.volces.com/api/v3/responses`
- 模型：`doubao-seed-2-1-pro-260628`
- 输入：火山方舟官方演示图片 URL + 中文视觉提问；不是用户商品素材，不上传 PSD、市场尺码图或本地路径。
- 第一次探测：客户端等待 60 秒未返回。
- 第二次探测：客户端等待 180 秒未返回。用户随后提供与 19:40–19:45 对应的平台账单：输入 1.361k tokens、输出 7.184k tokens，应付金额约 ¥0.22。该账单证明请求已被平台处理，不证明客户端收到了可用结果。
- 第三次探测：请求显式设置 `thinking.type=disabled`、`max_output_tokens=512`；HTTP 200，状态 `completed`，约 5.17 秒；输入 1,350、输出 64、合计 1,414 tokens，缓存命中 0。响应正文和完整 response ID 不写入仓库。

## 结论

1. 当前 Key、测试项目、Responses 端点、候选模型和图片 URL 在本环境可用；新西兰网络不是“完全无法调用”的充分解释。
2. 默认深度思考与无界输出会造成显著的等待和费用风险；不能把同步客户端超时误判为供应商未处理，也不能盲目重试未知结果。
3. 当前证据尚不足以冻结生产压缩配置、并发、重试次数、预算、告警线、硬停止线或结构化输出请求合同。下一步必须先实现正式供应商无关端口下的 `VolcArk` adapter、Credential Manager 读取、超时/429/5xx/断网/取消/未知映射和严格结构化 JSON 校验，再申请一次最小结构化 JSON 真实请求。
