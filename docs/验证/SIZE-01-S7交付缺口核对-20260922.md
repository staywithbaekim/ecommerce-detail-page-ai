## 核对结论

### 已有且不应重做

1. 默认 `DesktopV1` 数据根中存在可直接恢复的真实成功动态批次 `batch-ca74d73b43774474b1204f0793c9b031`。其 `size-table/v1` 为 6 列 6 行、revision 0，来源为 `ec290f29b949aace3d8e3c906f83bdcb.png`，414,576 bytes，SHA-256 `313f5ab383c62af1d48e811d850c88fa85a2bfff8ea51a7f4de28d56f4ca745a`。来源、结构状态和两次已提交执行均在本机默认数据根中，恢复只读现有结果，不需要再次调用 AI。
2. 该批次 attempt2 JPG 为 590,921 bytes，SHA-256 `f40366f39452cd7f28c723a5d7886314e749bc952ed0b1e2340d64eef79b9d41`；用户已确认该图无问题。首次生成、正常重启不重渲染、单页 attempt2、源保护和旧输出保留见 `docs/验证/RENDER-01-S6原生动态尺码流程-20260921.md`。
3. 第一组完整款 `A馨妈6015-58` 的 7 页/11 框和动态尺码 JPG+PSD 已通过正式生产链路、恢复和用户图片验收，见 `docs/验证/RENDER-01-S7完整款素材联验-20260922.md`。这已经提供真实模板 JPG/PSD、ICC、源保护和恢复证据，不需要为 SIZE 再重复渲染同一组。
4. 完整款使用的新尺码来源 `a84b9bd06604e260ed52d668bc2f4298.jpg` 为 43,703 bytes，SHA-256 `ebd1cec3561ac97355cf93c4a0a1c55907cb1e6d49898e53305fedf97dc3c04b`。它证明新样本的真实输出，不是两份 SIZE-S0 旧金标中的任一份。

检索范围严格限于用户已批准的 `office-assets-ecommerce-detail-page-ai-20260914/extracted/需求样本` 和当前仓库；`git worktree list` 只登记当前 worktree。本轮没有遍历其他用户目录。SHA-256 相同必然要求字节长度相同，因此长度候选为空已排除批准范围内以其他文件名保存的相同字节文件。

### 仍缺的窗口证据

O-03 仍需实际窗口证据：

- 产品负责人查看真实 O-03 弹层，而非测试夹具截图；
- 100% DPI 下 1440×900 和 1100×760；
- 125% DPI 下 1100×760，以及受当前工作区限制时的实际最大窗口尺寸；记录真实窗口边界和 DPI 值；
- 三栏、标题、来源摘要、状态文案、关闭/保存及行列操作按钮均在可视区内，无重叠或被侧栏覆盖；
- Tab/Shift+Tab 顺序跟随视觉顺序，焦点始终留在弹层，关闭后回到“编辑尺码数据”；Escape 可关闭；
- 使用真实中文 IME 完成组合输入并恢复原值。直接注入 Unicode 文本只能证明中文字符可显示，不是 IME 组合证据；
- UIA 重新获取后能看到 `SizeTableEditorDialog`、`SizeTableEditorSurface`、三个 panel、关闭/保存和四个行列按钮。若截图已进入弹层而 UIA 仍持续返回旧工作台树，应记录为 UIA 门失败或待定位，不能仅凭一次缓存快照推断根因。

旧自动化的 1100×760 断言只测量 `SizeTableEditorDialog` 遮罩 Grid，没有测量固定 `1080×680` 内层。外窗 1100 宽时主导航占 208，页面左右 margin 共 64，内容区显著小于 1080，因此该自动化不能证明内层不溢出。

本轮补丁将内层改为受宿主约束的 stretch + `MaxWidth=1080` / `MaxHeight=680`，三栏使用 `23* / 52* / 25*`，打开时焦点进入关闭按钮，Escape 关闭并恢复入口焦点。增强断言覆盖真实内层、三栏、关闭/保存及四个行列按钮的宿主边界和互不重叠。窄栏模板预览允许已有的文字省略显示；这不代表预览中每个值都可完整阅读，逐格数据仍以中间可滚动结构表为准。

### 输出证据如何归档

O-03 实机走查至少保留以下输出，而不是只写“看起来正常”：

1. 每个 DPI/窗口组合的一张全窗截图，包含真实 DPI、外窗尺寸、三栏和底部操作区；
2. UIA 节点清单及各关键元素 BoundingRectangle、Name、AutomationId、IsEnabled、HasKeyboardFocus；
3. 中文 IME 组合输入前、提交后、恢复原值后的截图或录屏片段；
4. 走查前后 `current.json` revision/digest、来源 hash 和既有正式 JPG/PSD hash。若本轮不保存，以上应保持不变；
5. 产品负责人对 O-03 窄窗/125% 实际弹层的明确视觉结论。

真实 JPG/PSD 集成已有新样本证据，剩余工作是把证据准确映射回 SIZE 行，而不是重复输出。它不能补齐两份旧金标的当前可复核输入。

## 主线程最短 O-03 实机步骤

主线程已恢复旧成功动态批次并进入结果详情时，从第 2 步开始：

1. 若仍在“新建批次”，点“取消”返回工作台，再点“恢复上次批次”。应恢复 `batch-ca74d73b43774474b1204f0793c9b031` 并进入仅有动态尺码页的结果；若批次 ID/内容不同，停止，不新建批次、不启动 AI。
2. 在动态尺码结果详情点“编辑尺码数据”。核对来源预览、结构化表格、模板样式预览都出现；表格应为“尺码、肩宽、胸围、衣长、袖长、建议体重”六列和 L 至 5XL 六行。
3. 在 100% DPI 分别设 1440×900 和 1100×760，记录全窗截图和关键元素边界。重点检查内层内容面板，而非只检查半透明遮罩。
4. 用 Tab/Shift+Tab 遍历关闭、表头/单元格、行列按钮和保存按钮；确认焦点可见、顺序合理且不跑到弹层后方。按 Escape，确认关闭并回到“编辑尺码数据”，随后重开。
5. 在一个已记录原文的非关键字段中使用系统中文 IME 完成真实组合输入，观察保存按钮变为可用；恢复完全相同的原文，确认保存按钮重新禁用。不要点击保存，不制造不存在的产品数据。
6. 切换 Windows 到 125% 后重启应用，再恢复同一批次并重复 1100×760 和实际最大窗口走查；确认实际 DPI 为 120/125%，不要用环境变量或程序缩放冒充。
7. 每次打开后刷新 UIA 根。若 UIA 树与截图持续不同步，记录时间、窗口 PID、截图和返回树；该结果保留为未通过证据。
8. 关闭弹层后只读复核结构 revision/digest、来源和正式输出 hash 不变。把截图、UIA 清单和产品结论写入新的实机记录，再由主线程同步验收矩阵/任务书/当前状态。

上述步骤刻意不点击“保存并重生成此页”：当前真实表没有已批准的错误值，随意改值会违反“不猜值”。如必须取得真实保存操作证据，需要产品负责人给出一项真实纠错，或明确批准在隔离批次中使用可回滚的测试改动；不能在现有正式成功批次中发明业务值。
