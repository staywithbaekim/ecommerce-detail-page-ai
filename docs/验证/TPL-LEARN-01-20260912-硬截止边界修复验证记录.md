# TPL-LEARN-01：手动失败根因与 AI 适配器硬截止修复验证记录

## 结论

手动流程失败的直接原因是独立真实请求在 HTTP/响应读取阶段没有在取消后及时结束，
不是 AI 已经返回成功语义后被校准界面覆盖。旧适配器的 `HttpClient.Timeout` 为无限，
仅依赖链接 CTS 的 `CancelAfter(180s)`；遇到不响应取消的底层任务，WPF 会继续等待，
最终才把会话保存为 `AiUnavailable`。

修复后，普通日常分析和参考学习都由 `HttpRequestScope` 对发送与响应体读取施加硬
deadline，并后台观察迟到 task 后再释放请求/响应资源。超时仍保持未知结果安全门，
不自动重试或伪造成功。

## 实现范围

- `src/Desktop.Infrastructure/Ai/VolcArkAiAdapter.cs`
  - 发送等待使用 `Task.WaitAsync(remaining, callerToken)`；deadline 到达即返回
    `AI_PROVIDER_TIMEOUT`。
  - 响应体读取共享同一总 deadline。
  - 迟到的 send/body task 由 observer 消费并在完成后释放资源。
  - 普通 `AnalyzeAsync` 与 `AnalyzeReferenceLearningAsync` 同时修复。
- `tests/Desktop.Infrastructure.Tests/VolcArkAiAdapterTests.cs`
  - 发送阶段忽略取消；响应体阶段忽略取消。
- `tests/Desktop.Infrastructure.Tests/ReferenceLearningAiInfrastructureTests.cs`
  - 参考学习发送/响应体两阶段回归。
