# TPL-LEARN-01 日常批次引用别名修复验证记录

## 范围

本记录只处理“模板已成功保存，但用 24 张目标款照片新建批次后 11 个图片框全部显示分析失败”的日常 `ai-analysis/v1` 传输问题。未修改或覆盖用户源 PSD、参考照片、目标款照片、已保存模板或正式输出，也未放宽引用闭合、未知结果、费用和自动重试安全门。

## 失败证据与结论

- 失败批次为 `batch-f9667a3171bb407f9833baf6700663ef`，包含 1 款、24 张照片和 11 条已确认模板规则。
- 供应商请求已真实发出并返回，ledger/session 为 `TerminalError`；输入 34,377 tokens、输出 2,541 tokens，估算费用 0.282492 CNY。
- 稳定错误码为 `AI_PROVIDER_RESPONSE_REFERENCE_MISMATCH`。因此本次不是上传授权、凭据、16 MiB 请求上限、180 秒超时、模板规则缺失或“AI 尚未返回”。
- 当时生产诊断回调未开启，旧响应未持久化具体不闭合字段，不能追认是 request、model、requirement 还是 asset 中的哪一个字符被改写。但代码审查确认日常链路要求模型逐字返回一个约 80 字符 request ID、一个约 40 字符 model version、11 个随机 `learn_frame_*` ID 和 24 个真实 `asset_*` ID；参考学习链路此前已经因同类问题改为短 frame alias，日常链路尚未同步。

## 修复

1. 模型侧只暴露一次性短别名：request=`request_0`、model=`model_0`、requirement=`req_0…req_10`、asset=`img_0…img_23`。
2. 每个 `image_alias` 文本紧邻放在它标识的图片之前，取消“先放全部图片、末尾再给真实 ID 映射”的易错结构；供应商提示词和动态 JSON Schema 不再暴露源系统真实 request、model、requirement 或 asset ID。
3. 返回后在本机把全部短别名严格映射回本次请求真实 ID，再执行既有结构、重复、排名、几何、集合和请求引用校验。未知、越界、冲突或归一化后重复的引用继续失败关闭。
4. 日常提示词/cache 合同升级为 `ai-prompt/v3`，旧 `ai-prompt/v2` 结果不会命中新批次 fingerprint。
5. WPF 对该稳定错误显示“AI 返回引用不匹配，需要重新建立批次”，并说明 AI 已返回但选图和生成已被阻止；不再统一投影为无法定位的“分析失败”。
