## 修复与聚焦回归

1. `AiRenderPlanFactory` 沿用原资源身份，通过现有模板仓库核对原始导入修订：必须已提交、属于同组、早于当前修订、确实引用该资源。继续核对当前冻结页面/资源身份、hash、长度与结构证据；缺失、草稿、其他组、未来修订或无资源引用的来源继续拒绝。不改 RenderPlan/SQLite/bridge 合同，不复制或重写模板身份。Application 聚焦 19/19；集成首次 39 项通过、1 项测试夹具失败，修正夹具后受影响 2/2 通过，不记作单次 40/40。
2. 原生运行又暴露 LocalAppData 被 Windows 打包启动器虚拟化的问题：逻辑路径与文件句柄最终路径不同，没有 reparse point，原逐字比较误报 `BRIDGE_RESOURCE_BINDING_INVALID`。通过真实生产资源准备器重现后，`BridgeResourceLease.VerifyOpenedPath` 保留精确路径快速匹配；不一致时，以不可删除共享的已批准父目录句柄解析实际父目录，要求完整父目录和叶文件名一致，并复核本地路径及所有祖先的 reparse 限制。没有硬编码包目录、放宽根目录或忽略 hash。
3. `InvalidDataException` 不继承 `IOException`。原异常过滤遗漏导致界面停留“正在生成”且 journal 停在 Submitting；现 session、coordinator 和 WPF 均显式收口，提交前明确失败、提交结果不确定时保留 Unknown/RecoveryRequired，界面解除忙碌并显示恢复状态。复核还发现后一个资源校验失败会遗留前一个租约句柄，已先以测试复现，再补相同异常的释放路径。
4. 最新 solution build 0 警告/0 错误；Infrastructure 资源准备/租约/批次/原子提交/输出预留聚焦 **65/65**；此前本次修改相关 WPF 聚焦 **15/15**。真实生产资源准备器在修复后返回 `RESOURCE_PREPARATION_OK`、模板 inspection 匹配。`git diff --check` 和本次更新文档的本地链接检查通过。
