# WPF UI 测试宿主生命周期隔离修复记录

## 范围

本记录只处理 `Desktop.App.UiTests` 的 WPF 测试宿主隔离。没有修改产品 WPF 启动流程、
AI 请求/传输、调度、缓存、模板规则、PSD worker 或用户数据。

## 原始复现

修复前执行：

```powershell
dotnet test tests/Desktop.App.UiTests/Desktop.App.UiTests.csproj -c Release --no-restore --logger "console;verbosity=normal"
```

测试宿主在 7 个用例通过后进程中止。FailFast 调用链为：

```text
System.Windows.Application.GetResourcePackage
System.Windows.Application.GetResourceOrContentPart
System.Windows.Application.LoadComponent
Desktop.App.App.InitializeComponent
WpfShellTests.FirstScanRequiresExplicitUncheckedUploadConsentAndContinuesAfterGrant
```

这不是普通断言失败，也不是 AI/网络超时；测试进程在 WPF 资源包内部不变量检查处被直接终止。

## 根因

旧 `RunInSta` 为每个用例创建新的 STA 线程，并在用例前后通过反射写入 WPF 私有静态字段
`_appInstance`、`_appCreatedInThisAppDomain` 和 `_isShuttingDown`。每个窗口场景又调用
`Application.Shutdown()`，线程最终调用 `Dispatcher.InvokeShutdown()`。同一测试进程因此反复：

1. 创建并初始化新的 `Desktop.App.App`；
2. 关闭 Application 和 Dispatcher；
3. 绕过公开生命周期，手工把 WPF 私有静态状态改回“未创建”；
4. 再次加载 `/Desktop.App;component/App.xaml`。

WPF 的 `Application` 是每 AppDomain/进程单实例生命周期对象。反射重置只能改动少数私有字段，
不能恢复资源包、Dispatcher 和其他内部缓存的一致状态，因此后续 `InitializeComponent()` 进入
`Application.GetResourcePackage` 时触发 FailFast。禁用 xUnit 并行不能修复这一生命周期破坏。

## 修复

`tests/Desktop.App.UiTests/WpfShellTests.cs` 改为测试进程内共享一个 WPF 宿主：

- 一个后台 STA 线程；
- 一个持续运行的 Dispatcher；
- 一个测试专用 `Application`，只装载一次当前 `DesignSystem.xaml`、
  `BooleanToVisibilityConverter` 和 `BoundedPreviewImageConverter`；
- 测试专用 Application 屏蔽生产 `App.OnStartup`，避免启动真实单实例协调器、默认数据根和服务组合；
- 每个场景同步投递到同一 Dispatcher，完成后只关闭遗留窗口、清空 `MainWindow`、恢复
  `OnExplicitShutdown` 并排空公开 Dispatcher 工作；
- 测试间不调用 `Application.Shutdown()`、`Dispatcher.InvokeShutdown()`，也不反射修改任何 WPF
  私有状态；测试进程退出时由操作系统结束后台宿主线程。

新增 `WpfHostReusesSingleApplicationAcrossSequentialWindows`，连续两次创建真实 `MainWindow`、
读取应用资源并断言 Application/Dispatcher 为同一实例，且关闭窗口后 Application 仍有效。

## 验证结果

| 验证 | 结果 |
| --- | --- |
| 新宿主聚焦回归 | `1/1` 通过 |
| `Desktop.App.UiTests` 全量 | `36/36` 通过，未出现 FailFast |
| WPF 全量连续三次 `--no-build` | 每次均 `36/36` 通过 |
| Release solution build | 通过，`0` 警告、`0` 错误 |
| 完整 solution 聚合回归（排除仓库明确缺失的 `SizeTableGoldSampleTests`） | `648` 通过、`5` 个显式真实环境探针跳过、`0` 失败；WPF 在聚合中 `36/36` |
| 目标文件格式检查 | `dotnet format ... --verify-no-changes --include tests/Desktop.App.UiTests/WpfShellTests.cs` 通过，`0` 文件变化 |
| 私有状态/关闭调用扫描 | `_appInstance`、`_appCreatedInThisAppDomain`、`_isShuttingDown`、`InvokeShutdown`、逐用例 `Application.Shutdown` 均为 `0` 命中 |

完整 solution 聚合命令：

```powershell
dotnet test EcommerceDetailPage.Desktop.slnx -c Release --no-build --no-restore --filter "FullyQualifiedName!~SizeTableGoldSampleTests" --logger "console;verbosity=minimal"
```

## 结论与边界

`Application.GetResourcePackage` 崩溃已从“可稳定复现”变为 WPF 全量多轮与 solution 聚合均不再
出现，测试宿主阻断关闭。该修复不改变 ADR-028/029 的 AI 传输策略，也没有发起真实 API 请求。
产品负责人仍需独立完成 `TPL-LEARN-01` 的真实 WPF 逐框业务走查；自动化宿主修复不能替代该产品验收。
