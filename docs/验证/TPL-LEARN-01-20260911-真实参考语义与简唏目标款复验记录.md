## 修复过程与真实结果

### 1. 请求体超限根因

首次真实复验发现参考学习仍固定使用旧 `wic-bounded/max1600/jpeg-q82/png/v1`，11 张 PNG 组合后的最终 JSON 请求体被安全门拒绝为 `AI_PROVIDER_REQUEST_TOO_LARGE`。这不是未知结果，也不是凭据错误。

已修复：

- `ReferenceLearningAiService` 的参考学习副本、cache fingerprint、兼容性检查和请求合同统一使用已批准的 `wic-bounded/max1600/jpeg-q82/png-opaque-jpeg/v2`；
- `reference-learning-ai-v2.schema.json` 明确兼容历史 v1 和生产 v2，当前学习请求固定发 v2；旧 v1 cache 不会被当前路径复用。

### 2. 多框结果引用闭合

切换 V2 后，供应商返回的长随机 `frame_id` 未通过当前请求闭合校验，系统安全返回 `AI_PROVIDER_RESPONSE_REFERENCE_MISMATCH`，没有把结果写成成功。

已修复：供应商提示词只暴露本次请求的短序号 `f_01` 至 `f_11`；适配器在本地按请求内序号映射回真实 `frame_id`，未知、重复、缺失或越界 ID 仍然 fail closed。
