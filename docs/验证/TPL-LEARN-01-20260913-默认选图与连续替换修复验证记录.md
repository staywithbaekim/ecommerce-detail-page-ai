# TPL-LEARN-01：默认选图与连续替换修复验证记录

## 1. 验证范围

本记录对应 2026-09-13 已批准的 ADR-030，验证以下产品行为：

- AI 返回 `exact` 且置信度 `≥0.85` 时直接判绿，不受第二候选分差或同分影响。
- AI Top-1 是默认确认结果，不要求用户逐框点击确认；只有低于绿色置信度门槛、实质语义差异/冲突、主体边界建议检查，
  或错款/错变体、缺图、不安全、无效结果等受控风险才进入黄/红门禁。
- 替换路径固定为“替换用图 → 选照片 → 确认”，确认后立即刷新左图、状态和使用次数。
- 同一图片框或不同图片框可以连续替换，后续替换不触发请求账本 CAS 冲突，也不额外调用 provider。
- 用户界面显示动态图片类别语义，不显示“图片框 N”、`frame_*`、“选用这张”或“待保存”。

本轮只做本地代码、自动化和隔离启动验证；未调用真实 API，未修改源 PSD、源照片、人工参考结果或正式
输出目录。

## 2. 根因与修复

第一次人工锁图会把请求账本从 `Validated` 转为 `ManualReview`。旧实现对第二次及之后的替换再次写入
同一个终态，检查点请求 CAS 因状态版本不再匹配而返回 `AI_CHECKPOINT_REQUEST_CAS_CONFLICT`，所以表现
为“只有第一张能替换”。

现实现把选择次数放在会话选择 revision：首次锁图按原流程更新账本；账本已经是 `ManualReview` 时，后续
操作只递增 `selection_revision`、写入新的锁定映射并重建投影，不重复写同一终态。失败时保留旧图，重试
不会产生 provider 请求。

## 6. 2026-09-13 语义风险门收口

本轮补齐 `safe_similar` 的同分、近分和低于绿色门槛回归，并移除用户可见的“候选接近”告警。当前黄色文案表达可行动
原因：候选未达到绿色置信度门槛、模型明确返回 `material_difference`/语义冲突，或缺少主体边界需要检查；候选分差和
同分本身不再触发黄色。隔离 smoke 的 SQLite `PRAGMA integrity_check` 为 `ok`，最新 `app_instance.safe_exit` 为 `1`。

本轮未调用真实 API，未修改源 PSD、源照片、人工参考结果或正式输出。原生 WPF 截图级手动验收仍需产品负责人执行，
