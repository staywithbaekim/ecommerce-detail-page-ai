## 范围与实现

沿用 owner、broker、输出 reservation、独立媒体 validator 和 SQLite 单 writer。RENDER-S4/S6 要求输出、manifest、checkpoint 与 marker 四方一致；没有新增替代桥接器、迁移版本、运行时或工作树，生产 availability 守卫仍保留。

- 已验证字节继续由 reservation 持只读租约；同目标 artifact 有独立排他 `.reservation` 锁，跨页面目录移动仍保持锁。逻辑 ID 经固定摘要编码成为安全目录段，不将冒号或设备名直接用作路径。
- 目标卷 `.app-staging/<batch摘要>/<款与页摘要>/<本次plan摘要>/` 存放上传原件；`page/` 中创建命名 JPG/PSD 提交副本，flush、hash 和文件集合检查后原子写入 manifest。plan 摘要目录代表不可变 attempt 身份，数字 attempt 同时进入 checkpoint；不覆盖已有页面索引。
- 单 SQLite 事务写入 Verified checkpoint 和 render_verified manifest；最后写入并校验页 marker；同卷移动整个 page 目录到从计划绑定的 artifact 目录；重新打开全部文件、禁止写入和删除，复核完整集合/长度/hash/manifest/marker 后，单 SQLite 事务写入 Committed、render_committed、PageCommitted 事件与任务投影。
- Windows 真实文件句柄探针确认，子文件使用 FileShare.Read 或 Read|Delete 时目录移动均失败；关闭子句柄后成功。实现因此在持续持有目标排他锁的情况下关闭提交副本子句柄、移动，再立即重新锁定并校验；原上传字节租约仍保持。交接期间任何差异都不能推进成功状态。
- copy/hash/SQLite 操作不持 broker transport gate；提交开始后取消推迟到下一页安全边界。断线可以先登记 unknown，已验证本地提交仍可完成；不会释放正在提交的 reservation。成功事件仅桌面端在提交完毕后生成，UXP 不能直接上报 execution_completed。
- 恢复核对指定 manifest、固定允许路径、排他锁、文件集合/hash、marker、SQLite 身份/attempt/digest/时间/状态，以及 broker 执行身份。缺失或冲突不重建未知半边，不重复调用 Photoshop。普通 checkpoint API 禁止创建或覆盖 render_output 记录。
- UXP 在 page_completed 后查询认证 execution 事件；只有连续且身份相同的 execution_completed 才释放本页临时资源，未知/缺事件/错序号均断开，不重执行。
