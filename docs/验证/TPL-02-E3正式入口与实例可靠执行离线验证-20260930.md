## 2. 真实调用链

1. WPF 现有批次命令选择已提交模板 → `BatchInputService.CreateDraftFromTemplateAsync`。无规则/alias-only 使用原 `BatchTemplateSnapshot`；有规则使用独立 `BatchRuleTemplateContext`。旧 Create/Replace 安全门 `TPL_RULE_INSTANCE_PIPELINE_REQUIRED` 不删除，不清空 Rules，不借旧 Restore 绕门。
2. 原 INPUT-01 扫描/清单/journal → `SqliteDesktopStore` 保存真实 BatchId、Styles、目标资产和选中修订上下文。新规则只允许全规则页面集合；部分选择明确拒绝 `TPL_RULE_CONTEXT_ALL_PAGES_REQUIRED`，不是暗中裁剪配方。
3. WPF `AiAnalysisViewModel.PrepareRenderingCommand` → `IAiBatchAnalysisWorkflow.PrepareRenderingAsync` → `AiRenderPreparationService.PrepareInstancesAsync`。全批分析状态必须闭合；从 `AiAnalysisResultReader`、session、batch assets、已提交修订/模板资源读取事实，非临时 UI 对象或调用方 Scope 授权。
4. 每款逐 FrameId/VariantId 取证；复用 `AiTargetMatchPolicy`，不取“第一个副色”。持久化选图、颜色成员、人工版本、主体几何；E0 投影 → E3 生产证据先冻结 → E1 首次 CAS 冻结 → E2 完整 Members 规划（含业务红和合法空展开）。固定 `production_ + ProjectionDigest` 命令可恢复 evidence-first/E1 之间中断；已存在 E1 但缺生产证据则拒绝，不猜事实。
5. 原 `RenderBatchCoordinator.PrepareAsync` 经正式 DI 延迟解析实际调用。`SqliteDesktopStore.ValidateInstanceRegistrationAsync` 以仓储批次、款式、context、E1/生产事实重建全体计划并核对完整成员、各页及每款 `InstanceSets` 摘要；任意 Scope、漏红成员、篡改准备或摘要均不授予执行权限。延迟 `Func<IRenderBatchWorkflow>` 仅解除 repair admission 构造循环，未另建执行协议。
6. 有健康计划时 WPF 原 `StartRenderingCommand` → `RunAsync` → 正式 `BridgeRenderBatchSessionFactory` → `BridgeSessionOwnerFactory` → `RenderBatchResourcePreparer` → 原 `BridgeExecutionBroker` → UXP 执行一个明确单页 RenderPlan。无计划时 workflow 经同一 Coordinator 收口，不开 Photoshop 队列。
7. Broker execution journal → 独立媒体验证 → `RenderPageCommitter` → SQLite Verified → 文件 manifest/marker/目录提交 → SQLite Committed/唯一页面计数 → `RenderStyleOutputPublisher` → 原公开命名/目录规划 → `RenderBatchOutputReader` → `ResultReviewViewModel` 的实例计数、选择、预览、原因和恢复命令。

### 实例人工锁和冻结生命周期

现有 AI 复核页“确认/替换用图”实际调用 `ITemplateInstanceSelectionWorkflow`（由同一 `AiBatchAnalysisWorkflow` 实现）。先用真实记录生成只读实例目标，用户明确选择一个实例再确认；候选不属于其颜色组时不提供该目标。预览不冻结、不建计划、不生成尺码栅格。

人工锁按 `(SourcePageId, BranchId, RecipeId, RepetitionIndex, FrameId)` 保存，款级 revision CAS，绑定基础事实 digest；重开能读取已选 AssetId/SelectionRevision。原 frame-global 锁仅在无歧义时迁接；不能复制给多个实例。新规则正式旧框锁 API 明确拒绝，UI 不再走该入口。

冻结事务核对 session selection revision 与实例人工 revision；仓储拒绝冻结后改锁。正式尺码编辑与 prepare/freeze 使用同一 admission，文件仓储也拒绝已冻结款的改写。迟到 AI 记录不能覆盖冻结证据；恢复只消费冻结事实。**修正输入、几何、尺码或锁后须新建批次；未开放 E1 原位更新/二次编辑。** 跨进程绕过正式工作流直接修改尺码文件与首次冻结的并发窗口，没有完整压力/故障注入证据，不声称多进程跨介质原子提交。

## 4. 普通页与动态尺码

普通实例只带自己的选图及已保存主体几何，复用原 builder 的绝对 placement 验证；没有无条件丢弃几何或跨实例借图。

尺码复用 SIZE-01 repository、校准、确定性栅格和 `SizeTableRenderPlanBuilder`，逐 SourcePageId 准备后给每个 PageInstanceId 独立 plan/artifact/名称。核对当前款 SourceAssetId/hash、逐格数据/DataDigest、模板 hash/长度、revision、校准目标/版本和栅格受控地址。资源地址必须为 `batches/{batch}/size-tables/{style}/{sourcePage}/resources/{resourceId}.png`；正式租约再次校验实际用途、长度/hash、路径和归属。市场尺码图只是来源证据，不作为 render resource。

缺失/冲突/需人工复核等白名单原因只隔离尺码实例；坏校准、能力未配置、错误资源路径/hash、正文不一致不降级为缺图。普通页不注入尺码资源。E0 `RequiresProductionValidation` 未改义；E3 附加准备证据通过后才可规划。不在模板保存时要求目标款尺码图。

JPG-only 延续 ADR-014 2026-09-24/P0 的现行生产语义：不输出 verification_psd，不伪造 PSD 内部层检查。计划/输入 hash 和已登记计划 digest 仍闭合；只有用户选择可编辑 PSD 时才有独立 PSD 结构证据。F 必须分别验证两种输出选项。旧 v1 带验证收据的读取仍兼容。

## 5. 隔离、恢复与发布行为

- Ready/PartiallyReady 是规划状态；CanContinue 不是执行授权，更不是完成。全分析/准备闭合后才启执行；红实例占位和下一步保留。
- 混合业务红 + 健康：只执行健康实例，实际提交成功后才可能 CompletedWithIssues。全业务红 → UserActionRequired；合法零展开 → Empty；全取消 → Cancelled；全明确执行失败 → Failed。新分类仅用于 v4，旧 journal 的终态语义保持。
- Committed：独立核对原文件、manifest/marker、SQLite 证据及 Instance/PlanDigest 后跳过；不是只信 UI 状态。刷新/重复事件/重开不重复计数。
- Unknown/提交确认丢失：先按持久化幂等键查询并核对原 ExecutionId。不能换 attempt/key/ExecutionId 重投；无可靠终态保持 RecoveryRequired。
- 已明确 Failed：仅对应实例追加 attempt/新计划身份，通过原事实等价、登记 origin 和任务重开协议；成功实例与 Unknown 不准重试。公开发布 intent 已登记的款不开放二次编辑。
- 文件提交后数据库确认失败：沿既有 Verified → 文件提交 → Committed 协议恢复，不假设 SQLite 与文件系统同事务；登记丢确认、关闭重开也不重造执行记录。
- 公开发布失败：消费已有独立核验的内部提交，恢复发布，不创建 renderer session、不重复渲染。取消/暂停仍遵守原款边界和当前页安全收口。
