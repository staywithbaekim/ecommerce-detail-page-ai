# TPL-LEARN-01 结果未知时人工锁定修复验证记录

## 触发问题

产品负责人在款式检查页看到全部图片框为“结果未知，禁止重发”。进入“替换”后可以选中候选照片，
但点击“改用这张”没有可见结果。两张问题截图分别生成于 2026-09-12 14:31:15 和 14:32:17。

第一项状态与第二项交互不是同一问题：

- `AiResultUnknown` 表示真实请求已经越过 HTTP 边界，但在批准的 180 秒内没有取得可验证结果；依据
  ADR-015 与 ADR-026，旧请求必须保持未知且禁止自动重发，不能事后改写为成功。
- 原实现虽然在未知状态页保留了“替换”入口，但领域会话和 scheduler 只允许对
  `Validated/ManualReview` 锁图，点击后以 `AI_SELECTION_NOT_AVAILABLE` 被拒绝；页面底部又只显示静态说明，
  因而用户看到的是“按钮没有反应”。这是前后端合同未闭合，不是用户操作错误。

## 修复

- `AiAnalysisSession` 允许 `AiResultUnknown` 会话保存本地人工锁图，但状态继续保持
  `AiResultUnknown`，`HasVerifiedResult` 继续为 `false`。
- scheduler 只在 ledger=`AiResultUnknown` 且 `result_reference=null`、请求与会话身份完全一致时放行；
  只递增 selection revision 并保存 lock，不创建 result reference、cache 或 usage，也不调用 provider。
- SQLite full-batch checkpoint 接受未知状态内恰好递增一次的 selection revision，保持 CAS 与恢复门。
- 投影对已锁定框显示“人工选用 · 已锁定”，未锁定框继续显示“结果未知，禁止重发”。重启后锁定仍保留。
- 款式检查页底部改为显示实际成功/失败消息；本地持久化异常显示“本地选图保存失败”，不再吞掉错误。

## 验证

- 聚焦复跑：
  `UnknownSelectionLockPersistsWithoutChangingUnknownLedgerOrCallingProvider`、
  `UnknownFirstLayerKeepsSystemStateWhileManualLocksPersistAndProjectPerFrame`、
  `AiStyleReviewShowsAllUsageAndAssetsAndReplacesWithoutProviderRequest`，3/3 通过、0 失败。
- 完整离线 solution：630 通过、4 个显式外部/真实探针跳过、0 失败。
- `dotnet format --verify-no-changes` 与 `git diff --check` 通过。
- 独立启动 smoke：进程响应、退出码 0、SQLite `quick_check=ok`、migration 12、`safe_exit=1`，worker 存在。
