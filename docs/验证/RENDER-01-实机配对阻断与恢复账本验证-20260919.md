## 独立推进的恢复边界

`FileBridgeExecutionJournalStore` 原先完整读文件后才检查 16 MiB，现改为打开同一受控路径上的只读文件，读取前及分块过程中限长，写入也拒绝超限。复用既有 `AtomicFileStore` 原子写入；不改变通用 `IFileStore`、RenderPlan 或 bridge wire 合同。探针调用方同步传入现有路径策略。

保留 journal v1 的 PascalCase 文件格式。恢复解析拒绝重复键（含转义同名）、未知字段、缺失必需构造参数、非空字段的 null、损坏 JSON/UTF-8；错误只返回 `BRIDGE_JOURNAL_INVALID`，不附带包含原文的 JSON 异常。

broker 在发布任何恢复记录前验证完整 journal：版本、数量、标识符/幂等键/摘要、状态、事件数量/序号/全局唯一 ID、execution/page 归属、事件 wire Schema、状态迁移及终态一致性。事件回放保留“后来的取消不能否定早先启动”语义。合法终态保持，未完成记录恢复为 unknown，不能重新领取。后部记录损坏时不部分导入前部记录，不写回损坏文件。该账本仍不是业务页面 checkpoint，不等于 S6 已完成。
