## BUG-002: PSD重复检测修复

### 问题描述
用户尝试重新学习已存在的PSD时，系统强制要求处理重复决策，导致工作流中断。每次导入都基于SHA256查询重复，即使在同一草稿中也需要手动决策。

### 根本原因
- 重复检测逻辑没有区分"草稿内重复"和"跨草稿重复"
- 缺少自动重用选项，强制用户每次手动选择
- 没有记住用户偏好的机制

### 修复方案

#### 1. 新增 `AutoReuseDraftDuplicates` 决策选项

**文件**: `src/Desktop.Application/Templates/TemplateImportContracts.cs`

```csharp
public enum TemplateDuplicateDecision

    AutoReuseDraftDuplicates  // 新增
}
```

## BUG-004: 删除模板功能修复

### 问题描述
无法删除草稿或已提交的模板，没有明确错误提示。用户点击删除后没有任何反馈，模板仍然存在。

### 根本原因
1. 批次引用检查返回阻止者列表，但UI没有正确显示
2. 文件占用（File Locks）导致删除失败，但没有异常捕获
3. `Directory.Delete` 调用没有重试机制
4. 异常没有被转换为用户友好的错误消息

### 修复方案

#### 1. 增强文件删除逻辑（带重试机制）

**文件**: `src/Desktop.Infrastructure/Templates/TemplateOwnedStorage.cs`

完全重写 `DeleteGroupFilesAsync` 方法：

```csharp
public async Task DeleteGroupFilesAsync(string groupId, CancellationToken cancellationToken)
{
    TemplateValueRules.Identifier(groupId, "TPL_GROUP_ID_INVALID");
    cancellationToken.ThrowIfCancellationRequested();
    var directory = paths.ResolveOwnedPath($"templates/groups/{groupId}");
    if (!Directory.Exists(directory))
    {
        return;
    }

    // 重试逻辑处理文件锁
    const int maxRetries = 3;
    var retryDelayMs = 100;

    for (var attempt = 0; attempt < maxRetries; attempt++)
    {
        try
        {
            // 强制GC释放文件句柄
            if (attempt > 0)
            {
                GC.Collect();
                GC.WaitForPendingFinalizers();
                await Task.Delay(retryDelayMs, cancellationToken).ConfigureAwait(false);
                retryDelayMs *= 2;
            }

            Directory.Delete(directory, recursive: true);
            return;
        }
        catch (IOException) when (attempt < maxRetries - 1)
        {
            continue;
        }
        catch (UnauthorizedAccessException) when (attempt < maxRetries - 1)
        {
            continue;
        }
    }

    // 所有重试失败后抛出友好错误
    throw new IOException(
        $"TPL_DELETE_FILES_LOCKED: Unable to delete template group files at {directory}. " +
        "Files may be in use by another process.");
}
```

**关键改进**:
- 3次重试机制（延迟100ms, 200ms, 400ms）
- 强制GC回收释放文件句柄
- 区分 `IOException`（文件锁）和 `UnauthorizedAccessException`（权限）
- 友好的错误消息

#### 2. 添加异常处理层

**文件**: `src/Desktop.Application/Templates/TemplateWorkspaceService.cs`

在 `DeleteTemplateGroupAsync` 方法中添加异常捕获（第813-843行）：

```csharp
public async Task<IReadOnlyList<string>> DeleteTemplateGroupAsync(
    string groupId,
    CancellationToken cancellationToken)
{
    try
    {
        var blockers = await templates.GetBlockingBatchIdsAsync(groupId, cancellationToken)
            .ConfigureAwait(false);
        if (blockers.Count > 0)
        {
            return blockers;
        }

        await templates.DeleteGroupAsync(groupId, cancellationToken).ConfigureAwait(false);
        if (ownedStorage is not null)
        {
            await ownedStorage.DeleteGroupFilesAsync(groupId, cancellationToken).ConfigureAwait(false);
        }
        return [];
    }
    catch (IOException ioException)
    {
        throw new IOException("TPL_DELETE_FILES_FAILED", ioException);
    }
    catch (UnauthorizedAccessException accessException)
    {
        throw new IOException("TPL_DELETE_ACCESS_DENIED", accessException);
    }
}
```

## 风险评估

### BUG-002 修复风险

| 风险 | 等级 | 缓解措施 |
|-----|------|---------|
| 自动重用错误的重复副本 | 低 | 严格限制在相同 GroupId 和 DraftId 范围内 |
| 破坏现有手动决策流程 | 低 | 保留 NotSpecified 选项，只改变批量导入默认值 |
| 跨草稿混淆 | 低 | 明确检查草稿边界，跨草稿仍正常导入 |

**结论**: **低风险**。修复是增量式的，不影响现有功能。

### BUG-004 修复风险

| 风险 | 等级 | 缓解措施 |
|-----|------|---------|
| 重试机制延迟用户操作 | 低 | 总延迟最多700ms（100+200+400），可接受 |
| GC强制回收影响性能 | 低 | 只在重试时调用，且删除操作不频繁 |
| 部分删除（元数据删除但文件未删除） | 中 | 异常在文件删除阶段抛出，元数据已删除需要手动清理 |
| 异常消息过于技术化 | 低 | 提供中文友好消息，明确操作步骤 |

**结论**: **中低风险**。重试机制可能在极端情况下延迟响应，但显著提高成功率。部分删除情况需要文档说明。

## 2026-09-11 BUG-004 两阶段删除修正

后续真实 Windows 文件锁探针复现了初版实现的中风险缺口：当 `Directory.Delete` 持续失败时，SQLite 元数据已经删除，应用自有模板文件会成为 UI 不可见的孤儿。当前实现已改为：

1. 将 `templates/groups/{groupId}` 原子移动到 `templates/deleting/{groupId}-{guid}`；若文件锁导致暂存失败，不执行元数据删除。
2. 暂存成功后删除 SQLite 元数据；数据库删除失败时，以不可取消动作将目录恢复到原路径。
3. 元数据提交成功后，以不可取消动作清理 tombstone；用户取消不会中断提交后的清理。

真实锁定回归确认：文件被持续占用时返回稳定失败，SQLite 元数据与原目录均存在；释放锁后重试成功，元数据、原目录和暂存目录均清除。Application `TemplateWorkspaceServiceTests` 13/13，Infrastructure `TemplateOwnedStorageTests|TemplateRepositoryTests` 13/13；完整离线 solution 为 598 通过、4 跳过、0 失败。删除范围仅限路径策略解析后的应用自有模板目录，用户源 PSD、照片和正式输出不在删除范围。

因此，本文初版风险表中的“元数据已删除需要手动清理”不再描述当前实现。完整 DATA-01 的任务删除、缓存清理、存储迁移及产品 UI 走查仍需各自验收。
