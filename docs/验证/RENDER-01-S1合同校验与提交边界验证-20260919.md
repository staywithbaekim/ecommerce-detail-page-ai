## 2. 首次失败与修复

首次完整构建成功，既有 `BridgeWireValidatorTests` 为 **15 通过、3 失败**。三项都在合法握手拒绝响应处失败：根 `body.oneOf` 同时匹配 `handshakeResponse` 与 `responseEnvelope`，与“只能命中一个”矛盾。

兼容修正只将根联合改为 `anyOf`，仍由 `envelope_kind` 的条件分支选择精确 body；所有未知字段限制不变。补充两种合法拒绝和三种 discriminator 错配的正反例，不改变版本、端点或鉴权语义。协议文档和 ADR-013 已同步该澄清。

复核另外修复：

- 协议错误遍历曾进入未经 RenderPlan 校验的 payload；任意名为 `error` 的对象可能触发缺字段异常。现在只检查协议声明的 body.error 和 events[].error，未知计划字段由 Application 拒绝。
- 提交摘要比较按 SHA-256 十六进制大小写不敏感执行，与冻结 Schema 和既有 RenderPlan 校验一致；correlation/idempotency 仍精确匹配。
- event 信封不能误作 response；错误代码、retryable、scope、本地文案及 details allowlist 经验证，拒绝原始异常/路径；响应事件保持执行身份一致、ID 唯一、序号递增且不超水位。

## 3. 新增的执行前边界

`BridgePlanSubmissionService` 使用既有 wire 和 RenderPlan 校验器，只有计划、摘要、页面身份及资源/输出绑定闭合后才调用 `IBridgePlanSubmissionPort`。只读用途、hash/长度、唯一句柄、artifact 和覆盖策略都须匹配；禁止 analysis_copy、市场图角色、路径句柄及任意命令。

调用前取消不触达端口。端口区分明确未送达、收到响应及不确定：开始调用后取消、缺失/非法/身份错配响应、反序列化失败均返回 `BRIDGE_EXECUTION_UNKNOWN`，不自动重试。受控端口测试验证调用次数为零或一次；它不是实际网络丢包试验。`accepted` 只描述接收，不能关闭页面 checkpoint 或正式输出。

`BridgeWireMessageReader` 在 Infrastructure 层读取单条已分帧消息：

- 按方向/端点限制 1 MiB、8 MiB 或 256 KiB；已声明超限不读取，未知/虚假长度最多读取上限外一个判定字节。
- 严格 UTF-8，长度错配、截断、错误 Schema 均拒绝；断流不返回部分 JSON，不输出底层异常。
- 取消交由 transport owner 判断已发送状态；响应断流不能被分类为“计划未发送”。
- 不记录 token/绑定句柄，结果 `ToString()` 不展开消息；共享缓冲归还时清零。流释放、HTTP header/编码、截止时间、鉴权和会话由后续 HTTP owner 负责。

目前这些边界没有接入生产 DI。`UnavailablePhotoshopAvailabilityPort` 仍阻断正式出图，`IBridgeClient/MockBridgeClient` 仍是原基础实现，未被改名冒充正式通道。
