## 本轮范围

### 实现

- Application 新窄 `ISizeTablePageRepairWorkflow` 复用同一个 `RenderBatchCoordinator` 运行锁、写锁及单页调度；请求绑定 batch/style/page/variant、journal/attempt/plan/table revision 与 digest。重复同请求只返回原登记，内容冲突/陈旧基线/同级 Unknown 拒绝。
- `SizeTableRepairData` 严格、受限快照 JSON（4 MiB）、重复/未知字段拒绝、领域规则与数据 digest 重算；不归一化尺码原文、不猜值、无实际变化拒绝。UI 使用 Application DTO，不直接依赖 Domain。
- `SizeTablePageRepairPreparer` 核对冻结模板、资源和来源 hash，读取同页最近有效 repair 快照（普通 regen 沿祖先读取），不保存生成前 current。复用原 SIZE 编辑/rasterizer/resolver/builder，仅生成目标页候选。
- `RenderPlanSizeTableRepair` 白名单只允许尺码结构、相应唯一 PNG、确定性 contain-center placement 与新执行身份变化；模板、普通图片、隐藏层、输出名、PSD 意图等保持。原 `PreservesFacts` 未放宽。
- PNG 同内容身份同字节复用、不同字节拒绝，候选写后读回；失败不覆盖旧资源。候选本身不能触发执行。
- journal v3 带基/新尺码快照 origin；SQLite v18 新请求索引与 attempt origin、journal、`RenderPageRepairRequested`、任务投影同事务。v1/v2 原字节不回写，v3 后普通 regen 不降级；通用事件写口不能伪造修复。旧二进制不支持 v18。
- AI 准入租约借既有 workflow gate 阻止新命令进入，核对生产者、consumer、复制准备、持久化历史请求、恢复状态均收口；缺失/空调度证据不当作安全。租约跨候选准备和 SQLite 登记保持，不调用新 AI、不整批重新 preparation。
- O-03 加载精确修复基线；按钮为“保存修复并生成当前页”。保存中锁定编辑/关闭/切批；响应不明冻结同一 request 和草稿，再试不另建 attempt。成功关闭编辑器，回结果总览的连接/暂停/恢复入口并保持目标变体；已运行/完成的丢失响应不自动再次执行。原生成前保存和不支持旧形状仍受门禁保护。
- 多端口 DI 指向同一个 coordinator/AI workflow；补充幂等 Dispose，防止容器别名释放同一实例造成二次取消/释放错误。
