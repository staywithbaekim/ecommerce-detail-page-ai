# AI-01 S4 WPF 纵向接入任务书

## 1. 任务目标与基线

- 任务：`AI-01-S4`。
- Git 起点：`codex/desktop-foundation-01`，必须包含 AI-S2/S3 最终实现头 `8cd28b4371432a3fd16511a03aaa72eeee27b9fa` 及其治理关闭记录。
- 目标：把已合并的 INPUT-01 批次、AI 调度/结果/恢复生产者接入实际 WPF B-02/B-03，形成可运行、可恢复、可人工处理的生成前检查纵向链，并完成实际应用人工视觉走查。
- 产品与交互来源：PRD 1.5、`docs/设计/桌面端页面信息架构与交互规格-v1.2.md` 6.5/6.6、冻结 Figma 文件 `3lqnFu70Gj9hBQDV31Svj9`、`docs/任务/桌面端高保真视觉与组件规格.md`。

## 2. 前置门

开始实现前必须同时确认：AI-01 验收矩阵为 S0-S3 已通过；`8cd28b4` 在 HEAD 祖先链；`BatchDraft`、模板快照、asset manifest、AI scheduler/result/cache/checkpoint 的实际生产代码存在；工作树干净。路由文字与代码不一致时先停下纠正，不得用 mock 页面替代缺失生产者。

## 3. 范围

- B-02 不是独立等待页；点击“扫描并分析”后立即进入 B-03，并在同页渐进显示待分析、分析中、人工配置、可生成、待检查、不可生成。
- 按批次、款式和页面持久化刷新；接入真实 pause/cancel/waiting-for-network/budget-stop/result-unknown/restart 状态，不在 Presentation 复制 AI 状态机或供应商 DTO。
- 接通人工选图、锁定、Top-N 切换和逐图主体分析的现有 Application 合同；人工锁定后不得上传未选候选。
- 页面级业务红只隔离当前页；全取消、全业务红、单款业务零输出、系统/渲染失败必须按 PRD 分因，禁止启动 Photoshop。
- 中文错误必须给出下一步动作，不显示模型 ID、结构签名、Key、供应商原文、本机路径或内部异常。
- 实现冻结 Figma B-03 宽版 `77:3`、主工作区 `78:48`、窄版 `90:241` 及 HIFI-02 取消/零输出补充节点；复用现有 `DesignSystem.xaml`，不得建立第二套视觉系统。

## 4. 非目标与安全边界

- 不执行真实金标、准确率或 P95 结论；这些属于 S5。
- 不实现 RenderPlan/Photoshop 正式批量渲染、平台上传、账号、支付、云同步、动态尺码或设置页扩展。
- 用户源 PSD、照片、人工结果和尺码图永远只读；不得提交媒体、数据库、缓存、日志、凭据、截图生成物或外部资料。
- 保持供应商无关合同和 renderer-neutral RenderPlan；AI/产品规则不得进入 Photoshop adapter 或 WPF code-behind。

## 5. 验收与走查

- 自动验证覆盖状态投影、命令启用、人工选择、逐页红色隔离、零输出分因、暂停/取消/断网/费用停止/未知结果、重启恢复、长列表和敏感信息不泄漏。
- 实际 WPF 应用必须人工走查代表状态；不能用截图、fixture 或自动化测试替代。至少核对 1440×900、1100×760、100%/125% DPI、键盘焦点、中文输入、UIA、长列表滚动和宽窄布局。
- 走查按冻结 Figma/交互逐项记录差异；需要改变产品行为或冻结设计时回产品负责人选择，不得自行改 Figma 目标。
- 完成候选必须包含 reviewed diff、build/完整 solution/format/diff、安全扫描、未跟踪文件审查，以及任务书、验收矩阵、当前状态和验证记录同步。

## 6. 执行节奏

普通本地实现、测试、文档修正连续完成，不因小提交或单个 checkpoint 回治理。只有同一技术阻断连续两次、资源异常、需要新的产品选择，或形成完整候选等待 reviewed diff 时回治理主线。S4 候选未通过治理合并门前不得进入 S5。
