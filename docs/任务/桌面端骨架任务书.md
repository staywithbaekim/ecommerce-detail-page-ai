## 2. 任务目标

建立可启动、可测试、可恢复的桌面端最小骨架，为 `TPL-01`、`AI-01`、`SIZE-01` 和后续渲染集成提供稳定边界。骨架必须先把分层、状态持久化、事件回放、契约校验、mock 端口、单实例和 UIA/窄窗口验证接通；不得用临时 Demo 代替正式产品边界。

## 3. 前置输入与必须遵守的决策

- `ADR-011`：WPF + `.NET 10 x64`、Windows 11 x64 和 Photoshop 2025 `26.8.1` 逐机准入边界。
- `ADR-012`：SQLite WAL、单实例/单 writer、manifest/checkpoint/journal、页级原子提交和迁移恢复。
- `ADR-013`：仅回环 `ps-bridge/v1`、配对、token、心跳、幂等、断线查询和请求体限制。
- `ADR-014`：renderer-neutral RenderPlan v1 及独立 Schema；禁止路径、token、Photoshop 命令和 adapter 私有字段进入计划。
- `ADR-015`：火山方舟只存在于 Infrastructure adapter，凭据按请求注入；模型配置在 AI-01 前保持 `proposed`。
- `ADR-016`：当前用户签名 bootstrapper 与配套 `.ccx` 的发布边界；阶段 0 不制作客户发布包。
- `docs/技术方案/schemas/render-plan-v1.schema.json`、`render-plan-v1.valid.example.json`、`render-plan-v1.examples.md`。
- `docs/技术方案/schemas/bridge-v1.schema.json`、`docs/技术方案/bridge-protocol-v1.md`。

## 4. 骨架边界

### 应建立

1. WPF 应用壳、四个一级导航（工作台、模板、任务、设置）和活动任务条的只读占位投影；布局遵守 HIFI-01/HIFI-02，不把占位页写成业务功能完成。
2. `Domain`、`Application`、`Infrastructure`、`Presentation`、`Contracts` 的项目边界和依赖规则。Domain 不能引用 WPF、SQLite、HTTP、AI SDK 或 Photoshop/UXP 类型。
3. MVVM/DI 启动、命令处理、只读查询投影和统一事件总线；UI 不直接读写数据库或文件。
4. SQLite WAL 初始化、迁移版本表、单 writer 队列、事件表、任务/批次/检查点最小记录和关闭时安全 flush。
5. 任务状态 reducer 与事件回放：至少支持 `Draft`、`Scanning`、`SystemBlocked`、`ReadyToRender`、`Rendering`、`Paused`、`RecoveryRequired`、`Failed`、`Cancelled`、`Completed`、`CompletedWithIssues` 和 `UserActionRequired` 的持久化/回放；零输出守卫不能被 UI 绕过。
6. `IPathPolicy`、`IFileStore`、manifest/checkpoint 接口和脱敏日志接口的 mock/最小本地实现。骨架只生成应用自有测试数据，不接触用户 PSD、源图、尺码图、人工结果或正式输出。
7. `IRenderPlanValidator` 和 `IBridgeClient` 端口；接入 RenderPlan/bridge Schema 正反例校验。mock bridge 只返回协议事件，不启动 Photoshop、不监听真实端口。
8. `IAiAnalyzer`、`IAiCredentialSource`、`IAiUsageRecorder` 端口和 mock 实现；不发真实 AI 请求、不保存 API Key、不引入供应商 DTO。
9. 单实例互斥和重复启动激活现有窗口；主实例退出/锁释放有可回放事件。
10. UIA AutomationId、键盘焦点顺序、可见焦点环、中文输入控件、稳定尺寸列表行，以及 `1100x760` 窄窗口和 100%/125% DPI 的验证夹具。

### 明确不建立

- 不实现 PSD 结构扫描、图片框绑定、模板修订或模板包导入导出。
- 不实现真实火山方舟请求、模型选择、Prompt、候选排序、尺码提取或自然语言修复。
- 不实现真实 UXP `.ccx`、Photoshop 启动、`executeAsModal`、JPG/PSD 导出或 bridge 监听服务。
- 不实现正式安装器、签名、自动更新、账号、支付、云同步、平台上传或商家工作区。
- 不引入生成式图片、尺码数字猜测、固定服装角色枚举或外部 Demo 依赖。

## 5. 目标结构

建议 solution 采用以下职责分层；具体项目名称可在实现时保持语义一致，但不得改变依赖方向：

```text
src/
  Desktop.App/              # WPF 启动、窗口、资源和 UIA
  Desktop.Application/      # 命令、查询、编排、端口调用
  Desktop.Domain/            # 状态机、值对象、规则和事件
  Desktop.Infrastructure/   # SQLite、文件、凭据/日志抽象的实现
  Desktop.Contracts/        # RenderPlan/bridge/事件 DTO 和 Schema 校验入口
tests/
  Desktop.Domain.Tests/
  Desktop.Application.Tests/
  Desktop.Contracts.Tests/
  Desktop.Infrastructure.Tests/
  Desktop.Architecture.Tests/
```

依赖只能从 Presentation -> Application -> Domain；Infrastructure 实现 Application/Domain ports；Contracts 不引用 WPF、SQLite 或 UXP。任何反向依赖必须在架构测试中失败。

## 6. 最小持久化模型

阶段 0 只建立承载后续功能的最小表和迁移，不提前猜完整业务字段：

| 记录 | 最小用途 |
| --- | --- |
| `schema_migrations` | 单调迁移版本和校验 |
| `app_instance` | 当前实例/启动与安全退出摘要 |
| `tasks` | 任务身份、状态、版本和更新时间 |
| `task_events` | 事件 ID、顺序号、类型、脱敏 payload 摘要 |
| `checkpoints` | 任务/款式/页面阶段、attempt、plan digest、桥接 execution ID 和输出提交状态 |
| `manifests` | 应用自有文件相对引用、长度、hash、state |

禁止在阶段 0 保存图片字节、API Key、认证头、绝对路径或 Photoshop 原始响应。迁移失败必须保留旧数据库可读，不能自动删除旧数据。

## 7. 完成条件

### 结构与启动

- 在 Windows 11 x64 可启动 WPF 壳；重复启动激活同一窗口，不能创建第二个 writer 或第二个 Photoshop 通道。
- 四个一级导航、活动任务条、空任务/恢复任务只读投影可显示并可通过键盘访问。
- 架构测试证明 Domain 未引用 UI/HTTP/SQLite/AI/Photoshop；契约层未依赖 UXP 私有类型。

### 状态与恢复

- 新建一个模拟任务，写入事件和 checkpoint，关闭后重新打开可以从最后安全事件回放。
- 模拟 `Paused`、`RecoveryRequired`、`Failed`、`Cancelled`、`UserActionRequired`、`CompletedWithIssues`；零输出不得被 reducer 变成完成状态。
- 事件重复提交按 `event_id` 去重，序号倒退被拒绝；已成功页不会因恢复回放而重复执行 mock 副作用。

### 契约

- RenderPlan 正例通过，含绝对路径、`analysis_copy`、`superseded_paths`、Photoshop 命令、缺失结构预期或普通页无目标的反例被拒绝。
- bridge 正常握手、拒绝握手、过期 token、请求超限、重复提交、断线查询和未知 execution 的 mock 契约测试通过。
- 每次契约失败返回 `code/retryable/scope/user_action`，不泄漏路径、凭据或原始异常。

### UIA 与窗口

- 1440x900 和 1100x760 下无导航遮挡、标题/列表/底栏裁切或控件尺寸跳动。
- 100%/125% DPI、Tab 顺序、可见焦点、中文 IME 和基本 UIA 属性有可复现证据。
- 高保真通过仅作为视觉输入；没有用截图通过替代实际控件和 UIA 验证。

### 数据安全

- 骨架测试只写应用临时/测试目录；对指定保护目录执行前后 hash 检查并证明未修改。
- 日志和诊断 mock 通过 secret/绝对路径/媒体扩展名扫描；API Key、源图、PSD 和正式输出不会进入测试产物。

## 8. 验证记录要求

当前仓库没有可执行的 canonical build/test command。实施时必须先记录实际使用的 SDK、restore、build、test、架构测试、Schema 校验、UIA/DPI 测试命令及其版本和结果，再把命令写入本任务和 `docs/当前项目状态.md`；在命令真实存在前，不得在仓库文档中虚构命令名或“通过”证据。

每次交付至少附：变更文件清单、测试环境、失败注入输入、事件回放摘要、RenderPlan/bridge 正反例结果、UIA/DPI 截图或自动化报告、源文件 hash 保护结果和未完成项。

## 9. 阶段风险与回滚

| 风险 | 处理 |
| --- | --- |
| .NET 10/WPF/UIA 或窄窗关键门失败 | 停止阶段 0 交付，依据 ADR-011 形成验证记录；不私自降级验收标准 |
| SQLite/WAL 或单 writer 恢复失败 | 保留旧迁移版本和测试数据库，按 ADR-012 修复或形成新 ADR |
| Schema/bridge 需求不足 | 新增兼容版本和迁移/正反例，不把私有字段塞入合同 |
| 依赖安装或网络不可用 | 记录实际阻断；不以未安装依赖的“空壳截图”标记完成 |
| 用户保护目录误写 | 立即停止并隔离测试目录，核对 hash；不得删除或回滚用户文件 |
