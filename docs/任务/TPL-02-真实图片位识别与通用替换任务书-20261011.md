## 1. 用户要求与完成定义

以最终画面中真正需要替换的商品图片位为规则和替换对象，不以智能对象类型作为唯一准入条件。源内容由智能对象、普通像素层、多层组合或其他结构承载，是软件内部问题，不是客户操作负担。

- 不是列出全部 PSD 图层；文字、背景、装饰、隐藏旧图、被完全覆盖的对象和无效残留不因存在图层就成为商品框。
- 保持现有导入、侧栏手填、可选参考学习、正文自然语言/@、保存与生产步骤。三种规则入口并列，不强制参考款、手动画框、逐层校准、转换模板或逐框确认。
- 图片位必须接通“预览定位 → 写规则 → 保存重开 → 选真实商品图 → 实际替换 → 输出验证与恢复”，只画框不算完成。
- 原图不得残留；文字、背景、装饰及其他图片位不得被误改；不虚构商品照片或补猜尺码。
- 对不能可靠处理的结构，保持明确失败/未完成和页级隔离，不静默漏框、不发布错误结果，不以要求客户修模板作为本任务的成功路径。
- “不增加时间”同时保留用户操作负担和系统等待两类要求；不能擅自缩减为“不增加点击数”。性能门见 §8。
- 用户实施中纠偏：模板识别、图片位定位与规则绑定在导入/学习阶段完成并保存；生产批次消费冻结规则、图层绑定、目标照片和计划，不重新识别/学习模板。只出 JPG 时保持原链路，不额外保存或导出验证用临时 PSD；原有受控模板输入副本仍保留以保护源文件。必要的文件身份、目标存在/类型与执行结果检查不等于重新找框，不扩展成逐页全量重分析。

## 2. 已核实的根因及证据边界

根因是图片位与智能对象身份耦合，限制贯穿识别、学习、绑定、计划、执行和独立验证，不能仅放宽候选筛选。

| 位置 | 当前事实 |
| --- | --- |
| `src/Desktop.Application/Templates/TemplateCalibrationService.cs` | `InspectFrames` 先筛选非空 SmartObject，普通像素图片不会成为规则候选 |
| `src/Desktop.Application/Templates/ReferenceLearningService.cs` | 结构学习准入和证据构造依赖智能对象，不能只改工作台显示 |
| `src/Desktop.Domain/Templates/TemplateValueObjects.cs` | 当前 TemplateLayerKind 只有 SmartObject，ExpectedLayerEvidence 也固定该类型 |
| `src/Desktop.Application/Templates/TemplateRenderPlanBuilder.cs` | 目标和被取代层的类型按 smartObject 生成 |
| `docs/技术方案/schemas/render-plan-v1.schema.json` | 普通 targets 的 kind/expected_kind 固定为 smartObject；尺码插入的其他引用类型不等于普通商品图已支持像素目标 |
| `uxp-render-adapter/src/photoshop.js` | 普通替换前置与执行依赖真实智能对象结构 |
| `src/Desktop.Application/Rendering/RenderTemplateEvidenceValidator.cs` 与 `src/Desktop.Application/Rendering/RenderOutputEvidenceValidator.cs` | 模板及结果按智能对象目标闭合，新增显示框不能绕过验证 |

既有四份 PSD 结构证据记录在本机受控诊断材料中，该记录含客户样本信息、不纳入共享提交；它是已有诊断，不是本草案新增的 PSD 检测、实机出图或验收。

K08 微小残留候选已有源码过滤和既有聚焦测试记录，但不等于当前运行版本已确认生效，也没有解决顶部像素图片位缺失。现有 1% 贡献边界面积阈值只是启发式，不能代替图片语义判断，也不能永久排除真实的小图片位。

## 3. 通用能力范围与禁止特判

| 结构类别 | 必须研究和验证的通用能力 |
| --- | --- |
| 有效智能对象 | 保留已有规则与替换能力，不回归 |
| 独立像素图片 | 定位实际显示区域，自动准备/替换目标，保留位置和相关结构 |
| 带用户/矢量蒙版、剪贴或调整关系的图片 | 分清图片内容与保留结构，验证替换后裁剪、层序及效果，不仅用图层矩形 |
| 多层组成的同一图片位 | 多个贡献层归并为一个业务图片位；明确被取代内容和需保留的装饰/效果 |
| 覆盖旧图/替换栈 | 最终显示内容作为证据，处理正确的覆盖关系，不绑定一个换后仍看不见的底层对象 |
| 同一像素层中的多个图片区域或图片与文字/背景合并 | 单独验证区域分离和非目标保护；无法闭合时保持开放，不能通过整层智能对象化假装解决 |

不能按 PSD 文件名、图层名、固定 layerId、层索引或该四份样本的坐标写生产分支；测试预期可以记录它们的身份。不是把所有像素层、所有可见层或所有有贡献层都注册为商品框。

合并内容可能没有独立背景/图层证据。不得承诺任意 PSD 都能无损自动重建；本任务须如实报告该类别的支持证据与缺口，而不是将其删除后宣布“通用支持完成”。

## 4. 技术路线：在现有链路扩展，先验证再确定

### 4.1 统一图片位描述

在应用层区分业务图片位和底层执行对象。最小信息包括：稳定图片位身份、来源模板身份、最终显示区域/遮罩证据、贡献层集合、保留层/被取代内容、规则归属、可执行策略与版本。

- 一个图片位不必对应一个图层；同一图层也不能被默认当作一个完整图片位。
- 结合结构、可见贡献、页面/图片语义判断。视觉模型仅给候选和语义证据，不能用模型矩形冒充已证实的替换目标。
- 有参考材料时复用，无参考材料时不能新增强制前置。语义能力优先沿用项目现有 AI 端口和受控输入，不新建模型平台或第二套请求账本。
- 未填选图规则不保存空白生产绑定；预留引用和生产准入仍分开。

### 4.2 备选路线 A：导入阶段内部标准化（不是当前默认生产流程）

源 PSD → 图片位分析 → 确定性准备方案 → 自动制作应用自有工作副本 → 重新读取真实结构 → 闭合映射和绑定 → 复用现有规则/RenderPlan → Photoshop 替换 → 独立验证与输出。

要求：

1. 源 PSD 不变；工作副本在首次准备后可按真实身份复用，不是客户额外制作模板。
2. 转换不能只是修改类型标签、伪造 SmartObject 检测结果或整层包一层后宣称可替换；必须证明实际替换改变了目标画面且未破坏非目标内容。
3. 准备后的模板需重新检查、hash 和绑定；预览、alias、学习、生产及验证都引用同一版本。原始结构路径与工作副本路径有可追溯映射，不沿用失效路径。
4. 结果校验以经独立验证的工作副本作为替换基线，同时闭合“源 PSD → 工作副本”的允许变更证据，不能通过换基线掩盖准备阶段误删/误改。
5. 应用层决定目标和允许操作；UXP 只执行受控确定性步骤，不接收自然语言、不承担商品规则判断。
6. 现有正式执行合同是否能表达准备操作需单独核实，不偷用验证插件或把普通 RenderPlan 当任意 Photoshop 命令通道。

### 4.3 当前选择：显式像素目标与生产阶段最小受控替换

在现有源码直接增加 Pixel 目标及版本化执行能力，导入保存真实显示贡献和候选内容证据，规则保存原始图层身份、路径及显示区域。生产消费这些已保存信息，按计划对受控 Photoshop 文档中的指定像素层做最小准备与替换，不重新找框、不制作另一份持久化标准模板。只出 JPG 不增加验证 PSD 的导出/传输/发布步骤；用户本来选择输出 PSD 时继续沿用原有结果验证。

任何必要的 RenderPlan、AI 结果、SQLite、checkpoint、manifest 或 bridge 变更先列明最小版本化兼容方案，再实施；不默认增加 Pixel 枚举就算完成。已实施的最小变更范围及真实证据须在交接中记录；历史迁移和已提交快照不重写。

保持 renderer-neutral 边界，不向计划加入 Photoshop 命令字符串，不以用户批准本能力为由扩大到其他合同重构。

## 8. 性能与尚待确定的问题

操作负担硬目标：额外强制步骤为 0，额外人工模板准备/逐框校准时间为 0。后台处理不等于“零等待”，不能用缓存架构声明替代测量。

性能记录须在同一机器、Photoshop 构建、模板和素材条件下区分：

- 首次导入至可编辑图片位；首次完整生产至可验证结果；
- 模板缓存命中后再次打开/生产；
- 解析、语义分析、准备、替换、验证各环节及AI请求次数；
- 旧版漏框而“更快结束”的情况，不作为成功完成同一任务的等价基线；分别报告旧软件耗时与完整任务耗时。

待确定但不阻塞本地根因测试：首次/复用等待允许的绝对预算或相对回归上限、可用真实陌生模板覆盖、当前正式 Photoshop/插件认证与构建、合并区域可保护证据及必要合同演进范围。未明确性能标准前不关闭 SLOT-12；不承诺未经测量的日期或任意PSD零耗时自动完成。
