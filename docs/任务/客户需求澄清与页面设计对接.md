# 客户需求澄清与页面设计对接

## 状态

进行中：UXP 执行通道验证已收口，进入 V1 产品方案收口和正式实现准备阶段。

## 目标

在不推翻 PRD 1.0 的前提下，完成客户业务口径、页面信息架构、页面模板规则、试点验收和数据边界的确认，形成可进入正式页面实现、AI-01 和 SIZE-01 纵向开发的 PRD 1.1 补充输入。

详细问题清单见 [`docs/需求评审/PRD-1.0客户需求澄清与页面设计对接清单.md`](../需求评审/PRD-1.0客户需求澄清与页面设计对接清单.md)。

## 范围

- 客户角色、批次规模、人工工作流和节省工时基线；
- 页面清单、页面顺序、生成方式、图片框角色和视觉金标；
- 变体、素材角色、尺码表和绿/黄/红状态边界；
- 输出目录、命名、PSD/JPG 交付和返修规则；
- AI 数据上传、API Key、网络、Photoshop 版本和本地存储责任；
- 试点样本、验收人、问题分级和上线/暂停条件；
- 文档、验证包、临时目录和外部 Demo 的归档策略。

## 非目标

- 不在客户确认前重写 PRD 1.0；
- 不把 UXP 技术验证细节改写成客户功能承诺；
- 不在本任务中删除验证证据、用户样本或历史 Demo；
- 不把尚未完成的 AI-01、SIZE-01 或完整产品性能验收口头标记为已完成；
- 不在页面结构确认前冻结高保真视觉细节。

## 完成条件

1. P0 澄清问题均有客户答案、负责人和日期。
2. 页面信息架构、核心流程和低保真线框图完成客户走查。
3. 每个首批页面都有页面模板确认表、真实 PSD/JPG 金标和输出规则。
4. 绿/黄/红状态决策表和 AI-01、SIZE-01 产品验收草案完成。
5. 试点范围、验收人、问题分级、培训和支持边界书面确认。
6. 形成 PRD 1.1 变更摘要，并同步 `docs/验收矩阵.md` 的新增证据行或待验证项。
7. 生成归档清单后，才处理 `tmp/`、重复验证 ZIP 和外部 Demo 的迁移或清理。

## 下一步

产品负责人已先行澄清：模板组页面数量不固定、一个图片框只放一张图、AI 选图先用 Top-1、自然语言由第三方 API 理解后转为受限动作、缺图或无法安全生成进入红色；生成前红色按页面隔离，同款正常页面继续输出，该款显示“完成但有问题”。PRD 中的“7 页/70 页”仅是历史性能基准，不是模板组限制。仍需召开一次 60 至 90 分钟客户需求会，使用真实批次、原照片、PSD 模板和人工结果走查页面与异常，不以技术验证截图替代客户业务确认。会议后进入信息架构、高保真页面设计以及 AI-01/SIZE-01 的正式纵向实现。
