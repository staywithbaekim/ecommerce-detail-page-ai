### 2026-09-14 产品范围澄清

V1 默认用户具备并提供可复用的 PSD 模板；尺码表页作为模板组中的明确页面类型，系统从用户上传的尺码图提取结构化数据，并在 PSD 模板样式和动态表格区域内自动排版。用户不需要为每个新款手工修改 PSD，但 V1 不要求在没有 PSD 的情况下凭空建立尺码表样式。无 PSD 的内置尺码表生成器、独立样式库和不依赖 PSD 的完整输出路径列入 V1 之后的候选方向，不作为本任务或 RENDER-01 的完成门。

## 2. 任务目标

把 AI-01 输出的尺码表候选和 INPUT-01 登记的批次资产，转化为可追溯、可校验、可编辑、可确定性排版的动态尺码表，并接入 renderer-neutral `RenderPlan` 边界。

SIZE-01 的目标结果是：

- 从正式批次 manifest 识别市场尺码图，按内容 hash 去重，并对多来源冲突提供用户选择；
- 形成结构化 `SizeTable` 数据，保留表头、尺码、数值和单元格内单位的来源原文；
- 对缺失、冲突、结构不可靠和校验失败进行明确状态路由，不猜测、不静默补值；
- 对不固定行数、列数和表格高度执行确定性布局，保留模板自己的标题、固定说明和视觉样式；
- 提供异常纠错用的 O-03 结构化编辑器，编辑后只重生成当前款当前尺码页；
- 生成符合 `render-plan/v1` 的尺码页计划和 `deterministic_size_table` 逻辑资源，供后续 Photoshop/UXP 执行器消费。

## 3. 硬约束与非目标

### 3.1 必须遵守

- 只消费 INPUT-01 的 `BatchDraft`、`asset-manifest/v1` 和模板快照；不在 SIZE-01 复制目录扫描或重新定义输入归属。
- AI-01 的 `AiSizeTableCandidateV1` 只作为结构化候选输入，不能因为 AI 返回候选就跳过本地结构、来源和布局校验。
- 市场尺码图、源照片、PSD 和人工参考结果只读；实验、预览和渲染必须使用应用自有副本或确定性生成资源。
- 不可靠结构、来源冲突、缺失必需尺码图和无法确认的单元格必须进入 `ReviewRequired`/`Invalid` 或页面级业务阻断，具体状态在 SIZE-S1 冻结后执行。
- 单元格保留来源原文，包括合法的 `-`、`\\`、`/` 和单元格内单位；不得把不确定文本强制转成数字或自行换算。
- `RenderPlan` 只包含逻辑资源、结构证据、摘要和输出意图；不得包含绝对路径、临时路径、token、Photoshop 命令或分析副本。
- 动态尺码表使用确定性无损资源，并以 `deterministic_size_table` 注册；不得直接把市场尺码图贴到正式尺码页，也不得使用生成式图片。
- 所有新建计划、编辑和当前页重生成均保持旧数据/旧输出可恢复；新计划使用新的 `plan_id`/幂等标识，不覆盖历史计划。

### 3.2 明确不做

- Excel、CSV 或其他表格文件输入；
- 通用行业表格识别、广告/模特图/联系方式/表格外说明提取；
- AI 猜值、自动补齐缺失数字、未经确认的单位换算或冲突自动择一；
- 重新绘制商品图、市场尺码图或任何产品真实性内容；
- 新建独立 PSD 渲染器、独立 Photoshop 批量生产链或第二执行器；
- 在 SIZE-01 内扩展账号、云同步、平台上传、支付、计费或通用批量重分析；
- 因实现方便修改模板规则、既有模板修订、其他页面或其他款式输出。

SIZE-01 负责结构化尺码数据、确定性资源和 `RenderPlan` 生产。正式 Photoshop/UXP 批量执行、bridge 接管、JPG/PSD 原子提交、执行中断恢复属于后续 `RENDER-01`/阶段 4。若 SIZE-01 尚未取得真实 JPG/PSD 集成证据，验收矩阵不得提前把完整 SIZE-01 行标记为通过。

## 4. 上游门与现有生产者合同

### 4.1 上游验收门

开始 SIZE-S1 代码实现前，必须复核并保留以下证据：

1. `INPUT-01` 验收状态为通过，`BatchDraft`、扫描状态和 `asset-manifest/v1` 生产代码在当前基线存在；
2. `TPL-01` 验收状态为通过，模板快照可表达 `DynamicSizeTable` 页面内容类型，且旧修订/旧批次快照不可变；
3. `AI-01` S0-S7 验收状态为通过，`AiSizeTableCandidateV1`、`size_table_extraction`、结果语义校验和未知结果门在当前基线存在；
4. `render-plan/v1` Schema 与 ADR-014 仍为当前批准合同；
5. 产品负责人认可的只读金标清单可用，至少覆盖清晰有效表格、可变行列和高度、合法原文符号、缺值、重复图和冲突来源。

上游门只允许由仓库证据关闭，不因本任务书批准而自动视为通过。样本媒体、数据库、缓存、截图和本机路径不进入 Git。

### 4.2 现有待补生产者缺口

当前 `AiRenderPlanFactory` 对动态尺码页仅能返回：

- 没有候选：`BusinessBlocked` / `AI_SIZE_TABLE_CANDIDATE_MISSING`；
- 有候选但尚无栅格器：`AwaitingSizeTableRasterization` / `AI_SIZE_TABLE_RASTERIZER_PENDING`。

SIZE-01 必须以最小闭合方式替换第二种 pending 结果：完成来源选择、结构校验、确定性资源和尺码页计划后，才允许进入可渲染计划；不改变普通套图页和 AI-01 已通过的状态语义。

### SIZE-S2：来源识别、去重和冲突选择

交付：

- 直接消费 manifest 的尺码图候选筛选和来源登记；
- 相同内容的重复尺码图按 hash 去重；
- 多张内容冲突尺码图进入用户选择，不静默择一；
- 未找到有效尺码图时，已启用尺码页的款式进入业务红色；
- 来源 hash、候选 ID、选择 revision 和结构化数据之间的引用闭合。

质量门：不重扫源目录、不保存源绝对路径、不把普通商品图当尺码图、不删除源文件；混合目录归属继续由 INPUT-01 负责。

### SIZE-S3：结构提取和数据校验

交付：

- 从已选择来源提取表格区域的表头、尺码、数值、行和列；
- 将 AI 候选规范化为结构化数据，同时保留单元格来源原文；
- 校验行列一致性、必要表头、重复列/行、缺失值、非法结构和来源一致性；
- 清晰可靠样本可进入 `Valid`；低置信度、缺值、冲突或整体结构不可可靠解析的样本进入复核/红色；
- 记录可解释原因和所需用户动作。

质量门：逐单元格与金标一致；不能同时满足证据要求时 fail closed；不能通过默认值、邻近值、数值推断或模型自由发挥收口。

**2026-09-02 实现结果：代码候选与自动化门通过，真实金标逐格回归已完成。** 候选规范化保留来源原文，`/`、`\`、`-` 合法，真正空值、ragged、重复和低置信正确阻断/复核；`SizeTableGoldSampleTests` 读取两张真实忽略样本、校验收口 hash，并验证人工逐格核对数据进入正式 `SizeTableService`，2/2 通过。该测试不冒充 OCR 或真实 provider 准确率证据。

### SIZE-S4：确定性动态布局和资源生成

交付：

- 与模板尺码页样式版本绑定的确定性布局器；
- 不固定行数、列数和表格高度，按冻结规则计算列宽、行高、字体、边距和固定内容位置；
- 额外列保留，缺列按明确的模板/业务规则处理；固定标题、说明和装饰不被改写；
- 生成可复现 digest 的无损尺码表资源，输出资源用途为 `deterministic_size_table`；
- 相同结构和样式输入得到稳定结构/digest；字体、中文度量、DPI 和边界反例有证据。

质量门：不贴源尺码图；不受 WPF 当前 DPI 或机器路径影响；渲染资源失败不覆盖旧资源或旧输出；若实现选择改变已批准的长期技术方向，先补 ADR 再编码。

**2026-09-01 实现结果：代码候选与自动化门通过。** 固定 96 DPI WPF PNG、字体签名、内容寻址资源、可变高度和重复 hash 已验证；实现选择记录于 ADR-020。真实模板视觉走查仍未关闭。
