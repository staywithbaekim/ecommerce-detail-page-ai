# UI-01 全局视觉收口清单

## 状态与执行时机

- 状态：已建立，待主要业务页面齐全后集中执行。
- 执行门：`AI-01`、`SIZE-01`、批次分析/生成、结果检查/修复和设置等主要页面具备真实 WPF 状态后，再开启一次统一的 `UI-01` 视觉收口。
- 当前基线：产品负责人于 2026-08-28 接受当前 TPL 校准界面作为阶段性视觉基线，允许 `TPL-01` 按真实纵向行为完成验收；该确认不等于完整 `UI-01` 通过。
- 产品内容仍以 PRD 1.5 和交互规格 v1.2 为准；冻结 Figma 只作为视觉、空间和组件状态输入，不用旧原型文案覆盖最新业务口径。

## 收口原则

1. 先保证全部主要页面具备真实内容、真实状态和稳定交互，再统一比较，避免单页反复精修后被全局组件调整推翻。
2. 优先复用全局资源和组件样式，不在各页面复制相近但不一致的色值、圆角、字重、间距或状态实现。
3. 视觉精修不得改变已批准业务流程、持久化合同、renderer-neutral `RenderPlan` 或 Photoshop adapter 边界。
4. 自动化负责尺寸、状态、DPI、键盘和 UIA 的可重复检查；产品负责人在实际应用中完成代表页面视觉走查。Figma、截图或测试数量不能单独替代真实窗口确认。

## 全局精修清单

### 视觉变量与基础组件

- 统一字体家族、中文字重映射、标题/正文/辅助文字字号与行高。
- 统一背景、面板、分隔线、输入框、禁用态和状态色；状态色只承担批准的业务语义。
- 统一结构容器与控件的圆角、边框粗细、阴影强度、内外间距和最小点击区域。
- 统一按钮、输入框、下拉框、标签、列表行、弹窗和底栏的默认、悬停、按下、焦点、禁用、加载与错误状态。
- 统一图标来源、线宽、尺寸、对齐和文字间距，清理临时字符图标或风格不一致的图形。

### 壳层、左右栏与信息层级

- 复核四个一级导航、页头、主工作区和底部任务栏在各页面的对齐、留白与视觉节奏。
- 统一左侧列表、右侧属性栏、筛选栏和详情面板的边框、行高、选中态、悬停态、焦点态及滚动条外观。
- 复核技术字段是否已从普通用户界面隐藏；状态和操作必须使用中文、可行动文案。
- 复核长名称、长路径、空状态、加载、警告、失败和只读状态下的层级，避免文字截断、重叠或无意义留白。

### 画布与专业编辑状态

- 以当前 T-04 三栏界面为阶段基线，统一画布背景、PSD 自适应占比、缩放反馈和可用空间分配；不同横竖比例 PSD 不出现大面积无意义灰区或主体过小。
- 复核 `Ctrl + 滚轮` 缩放、画布聚焦、缩放上下限和恢复适合窗口的反馈；不把高级位置精调提升为普通用户必做步骤。
- 统一图片框选中边框、控制点、悬停和键盘焦点：明显但不刺眼，不遮挡关键图片细节。
- 统一素材拖入、移除、撤销/重做、只读原页面和“未绑定，可跳过”等状态的即时反馈。

### 响应式、DPI 与可访问性

- 对全部代表页面覆盖 `1440×900`、`1100×760`、100%/125% DPI；必要时补充更高 DPI 风险检查。
- 明确每页滚动所有权，消除外层与内层争抢、意外横向滚动、焦点导致页头移出窗口等问题。
- 复核 Tab 顺序、焦点环、Enter/Escape、快捷键、中文输入、屏幕阅读器名称和 UIA 自动化标识。
- 复核窄窗口下按钮不重叠、文字不裁切、画布不被侧栏遮挡，主要操作无需依赖横向滚动才能到达。

## TPL 阶段已知后续精修点

- 左右栏的按钮、文字、列表行、输入控件和分区标题继续做跨页面一致性微调；本阶段不再围绕单页进行像素级反复打磨。
- 在更多真实 PSD 比例下复核中央画布占比、空白分配和缩放体验；当前已支持按可用高度放大与 `Ctrl + 滚轮` 缩放。
- 结合完整组件体系复核图片框边框与控制点的精致度、悬停/焦点状态和高 DPI 清晰度。
- 将当前页已经采用的 8px 结构容器、6px 控件圆角、浅灰细边框和克制选中态纳入全局 token 对照，而不是让 TPL 页面形成孤立样式。
