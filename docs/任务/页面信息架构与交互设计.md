# 页面信息架构与交互设计

## 状态

进行中：PRD 1.2 已正式签署并完整替代 PRD 1.1，需求澄清已收口，进入页面信息架构与交互设计阶段。

## 目标

以已签署的 `产品需求文档-电商详情页智能生产系统-PRD-1.2.md` 为唯一需求输入，完成页面信息架构、核心流程、低保真交互和客户模板配置规格，为桌面端页面实现以及 AI-01、SIZE-01 正式纵向开发提供无歧义输入。

## 范围

- 桌面应用主导航、首页工作台和全局返回规则；
- 模板库、新建模板组、两种校准模式、页面排序与生成规则；
- 新建批次、AI 分析、绿/黄/红预检和页面级红色隔离；
- Photoshop 渲染进度、暂停恢复、失败状态和安全接管提示；
- 结果检查、Top-2/Top-3 换图、自然语言或手动调整、单页重生成；
- 动态尺码表编辑器、设置、存储清理和诊断入口；
- 首次使用、空状态、加载、无网络、Photoshop 未连接和恢复状态。

## 非目标

- 不重新解释或保留已经被 PRD 1.2 替代的更早版本口径；
- 不把 UXP 技术验证细节改写成客户功能承诺；
- 不在本任务中删除验证证据、用户样本或历史 Demo；
- 不把尚未完成的 AI-01、SIZE-01 或完整产品性能验收口头标记为已完成；
- 不在页面结构确认前冻结高保真视觉细节。

## 完成条件

1. 页面信息架构、核心流程和低保真线框图完成走查。
2. 每个核心页面的入口、主要信息、操作、离开条件和异常状态明确。
3. 模板配置、红页隔离、结果修复、暂停恢复和单页重生成在交互稿中可完整走通。
4. 页面设计不引入 PRD 1.2 之外的新范围，也不遗漏其中的 V1 必做能力。
5. 设置页能够走通固定 AI 服务与 Key、Photoshop 选择、存储迁移与安全清理、上传授权与诊断导出；删除任务或模板的确认文案明确不影响原始输入和正式输出。
6. `docs/验收矩阵.md` 能追踪页面实现、AI-01、SIZE-01、FLOW-01、DATA-01 和 SET-01 的后续证据。
7. `docs/当前项目状态.md` 记录设计产物、未决参数和下一项正式实现任务。

## 下一步

直接基于 PRD 1.2 设计一张信息架构图、一张端到端主流程图和核心页面低保真线框。使用现有真实 PSD、源照片和人工结果检查流程是否完整；低保真确认后再进入高保真视觉设计以及 AI-01、SIZE-01 正式纵向实现。
