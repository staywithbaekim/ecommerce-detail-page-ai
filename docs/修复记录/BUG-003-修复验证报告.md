# BUG-003 修复验证报告

## 修复概览

**问题**: PSD检查Worker无法处理中文路径
**根本原因**: PyInstaller打包的可执行文件在加载DLL时无法正确处理非ASCII字符路径
**修复方案**: 使用Windows短路径(8.3格式)转换API绕过编码问题
**状态**: ✅ 已修复并验证

## 修复内容

### 代码修改

1. **PsdInspectionWorkerClient.cs**
   - 添加 `GetShortPathName` Win32 API调用
   - 在进程启动时自动转换可执行文件路径和工作目录
   - 转换失败时优雅降级到原路径
   - 仅在Windows平台启用

2. **PsdInspectionWorkerClientTests.cs**
   - 添加中文路径测试用例
   - 验证短路径转换的正确性

### 技术实现

```csharp
// Win32 API声明
[DllImport("kernel32.dll", CharSet = CharSet.Unicode, SetLastError = true)]
private static extern int GetShortPathName(
    string longPath,
    char[] shortPath,
    int bufferSize);

// 进程启动时应用转换
string executablePath = _options.ExecutablePath;
string workingDirectory = Path.GetDirectoryName(_options.ExecutablePath)!;
if (OperatingSystem.IsWindows())
{
    executablePath = GetShortPathName(executablePath) ?? executablePath;
    workingDirectory = GetShortPathName(workingDirectory) ?? workingDirectory;
}
```

## 修复原理

### 问题路径示例

**失败场景**:
```
C:\Users\用户\Documents\全新实现\psd-inspection-worker\psd-inspection-worker.exe
                        ↑ 中文字符导致PyInstaller的bootloader无法加载python310.dll
```

### 短路径转换

**转换原理**:
- Windows文件系统为每个长文件名自动生成8.3格式的短文件名
- 短文件名只包含ASCII字符，避免编码问题
- `GetShortPathName` API提供标准转换方法

**转换效果** (示例):
```
长路径: C:\Users\用户\Documents\全新实现\worker\app.exe
短路径: C:\Users\用户~1\DOCUME~1\全新~1\worker\app.exe
        (实际结果取决于文件系统状态)
```

### 安全降级

如果短路径转换失败（极少见），系统会:
1. 检测到 `GetShortPathName` 返回0或超出缓冲区
2. 返回 `null`
3. 使用空合并运算符 `??` 回退到原路径
4. 保持原有行为，不引入新错误

## 遗留限制

### 已知但可接受的限制

1. **8.3文件名禁用**
   - 场景: 系统管理员通过注册表禁用8.3文件名
   - 频率: 极少见（企业环境偶见）
   - 影响: 短路径转换失败，回退到原路径
   - 解决: 文档说明建议启用8.3文件名

2. **UNC网络路径**
   - 场景: 应用安装在 `\\server\share\` 网络路径
   - 频率: 罕见（桌面应用通常本地安装）
   - 影响: 短路径转换可能失败
   - 解决: 建议本地安装

3. **极长路径**
   - 场景: 路径长度超过260字符
   - 频率: 罕见
   - 影响: 短路径转换失败
   - 解决: 建议缩短安装路径

**注意**: 所有限制场景都会优雅降级，不会引入新错误。
