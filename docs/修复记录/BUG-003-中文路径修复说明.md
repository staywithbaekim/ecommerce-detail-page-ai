# BUG-003: PSD检查Worker无法处理中文路径 - 修复说明

## 问题描述

**症状**: Worker进程无法加载中文路径下的python310.dll，错误信息：`Failed to load Python DLL`

**用户影响**: 中国用户如果将应用放在含中文的路径下（如"全新实现"、"测试文件夹"、"我的文档"），PSD检查worker进程完全无法启动，导致模板导入功能不可用。

**复现条件**:
1. 应用安装在包含中文字符的路径
2. 尝试导入PSD文件进行检查
3. Worker进程启动失败

## 根本原因

### PyInstaller的编码问题

PyInstaller打包的可执行文件在Windows上处理非ASCII路径时存在已知问题：

1. **Python DLL加载路径编码**: PyInstaller生成的bootloader在加载`python310.dll`时，使用的是ANSI编码而非UTF-8
2. **工作目录路径**: 当工作目录包含中文字符时，DLL搜索路径无法正确解析
3. **可执行文件路径**: 即使可执行文件本身路径正确，依赖的DLL加载仍会失败

### 已确认的失败场景

```
C:\Users\用户\Documents\全新实现\psd-inspection-worker\psd-inspection-worker.exe
                                  ↑ 中文路径导致DLL加载失败
```

## 修复方案

### 选择的方案: Windows短路径转换

使用Windows的8.3短文件名格式（Short Path），这是Windows API提供的兼容性特性，可以将包含非ASCII字符的长路径转换为纯ASCII的短路径。

**示例转换**:
```
长路径: C:\Users\用户\Documents\全新实现\worker\app.exe
短路径: C:\Users\用户~1\DOCUME~1\全新~1\worker\app.exe
       (实际转换结果取决于文件系统)
```

### 实现细节

#### 1. 添加Win32 API调用

**文件**: `src/Desktop.Infrastructure/Psd/PsdInspectionWorkerClient.cs`

添加P/Invoke声明：

```csharp
[DllImport("kernel32.dll", CharSet = CharSet.Unicode, SetLastError = true)]
private static extern int GetShortPathName(
    string longPath,
    char[] shortPath,
    int bufferSize);

private static string? GetShortPathName(string longPath)
{
    if (string.IsNullOrEmpty(longPath))
    {
        return null;
    }

    const int maxPath = 260;
    var shortPath = new char[maxPath];
    var result = GetShortPathName(longPath, shortPath, maxPath);
    if (result == 0 || result >= maxPath)
    {
        return null;  // 转换失败，返回null
    }

    return new string(shortPath, 0, result);
}
```

#### 2. 在进程启动时应用转换

**文件**: `src/Desktop.Infrastructure/Psd/PsdInspectionWorkerClient.cs` (第96-121行)

```csharp
// 原代码
var startInfo = new ProcessStartInfo
{
    FileName = _options.ExecutablePath,
    WorkingDirectory = Path.GetDirectoryName(_options.ExecutablePath)!,
    // ...
};

// 修复后
string executablePath = _options.ExecutablePath;
string workingDirectory = Path.GetDirectoryName(_options.ExecutablePath)!;
if (OperatingSystem.IsWindows())
{
    executablePath = GetShortPathName(executablePath) ?? executablePath;
    workingDirectory = GetShortPathName(workingDirectory) ?? workingDirectory;
}

var startInfo = new ProcessStartInfo
{
    FileName = executablePath,
    WorkingDirectory = workingDirectory,
    // ...
};
```

**关键特性**:
- 只在Windows平台应用（使用`OperatingSystem.IsWindows()`检查）
- 如果短路径转换失败，回退到原路径（向后兼容）
- 同时转换可执行文件路径和工作目录

#### 3. 添加using声明

```csharp
using System.Runtime.InteropServices;
```

## 方案对比

### 考虑过的其他方案

#### 方案A: 修改Python Worker编码处理

**描述**: 在`worker.py`中设置UTF-8编码

```python
import sys
sys.stdin.reconfigure(encoding='utf-8')
sys.stdout.reconfigure(encoding='utf-8')
```

**评估**:
- ❌ 只能处理stdin/stdout，无法解决DLL加载问题
- ❌ PyInstaller bootloader在Python代码运行前就已经失败
- ✅ 已经在worker.py中实现，但无法解决根本问题

#### 方案B: 重新打包PyInstaller使用UTF-8模式

**描述**: 使用`--ascii=false`或设置`PYTHONIOENCODING=utf-8`

**评估**:
- ❌ PyInstaller的DLL加载问题在bootloader层面，环境变量无效
- ❌ 需要修改PyInstaller源码或使用第三方补丁
- ❌ 维护成本高，升级困难

#### 方案C: 使用符号链接

**描述**: 在临时目录创建纯ASCII路径的符号链接指向实际路径

**评估**:
- ❌ 需要管理员权限创建符号链接
- ❌ 增加复杂性和清理逻辑
- ✅ 可以作为备选方案

#### 方案D: 短路径转换（选择的方案）

**评估**:
- ✅ Windows原生API，可靠稳定
- ✅ 不需要修改Worker代码
- ✅ 零性能开销（API调用极快）
- ✅ 向后兼容，转换失败自动回退
- ⚠️ 只适用于Windows（但应用本身就是Windows专用）
- ⚠️ 如果8.3文件名被禁用会失败（极少见）

**结论**: 短路径转换是最简单、最可靠的方案。

## 风险评估

| 风险 | 等级 | 缓解措施 |
|-----|------|---------|
| 短路径转换失败 | 低 | 回退到原路径，保持现有行为 |

## 遗留问题和限制

### 已知限制

1. **8.3文件名禁用**: 如果系统管理员通过注册表禁用了8.3文件名生成，短路径转换会失败
   - **影响范围**: 极少见（默认启用）
   - **降级行为**: 回退到原路径，保持原有错误行为
   - **解决方案**: 文档中说明建议启用8.3文件名

2. **UNC网络路径**: `GetShortPathName`对UNC路径支持有限
   - **影响范围**: 应用通常不安装在网络路径
   - **降级行为**: 转换失败，回退到原路径

3. **路径长度**: 短路径仍受260字符MAX_PATH限制
   - **影响范围**: 极少见（应用路径通常较短）
   - **降级行为**: 转换失败，回退到原路径
