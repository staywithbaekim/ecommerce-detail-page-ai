## 2. 业务背景与建设目标

### 2.1 背景

产品把电商美工重复执行的选图、按图片框裁切和排版、生成 JPG/PSD、检查和少量返修，变成可校准、可复用、可恢复的 Windows 桌面流程。用户 PSD 是规则来源，Photoshop 是受控渲染环境，AI 只分析压缩副本并提供结构化建议；产品不生成、重绘或猜测真实商品。

V1 的正式纵向主线为 `TPL-01` 模板增量页面与校准、`AI-01` 素材分析与候选、`SIZE-01` 动态尺码表。高保真 Figma 的页面、组件和窄窗口画板是开发输入，不是实现证据；截至 2026-09-01，TPL-01、INPUT-01 与 AI-01 已有对应实现和验收证据，SIZE-01 仍待正式纵向实现。本方案继续只定义架构与技术门，业务验收状态以 `docs/验收矩阵.md` 和 `docs/当前项目状态.md` 为准。

### 2.2 V1 成功标准

1. 用户不改名、不分类源图即可完成模板校准和批次生产，页面数量不受历史样本页数限制。
2. 金标批次至少 95% 页面可直接上传，严重错误为零：旧商品残留、错款/错变体、必需素材缺失却标绿、清晰尺码数字错误仍被视为正常，均不得发生。
3. 10 款、约 70 张纯 JPG 的完整 `machine_total`（扫描、AI、计划、Photoshop、ICC/文件校验和结果整理）不超过 PRD 的 300 秒硬门。该门必须用真实桌面端批次和完整环境证明，不得用 UXP 单通道外推替代。
4. 约 200 款可进入持久化队列；界面不冻结，状态和检查点不丢失；暂停、应用重启或 Photoshop 异常后可跳过已成功页并继续。
5. 原始 PSD、源照片、市场尺码图和人工结果前后哈希不变；正式输出只在用户确认的输出目录中原子出现。
6. 默认 JPG 为 8 位 sRGB、高质量、尺寸和命名正确；可选 PSD 保持智能对象、文字、蒙版和装饰可编辑；JPG-only 当前页可按需生成 PSD 并在编辑后回写 JPG。
7. AI 上传授权、Key、缓存和诊断包符合最小数据原则；不新增账号、支付、云同步或平台上传。

## 3. 业务边界

### 3.1 V1 包含

- Windows 桌面应用和由本项目安装的 Photoshop UXP v5 配套组件；
- 一个或多个用户 PSD 的模板组导入、内部副本、校准、增量添加页面、另存、模板包导入/导出和删除；
- 普通套图页、动态尺码表页、页面排序和按款式/变体的生成组合；
- 单款目录、正常批次目录扫描，混合目录阻断；JPG/JPEG、PNG、常规 TIFF；
- 缩略图、受控并发 AI 分析、变体分组、候选排序、人工选图锁定和逐图主体适配；
- 动态尺码表图片识别、结构化网格提取、确定性重绘、编辑和当前页局部重生成；
- 生成前绿/黄/红页面状态，红页按页面隔离，正常页继续；
- Photoshop 页面/款式级 `RenderPlan` 执行，JPG 默认输出和可选可编辑 PSD；
- 结果总览、状态筛选、Top-2/Top-3 或全部素材换图、拖动/缩放、受限自然语言调整和当前页 PSD 编辑；
- 任务持久化、暂停/恢复、取消未开始款式、失败隔离、单页/单款/全部失败项重试和应用重启续跑；
- 模板库、任务数据、缓存和临时目录可配置，模板库迁移、安全清理、脱敏诊断包导出。

### 3.2 明确排除

V1 不建设或暗中引入账号、商家工作区、云同步、支付、计费、平台上传、多人协作、同一安装内按商家/租户划分的工作区或 Key 隔离、可视化任意规则编程器、RAW/Excel/CSV 输入、通用新模板生成、图生图/商品重绘、多画板分别导出、独立 PSD 渲染引擎、普通文字按款自动替换和通用批量重分析器。每个软件安装客户使用自己的一个 Key 与该排除项不冲突。

用户已确认 V1 固定使用火山引擎的“火山方舟”大模型服务，采用“客户自己的凭据 + 项目方协助配置”，不向客户开放供应商和模型选择。后续商业演进方向是：客户登录项目方统一服务，桌面端将用户授权的压缩分析图上传到项目方 AI 网关，由网关选择一个或多个模型、统一管理供应商 Key 和费用，并按客户用量出账单。该方向只影响 V1 的可替换接口边界，不授权在 V1 实现账号、租户、云网关、模型选择、配额、账单或支付。

V1 不在开始生成前承诺磁盘空间差额估算；输出不可写或空间耗尽时必须安全停止、清理不完整产物并保留已完成结果。

## 5. 总体架构

### 5.1 部署和依赖方向

```text
WPF Desktop Host
  Presentation/UI ──commands/events──> Application Orchestrator
                                      ──ports──> Domain (rules/state/RenderPlan)
                                      ──adapters──> Infrastructure
Infrastructure: SQLite + file store + cache + credentials + AI adapter + diagnostics
                                      └── Photoshop adapter ──loopback bridge──> UXP v5
```

依赖方向为 `Presentation -> Application -> Domain <- Infrastructure adapters`。领域层是纯 .NET 类库，不能依赖 WPF、SQLite、HTTP、Photoshop 或 AI SDK。AI 和产品规则不能进入 Photoshop 执行适配器；UXP 不读取产品数据库、不调用 AI、不选择素材、不决定红黄绿。

### 5.2 模块职责边界

| 模块 | 职责 | 非职责 |
| --- | --- | --- |
| Presentation | 页面、ViewModel、导航、UIA、焦点、文案、缩略图虚拟化 | 数据库、文件、Key、业务规则 |
| Application | 用例、事务、任务编排、检查点、重试、取消传播、事件回放 | Photoshop 图层细节、AI 供应商语义 |
| Domain | 模型、不变量、状态机、预检、页面组合、尺码校验、RenderPlan | I/O、网络、线程调度、凭据 |
| Infrastructure | SQLite、文件副本/哈希/原子写入、AI/UXP 适配器、凭据、日志、迁移 | 页面视觉和产品决策 |
| UXP v5 | 计划校验、Photoshop DOM/batchPlay、智能对象替换、变换、JPG/PSD 保存、ICC 读回 | 候选选择、规则判断、任意脚本、模板修订 |

### 5.3 进程、线程和 Worker 边界

| 执行单元 | 允许工作 | 取消/暂停边界 |
| --- | --- | --- |
| UI 线程 | WPF 布局、输入、状态投影；不做 I/O 和 AI | UI 命令立即转发，不阻塞渲染 |
| Application orchestrator | 持久化状态、调度队列、事件回放、检查点 | 在用例安全边界停止新工作 |
| AI Worker pool | 压缩副本、API 请求、响应校验、缓存读写 | 请求边界取消；响应完成后落库 |
| Thumbnail Worker | 元数据、缩略图和局部裁切 | 文件边界取消；内存/磁盘背压 |
| SQLite writer | 单写入队列、事务和迁移 | 事务提交前不推进状态 |
| Photoshop bridge/UXP | 单一执行通道内的页面/款式计划 | 页面/款式边界暂停；未知执行结果先查询 |
| Diagnostics/recovery | 崩溃标记、启动扫描、脱敏包 | 不读取或复制源高清内容 |

每个安装实例只有一个 `PhotoshopExecutionGate`；AI Worker 可以并行，Photoshop 不并行。取消令牌由 Application 向所有 Worker 和 bridge 传播。

用户已确认每台电脑只允许一个桌面应用主实例。重复启动应激活现有窗口，并可将受支持的启动意图转交主实例；所有批次、AI 队列、SQLite writer、迁移锁和 Photoshop 执行通道均由主实例持有。主实例无响应时不得直接启动第二实例争抢数据库或输出，必须提示恢复/安全结束；升级、卸载和数据迁移前必须确认主实例退出。

用户已确认有活动任务时点击关闭不能直接终止进程，也不转入系统托盘。应用显示“安全暂停并退出”确认；确认后停止分配新工作，AI 在请求边界取消或完成落库，Photoshop 等待当前款安全收口、写入页面 checkpoint 并释放执行通道后退出。无活动任务时正常关闭；若 Photoshop 长时间无响应，可在明确提示“当前页状态未知、下次启动需恢复检查”后强制退出，绝不把未知页标记成功。

### 5.4 桌面技术选型

| 候选 | 优点 | 缺点/风险 | 当前建议 |
| --- | --- | --- | --- |
| WPF + .NET 10 LTS + MVVM | Windows 文件/进程/凭据/UIA 成熟，适合稳定尺寸、长任务和本地部署；.NET 10 当前为活动 LTS | 视觉 token、高 DPI、UIA 和部署行为需要实测 | **首选（用户已确认）**，骨架阶段在 Windows 11 x64 验证 |
| WPF + .NET 8 LTS | 依赖生态成熟，已有方案迁移成本低 | 官方支持至 2026-11-10，接近生命周期末端；不宜作为新 V1 默认 | 备用，只有现有依赖阻塞 .NET 10 时采用 |
| WinUI 3 + Windows App SDK | 原生现代控件和 Windows 视觉更直接 | SDK/打包/外部目录和旧系统矩阵风险；Photoshop/文件集成仍需自建 | 视觉升级候选，先做部署/UIA 探针 |
| Electron | 前端生态和设计还原快 | WebView/Node 内存和本地权限面大；进程控制/UIA/安装复杂；主版本约 8 周节奏 | 不推荐 V1 |
| Tauri 2 | Rust 后端、系统 WebView、包体较小 | Rust/前端桥接、Windows 原生集成和团队维护技能风险 | 不推荐 V1 |
| Flutter | 自绘 UI 还原能力强 | Windows 文本/UIA、文件/凭据/Photoshop 集成需额外维护；底层依赖兼容风险 | 不推荐 V1 |

最终运行时需形成 ADR。不得因视觉便利引入第二套完整运行时。

### 5.5 Figma -> WPF 实施契约

Figma 文件只作为视觉输入，不能复制 `get_design_context` 参考代码作为生产代码，也不能用 Playwright 直接验证 WPF。

| Figma 输入 | WPF 落地 | 自动化程度 |
| --- | --- | --- |
| 颜色/字体/间距/圆角/阴影 token | `ResourceDictionary`、主题资源和控件参数；`Noto Sans SC` 缺失时按发布包字体策略处理 | 颜色、字号、间距可导出；语义命名需人工映射 |
| `StatusLightFilter`/`TaskStatus`/`Button`/`ProgressBar` 等组件 | WPF `ControlTemplate` + 状态 VisualState；状态灯同时显示业务文字 | 结构可参考；UIA 名称、键盘状态人工验收 |
| `ProductRow`/`RenderQueueRow`/`ResultPageCard` | 虚拟化 ItemsControl/DataTemplate，固定行高和操作槽 | 尺寸可提取；数据绑定和错误态人工实现 |
| B-03 1440x900、1100x760 画板 | 窗口最小尺寸、Grid 栅格、窄窗收起侧栏规则 | 截图基线可自动比较；中文输入和 UIA 必须实机 |

## 6. 核心模块设计

各模块交付必须包含“职责、非职责、输入、输出、依赖、状态、错误、测试责任”八类证据。

### 6.1 TPL-01 模板组管理和校准

- **职责**：导入 PSD 到内部副本、内容哈希去重、页面配置、已注册图片框/替换栈绑定、拖拽校准、人工结果学习、动态选图要求确认、增量页面、模板修订和模板包。
- **非职责**：不在模板阶段替未来目标款选定具体商品素材，不让 AI 决定结构或坐标，不修改用户源 PSD，不让示例效果成为保存门槛。
- **输入/输出**：输入为用户选择的一个或多个 PSD 副本、参考源照片文件夹和校准动作；输出为不可变 `TemplateRevisionSnapshot`、带动态 `selection_requirement`/语义来源的 `FrameBinding`、`LayoutIntent` 和规则 digest。
- **依赖**：`IFileStore`、`IPsdInspectionPort`、`ICalibrationPreviewPort`、`IAiServicePort`（仅经 TPL-LEARN 语义合同）、可选 `IPhotoshopProbe`、`ITemplateRepository`、领域校验器。
- **状态/错误**：`Draft -> Importing -> DuplicateReview -> FrameBinding -> SemanticInference -> Calibrating -> AwaitingReview -> Committing -> Committed`；结构不匹配、重复 PSD、AI/合同不可用、权限不足、提交失败均可安全停在人工补充/重试或回滚到旧修订。
- **测试责任**：五页加第六页只校准新增页、稳定 ID、动态语义/人工覆盖、失败回滚、旧批次快照隔离、源文件哈希保护。

绑定必须记录 `layer_path`、`layer_path_order=psd_bottom_to_top`、目标类型、可见性、剪贴、蒙版、透明度、混合模式、稳定层 ID/结构签名和替换栈逐层合同；不能按“所有智能对象”替换。

校准编辑器默认使用**本地缓存的 PSD 合成预览 + 已校准图片框/蒙版几何覆盖层**：`IPsdInspectionPort` 从内部 PSD 副本读取合成图、画布、图层和结构证据，`ICalibrationPreviewPort` 在 WPF 中对用户拖入的高清只读素材引用生成交互预览；移动、缩放、撤销和规则编辑不持续占用 Photoshop。只有用户主动选择准确示例预览，或本地结构证据不足而进入明确的兼容性检查时，`IPhotoshopProbe` 才在内部副本上运行。不得为维持“本地预览可用”而猜测图片框或修改源 PSD。PSD 合成图缺失、蒙版几何无法可靠提取和本地/Photoshop 预览偏差属于【待技术验证】，通过前不能宣称任意 PSD 均可校准。

“从人工完成结果学习”是 TPL-01 的另一种校准入口，由后续 `TPL-LEARN-01` 交叉任务实现：用户提供一个或多个带同一参考款商品图的分层 PSD（数量不固定，每个 PSD 对应一个模板页面）和该参考款实际使用的源照片文件夹，不要求另提供空白 PSD。本地解析智能对象、蒙版、结构、最终显示贡献和变换，以内容 hash 将图片框对应到具体参考照片并保留基准几何；当用户未手写充分规则时，AI 结合整组参考照片和已匹配参考图生成开放式动态 `selection_requirement`，不能直接修改 PSD 或决定未经校验的坐标。用户确认后才保存 `FrameBinding`、`LayoutIntent`、语义来源/版本/置信度和规则 digest。参考款只是学习样本，后续批次联合分析另选目标款的整组照片；JPG 仅作为缺少可复用 PSD 时的低置信度兼容路径。

### 6.2 INPUT-01 批次输入识别

- **职责**：读取所选目录一级内容，确定单款/正常批次/混合/空目录，创建批次草稿和资产清单。
- **非职责**：不重命名、移动、分类或修改源图；不在混合目录创建部分任务。
- **输入/输出**：输入为根目录；输出为带文件哈希、尺寸、可读性和脱敏路径的 `BatchDraft`。
- **依赖**：`IPathPolicy`、`IFileInventory`、`IAssetMetadataReader`、`IBatchRepository`。
- **状态/错误**：`Draft -> Scanning -> ScanBlocked|ScanReady`；混合、不可读、空目录为可执行阻断。
- **测试责任**：单款、正常批次、混合、空目录、权限失败、符号链接/路径穿越和零部分任务。

确定性规则：根目录直接有支持图片且无图片型一级子目录为单款；无根目录图片且一级子目录直接有支持图片为正常批次；两者同时存在阻断；其他结构阻断。

### 6.3 AI-01 素材分析

- **职责**：根据批次素材和已校准图片框的选图需求完成压缩图语义理解、商品变体归组、候选排序、主体边界、关键区域、尺码表网格和异常提示。
- **非职责**：不上传 PSD/高清原图、不生成商品、不猜缺失素材或尺码值、不覆盖人工锁定。
- **输入/输出**：输入为授权后的压缩分析副本和 `AnalysisRequest`；输出为版本化 `AnalysisResult`、`Candidate`、`SizeTableCandidate` 和渐进事件。
- **依赖**：`IAiServicePort`、`ICredentialPort`、`IConsentPort`、`IAnalysisCache`、压缩器。
- **状态/错误**：`Queued -> Uploading -> Analysing -> Validated|RetryableError|TerminalError|Cancelled`；响应 schema、授权和费用边界必须在进入领域层前校验。
- **测试责任**：AI-01 金标、响应 schema、人工锁定 compare-and-swap、缓存命中、授权撤回、429/超时/断网和费用记录。

用户已确认 V1 采用单一 `VolcArkAiAdapter` 接入火山方舟，当前实际调用的候选模型 ID 为 `doubao-seed-2.1-pro-260628`，认证形式为单个 API Key；客户使用自己的方舟 API Key 并由项目方协助配置。该确认用于收窄实现输入，不等同于 AI-01 验收通过；模型端点、请求与响应合同、压缩最长边、批大小、并发和费用上限仍必须由 AI-01 金标与官方接口证据冻结为 ADR/配置版本。应用层只依赖供应商无关的 `IAiServicePort` 和 `IAiCredentialSource`：V1 凭据来源为 Windows 凭据存储中的客户方舟 API Key，后续可替换为项目方网关访问令牌，但 V1 不实现网关或商业计费。任何真实 API Key 均不得写入方案、配置样例、日志或测试证据。

用户已确认 `AI-01` 的开发和金标验证建立独立火山方舟测试项目/API Key，与日常调用和未来客户 Key 隔离。测试 Key 进入开发机专用的 Windows Credential Manager 凭据槽，不进入源码、仓库配置、安装包、模板包、日志、诊断包或客户电脑；测试调用使用独立 correlation、用量记录和费用告警/预算边界。当前不凭空指定预算金额：先以少量受控探测请求取得单图、单款和尺码提取成本，再由 AI-01 任务书冻结每轮预算、停止阈值和异常费用处理。若方舟项目不能设置硬额度，则由本地请求计数/费用估算、平台告警和每轮人工批准共同控制，但不得依赖客户端估算作为未来客户账单事实。

用户已确认 AI 调度采用**有界队列 + 分层混合分析**。第一层按单款联合分析该款素材与批次模板快照中的图片框选图需求，形成变体归组、候选及可解释证据；第二层只对最终候选、需要主体级智能排版的已选素材，以及确有尺码内容的来源图执行所需精细分析。人工锁定后停止该图片框未选候选的后续分析。不得采用“整批一次性巨型请求”，也不得默认把每张图片、每个图片框拆成重复独立请求；具体每款图片数、请求批量、精细分析触发条件和最大并发由 AI-01 的准确率、P95、费用与限流证据冻结。

`正面`、`背面`、`细节`、`领口`等只能作为服装样本中的示例语义，不是系统枚举。领域模型、Prompt 合同、SQLite 和 RenderPlan 均不得内置固定品类角色或把商品变体写死为颜色；实际候选匹配以模板校准时形成的 `selection_requirement`、用户正确示范、最低可用条件和布局意图为准。非服装 V1 仍严格限定为“从商品照片中选图并套入已校准 PSD 图片框”，不因此扩展行业规格、成分或复杂图文数据自动化；无法可靠匹配的需求进入人工选图，不由 AI 发明新规则。

`selection_requirement` 必须根据参考组真实内容动态生成并足以区分同类照片。例如参考组同时有坐姿正面和站姿正面时，不得都降格为“正面图”；规则应保留姿态、视角、景别、构图、局部对象或其他消歧属性。图层名、文件名、尺寸和页面位置只能作为模型上下文或人工占位提示，不能单独形成“已学习”语义。自动总结在无用户充分手写规则且无同版本有效缓存时必须调用已批准视觉模型；请求/结果需按模型配置、提示词/规则版本和输入 digest 校验及缓存。

`TPL-LEARN-01` 与日常 `AI-01` 批次素材分析共用供应商无关端口和压缩/授权/结果校验边界，但为参考学习使用独立版本化请求/结果语义，不把参考款学习结果混入日常批次结果，也不把 AI 响应当作 Photoshop 动作。目标款分析按款联合提交整组候选与已确认的图片框要求；同一目标素材可被多个图片框选择，各框几何独立。精确或高置信且差异不影响用途的候选为绿色；只有模型明确报告实质差异、语义冲突、错款/错变体、无关、参考款引用或无安全候选等受控风险时才升级为黄色或红色。候选分差或同分本身不构成风险。整组上下文、动态提示词和主体证据用于尽量标绿，但不得降低严重错误门。无匹配、低置信或源照片与智能对象不一致时进入人工复核；不以单次 API 成功、mock 结果或本地启发式关闭模板学习验收。

### 6.4 人工选图和结果修正

- **职责**：款式/页面/图片框级选择、锁定、候选切换、拖动/缩放、受限自然语言动作、预览和当前页重生成。
- **非职责**：不回写模板规则、不跨款跨页修改、不接受任意 Photoshop 命令。
- **输入/输出**：输入为候选、人工动作和页面上下文；输出为带版本的 `Selection`、`RepairDraft` 和页级 `RenderPlan`。
- **依赖**：`ISelectionRepository`、`IAssetPreviewPort`、领域动作解析/几何校验器、`IRenderPlanFactory`。
- **状态/错误**：`Draft -> Validating -> Previewed -> Confirmed -> RegeneratingPage -> Committed`；不支持表达、几何越界、跨页目标和无有效候选均可解释阻断。
- **测试责任**：Top-N、锁定不可覆盖、自然语言结构化校验、当前页原子替换、模板和其他页不变。

自然语言链路固定为“文本 -> 本地规则或文本模型解析 -> 受限动作 DTO -> 领域校验/几何计算 -> 预览 -> 用户确认 -> 页面级 `RenderPlan`”。

### 6.5 SIZE-01 动态尺码表

- **职责**：有效尺码图识别/去重/冲突选择、结构化网格、确定性布局、结构化编辑和当前页重生成。
- **非职责**：不支持 Excel/CSV，不贴入来源市场图，不猜值，不生成式绘制数字。
- **输入/输出**：输入为授权分析副本、用户来源选择和编辑；输出为 `SizeTable`、确定性布局指令和尺码页计划。
- **依赖**：`IAiServicePort`、`ISizeTableRepository`、结构校验器、确定性布局器、`IRenderPlanFactory`。
- **状态/错误**：`Candidate -> SourceSelectionRequired|Extracting -> ReviewRequired|Valid|Invalid`；清晰图片在 AI 提取、本地结构/排版校验通过后自动生成，只有低置信、来源冲突、结构不可靠或排版异常才进入人工处理。来源单元格中的 `-`、`\`、`/` 及其他合法原样文本不是缺值或非法数字，必须按来源保留。
- **测试责任**：逐单元格金标、可变行列/高度、额外列保留、缺列省略、确定性 JPG/PSD 和局部重生成。

领域层只输出表格网格、样式 token、列宽/行高、文本对齐、换行和固定内容位移等确定性布局原语；不得在领域层调用 WPF、Skia 或 Photoshop。推荐由独立 `ISizeTableRasterizer` 使用固定版本的 SkiaSharp（或验证后等价的确定性 2D 引擎）和随应用发布的批准字体生成透明无损渲染资源，同时保存结构化 `SizeTable`、字体/布局版本和像素 hash。UXP 只把该资源作为内嵌智能对象置入已校准尺码页，并保留可替换性，不在 Photoshop 内重新识别或猜数字。SkiaSharp/字体许可、中文度量、不同 DPI 一致性、超宽表格、可变高度和 PSD 重开替换均为【待技术验证】；若候选引擎不稳定，只能更换确定性栅格器，不能改成 AI 生成图片或直接贴市场尺码图。

### 6.6 RenderPlan 生成

- **职责**：将模板快照、页面组合、变体、锁定选图、主体几何、尺码结构和输出选项转换为稳定计划。
- **非职责**：不读取文件、不解释 Photoshop 规则、不在执行器中重新选择候选或决定红黄绿。
- **输入/输出**：输入为不可变快照和修正；输出为通过 schema 校验的 renderer-neutral `RenderPlan`、`plan_digest` 和幂等键。
- **依赖**：纯领域组合器、版本化 Schema 校验器、路径相对化策略；不依赖 UXP 或 Photoshop SDK。
- **状态/错误**：缺框、结构签名不符、红页进入计划、输出目录不可写、schema 版本不兼容均阻断。
- **测试责任**：同输入稳定 digest、版本迁移、路径顺序、替换栈、红页隔离和 page-scoped 计划。

### 6.7 Photoshop 渲染适配器

- **职责**：安全接管、打开内部模板副本、首个替换前结构审计、`executeAsModal` 页面/款式级执行、JPG/PSD 保存、ICC 读回和 evidence。
- **非职责**：不调用 AI、不修改源 PSD、不读取领域数据库、不执行任意脚本、不改变模板修订。
- **输入/输出**：输入为已校验计划和短期 token；输出为进度事件、`RendererResult`、文件哈希和结构化错误。
- **依赖**：`IPhotoshopBridgePort`、`IFileStore`、`IOutputCommitter`、`IExecutionEvidenceStore`；不得依赖 AI 端口或产品规则服务。
- **状态/错误**：`Disconnected -> Handshake -> Ready -> Running -> PageCommitted|PageFailed -> QueryRequired|Released`；未知执行结果不得自动重提。
- **测试责任**：真实 PS 版本矩阵、smart object 替换、ICC、未知弹窗、断线、输出清理、PSD 重开和源文件保护。

### 6.8 结果检查和单页修复

- **职责**：投影每页状态、正式输出、源资产引用、模板/规则版本、异常和哈希；按冻结筛选规则展示 O-01；从 O-02/O-03 创建当前款当前页修复草稿并原子替换该页。
- **非职责**：不重算其他页、不更新模板规则、不覆盖未登记路径、不把业务红页伪装成运行失败或虚构预览。
- **输入/输出**：输入为 `OutputRecord`、`TaskError`、人工修正和页上下文；输出为只读结果投影、`RepairDraft`、页级计划和新 `OutputRecord`。
- **依赖**：`IResultRepository`、`IAssetPreviewPort`、`IRenderPlanFactory`、`IOutputCommitter`、Photoshop 单通道。
- **状态/错误**：`Result -> RepairDraft -> Previewed -> RegeneratingPage -> AtomicallyCommitted -> Result`；无有效候选、输出冲突未确认、PSD 回写未校验和执行结果未知均不得提交。
- **测试责任**：筛选命中范围、红页/运行失败分离、当前页原子替换、其他页和模板不变、JPG-only 按需 PSD、Photoshop 编辑回写及失败恢复。

### 6.9 设置、数据、缓存与诊断

- **职责**：实现 AI 服务、Photoshop、存储与清理、隐私与诊断、软件信息五分区；管理 Key 状态、上传授权、路径迁移、缓存保护、诊断包和版本信息。
- **非职责**：不显示完整已保存 Key、不自动上传诊断、不清理源文件/正式输出/活动恢复数据、不提供供应商或模型选择。
- **输入/输出**：输入为用户明确配置、确认和清理/迁移命令；输出为脱敏设置投影、凭据状态、迁移 journal、清理清单和诊断包 manifest。
- **依赖**：`IAiCredentialSource`、`IConsentPort`、`IStorageMigrationPort`、`ICacheIndex`、`IDiagnosticsExporter`、版本/支持矩阵探针。
- **状态/错误**：Key 使用 `Missing|Testing|Valid|Invalid|InsufficientBalance`；迁移和清理沿用第 8.6/10.2 节状态；权限、外置盘断开、仍被任务引用或脱敏失败均安全阻断。
- **测试责任**：Key 输入/更换/移除/脱敏、授权撤回、迁移故障注入、缓存引用保护、诊断包 allowlist/黑名单、软件/PS 版本与支持入口。

## 8. 状态机与关键流程

### 8.1 模板校准流程

主流程为 `Draft -> ImportingCopy -> StructureInspecting -> FrameBinding -> SemanticInference -> Calibrating -> AwaitingReview -> Previewing(optional) -> Committing -> Committed`。内容 hash 命中已有 PSD 时进入 `DuplicateReview`，由用户确认复用、作为新增页面继续或取消；不得删除/覆盖来源文件。AI 从正确示范总结的动态选图需求只能进入 `AwaitingReview`，用户确认前不能提交为生效规则；示例预览可跳过，不是保存门槛。

人工结果学习入口在同一模板修订内使用以下受控分支：`ReferenceInput -> StructureInspecting -> EmbeddedAssetMatching -> LayoutInference -> SemanticInference -> InferenceReview -> Calibrating -> Committing`。`ReferenceInput` 接受带参考款成品 PSD 和对应源照片文件夹；`EmbeddedAssetMatching` 用本地内容/结构证据确定具体参考照片；`LayoutInference` 本地提取几何；`SemanticInference` 使用真实 AI 或同版本有效缓存形成开放式动态选图要求；`InferenceReview` 必须由用户确认或修正后才能进入模板提交。没有充分手写规则时，AI 不可用、结果未知、合同不兼容、匹配失败、外部链接不可读、结构不可复用或 JPG 输入均不得绕过人工复核或提交。

| 转换 | 守卫与幂等 | 失败/恢复 |
| --- | --- | --- |
| `Draft -> ImportingCopy` | 源路径通过 `IPathPolicy`；以源 hash + 导入意图去重 | 只删除未提交内部临时副本，源 PSD 不变 |
| `ImportingCopy -> StructureInspecting` | 内部副本长度/hash 与只读源一致 | 校验失败隔离副本，不创建修订 |
| `StructureInspecting -> FrameBinding` | 页面结构可读；不把全部智能对象当图片框 | 不明确目标要求用户选择图层/候选 |
| `FrameBinding -> Calibrating` | 每个注册框有结构证据和稳定 `frame_id` | 绑定失败仅影响当前新增/受影响页 |
| `Calibrating -> AwaitingReview` | 正确示范、布局意图和带来源/版本/置信度的动态 `selection_requirement` 已形成 | 无充分手写规则时，AI/有效缓存缺失或推断未确认不得进入提交 |
| `AwaitingReview -> Committing` | 所有启用页的必需图片框完整；增量修订保持原页 ID/规则 | 可返回校准；旧 `current_revision_id` 不变 |
| `Committing -> Committed` | 文件 manifest 原子提交与 SQLite 事务均成功 | 任一失败回滚新修订指针；旧批次继续旧快照 |

### 8.2 批次和页面状态

批次状态至少包括：`Draft`、`Scanning`、`Analysing`、`ManualReview`、`PlanClosed`、`Preflighting`、`PreflightBlocked`、`ReadyToRender`、`Rendering`、`PauseRequested`、`PausingAfterProduct`、`Paused`、`UserActionRequired`、`Completed`、`CompletedWithIssues`、`Cancelled`、`RecoveryRequired`、`Failed`。款式状态至少包括：`Pending`、`Analysing`、`ReadyToRender`、`Rendering`、`Succeeded`、`CompletedWithIssues`、`NeedsRepair`、`Cancelled`、`RecoveryRequired`、`Failed`。页面状态至少包括：`Pending`、`Green`、`Yellow`、`Red`、`CancelledByUser`、`Rendering`、`Succeeded`、`RuntimeFailed`、`NeedsRepair`。

“零输出”只表示当前批次或款式没有正式 JPG/PSD，不等于所有任务均运行失败，也不是完成状态。用户主动取消全部页面时，经确认后批次进入 `Cancelled`；全部页面因缺素材、来源冲突或结构不可靠等业务问题为红时进入 `UserActionRequired`，允许应用内手动填图/重新绑定后重生成、受控 Photoshop 当前页编辑回写、重试或取消；单款业务零输出只隔离该款为 `NeedsRepair`，不阻塞其他款。全部页面因 bridge、Photoshop、磁盘、数据库或进程故障失败时，根据可恢复性进入 `RecoveryRequired` 或 `Failed`，不得混入业务红页或一律要求手动填图。`CompletedWithIssues` 只用于已经存在至少一个正式成功输出但仍有未解决、已取消或运行失败页面的情形，不能用于零输出。

关键批次转换如下；未列出的跨状态跳转全部拒绝：

| 转换 | 守卫 | 幂等/恢复证据 |
| --- | --- | --- |
| `Draft -> Scanning` | 模板修订、输入/输出根和页面选择已确定 | `batch_id + scan_intent_digest` |
| `Scanning -> Analysing` | 输入结构为单款或正常批次，资产 manifest 已提交 | `asset_inventory_digest` |
| `Analysing -> ManualReview\|PlanClosed` | 渐进结果 schema 有效；人工锁定版本不被覆盖 | `analysis_key + selection_revision` |
| `ManualReview -> PlanClosed` | 所有选择已保存；未解决红页保持红/取消，不伪装可生成 | `plan_close_revision` |
| `PlanClosed -> Preflighting` | 模板快照和资产/规则 digest 冻结 | `preflight_digest` |
| `Preflighting -> ReadyToRender\|PreflightBlocked\|UserActionRequired\|Cancelled` | 至少一页可执行才可 Ready；全业务红进入 UserActionRequired；全取消进入 Cancelled；两者均不启动 PS | 预检结果版本化持久化，取消必须有用户确认命令 |
| `ReadyToRender -> Rendering` | 安全接管、版本/能力、token、输出冲突确认全部通过 | `execution_id + plan_digest` |
| `Rendering -> PauseRequested -> PausingAfterProduct -> Paused` | 用户请求暂停；当前款安全收口 | 页面 checkpoint + 最后事件序号 |
| `Rendering -> Completed\|CompletedWithIssues\|UserActionRequired\|RecoveryRequired\|Failed` | 所有页均有终态；完成态至少一个正式成功输出；零输出按业务问题和系统/执行故障分因 | outputs/manifest/hash 三方一致，错误类别不可为空 |
| `Paused\|RecoveryRequired -> ReadyToRender` | 已成功页证据一致；未知页查询/确认完成 | 新 attempt，复用原 plan digest 或显式页级新计划 |
| 非终态 `-> Cancelled` | 用户明确确认取消范围；不删除既有正式输出 | `cancel_command_id` 去重 |

### 8.3 渐进 AI 分析和生成前检查

`Draft -> Scanning -> Analysing -> ManualReview(optional) -> PlanClosed -> Preflight -> ReadyToRender`。每款完成阶段即写 checkpoint 并刷新 B-03；人工锁定带版本号，异步写入使用 compare-and-swap。Key、授权、网络、路径、数据库或 Photoshop 错误是系统阻断/暂停，不伪装为页面红色。

生成前必须检查：模板快照、资产哈希、候选/锁定、页面选择、尺码结构、输出可写、协议/manifest 版本、磁盘基本可用、Photoshop 版本/握手，以及至少存在一个可执行页面；全业务红时进入用户处理，全取消时进入已取消，两者均不启动 Photoshop。

### 8.4 Photoshop 安全接管

`PlanClosed -> TakeoverChecking -> TakeoverReady -> Rendering`。检查未保存文档、未知弹窗、当前任务互斥、UXP 能力、端口/token、模板副本哈希和输出目录。未保存编辑或未知弹窗只允许用户处理后重新检查，禁止盲点确认。

### 8.5 暂停、恢复、失败隔离和单页修复

- `Rendering -> PauseRequested -> PausingAfterProduct -> Paused`：当前页面/款式完成后释放 Photoshop；不打断 modal 内页面。
- `Rendering -> PageFailed`：隔离当前页，清理临时产物，其他绿页继续；运行失败与生成前红页分开记录。
- `Result -> RepairDraft -> Previewed -> RegeneratingPage -> AtomicallyCommitted -> Result`：修复命令必须带 `batch_id/product_id/page_id`，不改模板修订、历史计划或其他输出。
- 尺码表修改只创建当前款尺码页计划，成功后原子替换该页，不触发整批 AI。

### 8.6 跨卷迁移和崩溃恢复状态表

迁移使用 `migration.journal` 和 `ready.marker`；文件 copy/校验、数据库提交和根路径指针切换均有独立阶段。

| 故障点 | 启动发现 | 处理 | 正式结果 |
| --- | --- | --- | --- |
| 复制中断 | journal=`copying`，ready 不存在 | 删除/隔离新位置临时目录，保留旧位置 | 继续旧位置，允许重试 |
| 校验失败 | `verify_failed` 或 hash 不符 | 隔离新位置，记录首个不符文件 | 继续旧位置，人工查看诊断 |
| 新位置 ready 后崩溃 | ready 存在，指针仍旧 | 校验 manifest 后提示恢复新位置或清理；默认不自动切换 | 旧位置仍可用 |
| 指针切换后崩溃 | 指针为新位置，DB 提交未完成 | 用 journal 恢复事务；不完整则回退旧指针 | 不产生半迁移状态 |
| 数据库提交后退出 | DB 已提交，文件 commit 未确认 | 以 outputs/manifest/hash 重建或标记 `RecoveryRequired` | 不重复覆盖，人工确认未知项 |
| 旧位置不可写 | 新位置完整但旧清理失败 | 保持新位置当前，旧位置保留并记录清理待办 | 不因清理失败回退结果 |
| 外置盘断开 | 路径不可达/句柄失败 | 暂停任务，等待重新连接，不删记录 | 恢复后从 checkpoint 继续 |
| 同名输出目标 | 本批次计划生成的目标路径已经存在 | 生成前列出冲突范围；用户选择其他目录，或明确确认只覆盖对应页面 | 每页原子替换已确认目标，目录内其他文件不变 |

用户已确认恢复采用页面级持久化检查点和原子提交，交互暂停采用款式级安全边界。启动恢复只跳过“正式输出存在、hash 正确、manifest 和 checkpoint 一致”的页；临时/不完整文件进入 quarantine 并记录原因；执行结果未知的当前页先查询 bridge/evidence，无法确定时只重做该页或要求人工确认，不盲目重提整款。源文件永不自动修复、移动或删除。

## 9. 接口与数据契约

### 9.1 UI 与应用层

UI 只调用命令并订阅只读投影：`CreateBatch`、`ScanBatch`、`StartAnalysis`、`LockSelection`、`FinalizePreflight`、`StartRender`、`RequestPause`、`CancelPendingProducts`、`RetryScope`、`RepairPage`、`EditSizeTable`、`MigrateStorage`、`ExportDiagnostics`。每个命令带 `correlation_id`、操作者意图、版本和幂等键；响应为 `Accepted/Rejected/NeedsConfirmation` 加用户可执行错误。

### 9.2 应用层与领域层

应用层调用纯领域服务：`DetectInputLayout`、`BuildBatchSnapshot`、`EvaluatePreflight`、`ComposeSizeTableLayout`、`BuildRenderPlan`、`ApplyRepairCommand`、`ReduceTaskEvent`。领域服务接收外部事实对象，不读文件、不发 HTTP、不持有线程。

### 9.3 AI 服务适配器

端口定义：`AnalyzeAssets(request, cancellation, consent)`、`ValidateResponse(raw)`、`EstimateUsage(raw)`、`RecordUsage(event)`。V1 火山方舟适配器负责 API Key 认证、压缩图上传、超时、429/5xx 映射和供应商响应转换；火山方舟 SDK/DTO、端点/模型 ID 和错误码不得越过 Infrastructure，领域层只看到供应商无关的版本化结构结果。`IAiCredentialSource` 的 V1 实现从 Windows Credential Manager 读取客户 API Key；后续实现读取项目方网关访问令牌。凭据只在请求作用域注入，不进入领域对象、日志、缓存或模板包。具体认证请求头或 SDK 注入方式必须依据采用的方舟官方接口冻结，不凭经验猜测。用量事件至少含模型配置版本、输入/输出计量、批次/请求 correlation、缓存命中和供应商返回费用摘要，但不得含业务图像内容；未来网关账单以服务端计量账本为权威，不能信任客户端自报费用。

供应商无关的请求合同草案如下；`analysis_copy_ref` 是应用内部引用，适配器只上传对应字节，不向供应商发送本地路径、客户目录名或模板 PSD：

```json
{
  "schema_version": "analysis-request/v1",
  "request_id": "req_01J...",
  "correlation_id": "corr_01J...",
  "analysis_kind": "product_semantics",
  "batch_id": "batch_01J...",
  "product_id": "product_01J...",
  "template_revision_id": "tplrev_01J...",
  "requirements_digest": "sha256:...",
  "requirements": [{
    "requirement_id": "requirement_01",
    "semantic_intent": "calibrated-requirement",
    "minimum_criteria": [],
    "layout_intent": "subject_complete"
  }],
  "assets": [{
    "asset_id": "asset_01",
    "content_hash": "sha256:...",
    "analysis_copy_ref": "internal://analysis/asset_01",
    "mime_type": "image/jpeg",
    "pixel_size": {"width": 1200, "height": 1600},
    "compression_profile_version": "pending-ai01"
  }],
  "consent": {"consent_id": "consent_01J...", "scope": "ai-analysis-copy"},
  "model_config_version": "volcark/doubao-seed-2.1-pro-260628/pending-ai01"
}
```

`pixel_size` 表示实际分析副本尺寸，正式 Schema 必须要求正整数；示例尺寸不构成压缩参数承诺。`analysis_kind` 只允许版本化能力类型，例如款内语义/候选、最终素材主体几何、尺码表提取；不得把服装角色作为能力枚举。响应合同至少包含：`schema_version`、`request_id`、`provider_request_ref`（脱敏）、`model_config_version`、`requirement_matches[]`（`requirement_id,asset_id,rank,confidence,evidence_codes`）、`variant_groups[]`（开放的 `dimension,value,asset_ids`）、`subject_geometry[]`、可选 `size_table_candidate`、`warnings[]` 和 `usage`。`evidence_codes` 只保存可解释标签/摘要，不要求或持久化模型隐藏推理过程。未知字段按版本兼容策略处理；缺少必需字段、引用未知资产/需求、重复 rank、越界坐标、非有限数值或非法尺码结构必须在进入 Domain 前拒绝。

缓存键为 `SHA-256(sorted asset content_hashes + analysis_kind + model_config_version + prompt_contract_version + response_schema_version + compression_profile_version + requirements_digest)`；缓存值同时记录 `consent_id`、创建时间、用量和来源。人工选择、页面状态或本地路径不进入内容缓存键；模板选图需求变化必须通过 `requirements_digest` 失效。每个请求先持久化 request ledger 和 fingerprint，再调用供应商；超时、最大请求体、重试次数与退避由 AI-01 配置版本冻结。只有官方合同证明安全或请求明确未被接受时才自动重试可能产生费用的调用；响应丢失且供应商状态未知时标记 `AiResultUnknown`，不得无限重发。

未来迁移时，桌面端将 `VolcArkAiAdapter + CustomerCredentialSource` 替换为 `ProjectGatewayAdapter + GatewayTokenSource`，内部 `AnalysisRequest/AnalysisResult/UsageEvent` 合同保持兼容；历史批次保留分析来源和模型配置版本，不自动重分析。客户原火山方舟凭据不得静默上传或迁移到项目方服务器。未来模型选择由网关返回受控模型目录并由服务器路由，不允许任意 Base URL/模型 ID 进入领域层。该设计使桌面端改动集中，但账号、租户隔离、鉴权、配额、服务端幂等、模型路由、用量账本、账单/支付、隐私政策和网关运维仍属于后续独立产品范围。

用户已确认：批次已完成 AI 分析、人工选择和生成前检查，且本地分析版本、模板快照、资产 hash 与计划完整一致时，可以在公网断开后继续纯本地 Photoshop 渲染、查看任务和模板管理；新的 AI 分析、未缓存的尺码识别和需要 AI 的自然语言动作进入 `WaitingForNetwork`。断网不自动切换模型/供应商，不使用过期或不完整结果；网络恢复后只继续未完成的 AI 项。本机 loopback bridge 不依赖公网。

### 9.4 RenderPlan 与 loopback bridge 契约

用户已确认采用 `127.0.0.1` 短生命周期 HTTP bridge，正式技术评审后记录 ADR；仅监听 loopback，不接受远程连接。推荐使用两阶段连接：安装范围固定的 loopback rendezvous 端口只负责发现/握手，延续现有 `17842` 证据但不接收 RenderPlan；握手成功后由桌面端返回本任务随机高位执行端口、`session_id` 和短期 `session_token`，后续计划、查询、心跳和释放只在随机执行端口完成。端口被占用时安全失败并诊断，不扫描或连接未知本机服务。

安装或首次配置必须建立每安装随机 `pairing_secret`：桌面端保存在 Windows Credential Manager，UXP 端保存在其受保护存储；不得把共享秘密写入插件代码、manifest、普通文件或日志。桌面端发出一次性 nonce，UXP 用 `HMAC(pairing_secret, nonce + session_id + plugin_manifest_version + photoshop_build)` 证明配对后才取得 session token。若 bootstrapper 无法依据 Adobe 正式机制可靠配置 UXP 受保护存储，则退回 F-01 中用户确认的一次性配对码流程并形成设计增补；不得发布无认证握手或以 plugin ID/版本号充当身份验证。配对存储、首次建立、重装/升级轮换和本机恶意进程抢占均为 ADR-013 前置【待技术验证】。

bridge 请求信封通用字段：`protocol_version`、`request_id`、`correlation_id`、`session_id`、`token`、`sent_at`、`idempotency_key`、`payload`。提交计划时 `payload` 包含已通过 Schema 的 renderer-neutral `render_plan`，以及本次 adapter 私有的 `resource_bindings[]`、`output_bindings[]`；绑定只把逻辑 resource/artifact ID 映射为经过根目录/hash/权限校验的 UXP session token 或目标卷暂存句柄，不改变 `plan_digest`，也不得返回领域层。响应通用字段：`ok`、`request_id`、`correlation_id`、`status`、`error`、`server_time`。错误结构固定为：

```json
{"code":"BRIDGE_PROTOCOL_MISMATCH","retryable":false,"scope":"session","user_action":"升级配套组件","details":{"expected":"ps-bridge/v1","actual":"..."}}
```

端点和边界：

| 端点 | 语义 | 幂等/超时 |
| --- | --- | --- |
| `POST /handshake` | 建立能力会话 | nonce 一次性；失败不重放 |
| `POST /plans` | 提交页/款式计划 | `idempotency_key` 去重；最大请求体由配置冻结并拒绝超限 |
| `GET /executions/{id}` | 断线查询执行状态 | 未知结果只能查询或人工确认 |
| `POST /executions/{id}/cancel` | 请求安全边界取消 | 已在 modal 内则返回 `accepted_at_boundary` |
| `POST /heartbeat` | 心跳和宿主状态 | 丢失进入 `BridgeDisconnected`，不自动重提计划 |
| `POST /release` | 释放会话/锁 | token 立即失效，重复调用安全 |

Token 只在单任务、单 Photoshop 实例和短期 TTL 内有效；成功释放、超时、桌面端重启、Photoshop/插件实例变化或 manifest 不匹配立即失效，刷新必须重新完成配对证明。计划提交前分别做 RenderPlan Schema、资源绑定根目录/hash/用途、输出绑定目标卷和结构校验；事件使用严格递增序号，重复事件由 `event_id` 去重。HTTP 断线、rendezvous/随机端口占用、配对秘密建立/轮换、UXP 权限、心跳和未知执行结果必须在首发 PS2025 客户构建实测；PS2022 不再是首发前置目标。

### 9.5 本地数据和文件系统接口

所有路径通过 `IPathPolicy` 规范化并验证：必须位于用户选择的输入/模板/输出根目录或应用内部目录；拒绝 `..`、符号链接逃逸、设备路径和未授权扩展名。`IFileStore` 提供 `CopyToInternal`、`HashReadOnly`、`WriteAtomic`、`CommitOutput`、`Quarantine`；SQLite 仓储提供事务和迁移，不让 UI 直接访问文件。

### 9.6 错误码、超时、重试和幂等

错误码按域分组：`INPUT_*`、`TPL_*`、`AI_*`、`SIZE_*`、`PREFLIGHT_*`、`BRIDGE_*`、`PS_*`、`STORAGE_*`、`SECURITY_*`。每个错误包含 `retryable`、`scope`、`user_action`、`correlation_id`，日志中的 `details` 脱敏。

可有限指数退避的边界：网络短断、429、临时 5xx、bridge 短暂失联；不可自动重试：Key 无效、授权撤回、余额不足、结构不匹配、权限拒绝、未知弹窗、输入损坏。所有副作用以 `idempotency_key + plan_digest + checkpoint` 去重；Photoshop 未确认执行完成时只查询/人工确认。

## 10. 数据与文件安全

### 10.1 推荐目录结构

```text
<data-root>/
  app-state/app.db
  templates/<group>/<revision>/manifest.json + copies/
  batches/<batch>/manifest.json + jobs/ + checkpoints/
  cache/thumbnails/ analysis/  (可清理，按引用保护)
  temp/<task>/  quarantine/<timestamp>/  diagnostics/  (仅可重建中间物)
<user-selected-output>/
  .app-staging/<batch>/<page>/<attempt>/  (目标卷内暂存，提交后清理)
  <product>/...  (正式输出，不由应用全量清理)
```

源 PSD、源图、市场尺码图和人工结果保持原路径只读引用，不复制进诊断包或安装包；内部副本和输出使用 ACL、规范化路径和 hash。

### 10.2 原子写入、迁移和清理

用户已确认 V1 的任务数据、模板库、缓存和工作目录支持本机固定盘及用户主动选择的外置盘，不支持网络盘/NAS。数据迁移的同卷写入为临时文件 -> flush -> SHA-256 -> 原子替换；跨卷为复制 -> 全树校验 -> ready marker -> 数据库事务 -> 指针切换 -> 延迟清理旧位置。外置盘断开时暂停并等待重新连接，不暗中回退到 C 盘或建立用户未知副本；非空迁移目标不自动覆盖或清理。清理缓存不删任务人工选择和输入摘要；JPG-only 临时 PSD 在无恢复引用且正式 JPG 已提交后才可删。任何清理失败都不覆盖正式输出。

正式 JPG/PSD 不得从可能位于其他卷的 `<data-root>/temp` 直接“原子移动”到输出目录。`IOutputCommitter` 必须先在目标输出卷的 `.app-staging/<batch>/<page>/<attempt>` 写入该页全部制品，逐个 flush、读回长度/hash 和 ICC/PSD 基本结构，再按已确认的目标清单替换单个文件；全部文件成功后最后写入页级 commit marker，并在同一事务中推进 manifest/checkpoint/SQLite。结果 UI 和恢复逻辑只承认 marker、manifest、hash 与数据库一致的页面为正式成功。多制品无法获得文件系统级整体原子性，因此替换旧文件时使用短期备份/恢复 journal；任一步失败或崩溃均恢复旧文件或进入 `RecoveryRequired`，不会暴露混合新旧页面。目标卷暂存命名、Windows `File.Replace`/rename 行为、FAT/exFAT/NTFS 和外置盘拔出点必须故障注入验证。

输出目录可以包含其他文件；系统只计算本批次将生成的目标路径。同名冲突必须在生成前展示现有路径和本次目标，用户只能选择其他目录或明确确认覆盖对应页面。确认后也只允许按页原子替换已列出的同名 JPG/PSD，不删除、重命名或覆盖目录内其他文件；O-02/O-03 仅可原子替换当前任务已登记的当前页输出。

用户已确认业务数据不自动删除：模板和任务记录只能由用户主动删除，正式 JPG/PSD 永远不由应用自动删除；AI 分析缓存只在用户从设置页明确清理并看到“重新分析可能产生费用”提示后删除，活动任务或恢复引用的缓存必须保留。只有启动恢复完成后确认无任务引用的失败临时文件可以隔离/删除，脱敏技术日志可按大小/时间滚动。外置盘暂时离线不能被解释为文件已丢失或可清理。

### 10.3 安全威胁模型与控制

| 威胁 | 控制 | 证据 |
| --- | --- | --- |
| API Key 泄露 | Windows Credential Manager/DPAPI；不进 DB 明文、日志、包 | SET-01、secret scan |
| AI 误上传源文件 | 只允许分析副本；上传前 consent、尺寸和 MIME 检查 | AI-01、网络审计 |
| loopback bridge 被本机进程调用 | 随机端口、短期 token、nonce、协议/请求体校验、loopback 限制 | bridge 契约测试 |
| 路径穿越/符号链接 | 真实路径解析、根目录白名单、拒绝设备路径和外部扩展名 | 安全单测 |
| 用户文件破坏 | 源文件只读、内部副本、前后 hash、输出非空保护 | 故障注入 |
| SQLite/缓存泄露 | ACL、最小字段、缓存引用保护、清理前清单 | DATA-01 |
| 日志泄露 | 结构化脱敏、禁止 Authorization/完整 URL/图像内容 | 诊断包扫描 |
| 第三方依赖/CVE | 锁定版本、依赖审计、SBOM、发布前漏洞门 | 发布报告 |
| 安装包/UXP 篡改 | 制品独立签名与 hash、manifest/plugin ID 校验、统一 bootstrapper 编排 | 发布验收 |

### 10.4 隐私、授权和诊断

首次启用 AI 明确说明上传压缩图范围、用途和撤回影响；撤回后阻断新请求，已有本地结果不删除。诊断导出前显示白名单/黑名单并再次扫描，默认不自动上传。诊断包包含软件/Photoshop/UXP 版本、协议、脱敏设置、错误码、阶段耗时、队列指标和 hash 摘要，不包含 Key、PSD、源图、尺码图、输出或分析缩略图。

## 11. 并发与资源控制

### 11.1 AI 并行和背压

目录扫描/缩略图、款式分析、单图主体分析、尺码提取采用分层有界队列；待处理项只存文件引用。初始并发值、缩略图最长边、批大小和重试次数均是候选测试参数，必须用 AI-01 金标、费用和延迟数据冻结，当前不把“最多 4 个在线请求”当成承诺指标。CPU、内存、网络和供应商限流取小值；达到阈值暂停生产者并提示。

### 11.2 Photoshop 单通道

只有 `PhotoshopExecutionGate` 持有 UXP 执行资格；准确预览、正式渲染和单页 PSD 编辑互斥。一次尽量提交页面/款式计划，降低 bridge 往返。页面内不支持强制中断，取消在安全边界生效。

### 11.3 多 Photoshop 版本

设置页可检测和选择已验证版本；一次只绑定一个 `photoshop_instance_id`。开始渲染后版本冻结；已有分析任务不要求 Photoshop。支持矩阵必须区分“已验证试点构建”“待验证目标范围”“不承诺版本/改版包”，不能把 `23.3+` 宣称为已支持全部版本。

## 12. 非功能实现方案

### 12.1 五分钟性能预算和测量

PRD 的 300 秒是外部硬门。用户已确认正式口径为完整生产机器时间：应用已打开且输入目录/模板已选定，从点击“扫描并分析”开始，到约 70 张正式 JPG 全部完成原子提交为止。计时包含目录扫描/缩略图、空缓存首次 AI 分析及响应校验、页面组合/预检、Photoshop 检测/安全接管、RenderPlan 执行、JPG 导出、ICC 读回、文件 hash 和原子提交；不包含用户停留、人工选图、手工尺码纠错或人工 Photoshop 编辑时间。

空缓存结果是正式主证据，缓存命中另组记录；应用/Photoshop 冷启动作为单独观察指标，不替代正式口径。内部目标建议先压到约 240 至 250 秒，以留出异常、重试和环境波动余量，但该数值标记【待技术验证】，不是已验证承诺。首轮测量记录各分段 wall-clock、P50/P95、CPU/内存峰值、网络请求和缓存命中，多次重复并保留全部原始结果，不以最快一次收口。环境、样本、模型/参数、Photoshop 构建必须完整可复现；PSD 批量另行报告。

### 12.2 日志、指标和诊断

日志分为用户事件、技术日志和安全审计日志。指标至少包括批次/款式/页面耗时、AI 请求/缓存/重试/费用估算、队列深度、PS modal 时间、ICC 后处理、输出提交、失败清理、恢复跳过数、内存峰值和 bridge 心跳。维度使用 `correlation_id/task_id/product_id/page_id/frame_id` 和脱敏路径。

统一事件字段为：`event_schema_version,event_id,occurred_at,level,category,event_name,app_version,correlation_id,task_id,product_id,page_id,frame_id,stage,duration_ms,outcome,error_code,retryable,metrics,redacted_details`。所有 ID 可空但字段语义稳定；禁止记录 API Key、认证头、图片字节、Prompt 原文中的客户内容、完整本地路径或供应商原始响应。路径只保存根类型、扩展名、长度和不可逆摘要；异常对象必须先经过 allowlist redactor，再进入滚动日志。

诊断包由用户主动导出，先生成可见清单再确认。`diagnostics-manifest.json` 至少包含 `schema_version,package_id,created_at,app_version,os_build,photoshop_build,uxp_manifest_version,protocol_version,included_files[]`（相对路径、类型、长度、SHA-256、隐私分类）、`excluded_categories[]` 和 `redaction_version`。导出器采用 allowlist，只允许版本/支持矩阵、脱敏设置、错误码、阶段耗时、队列指标、迁移/恢复摘要和技术日志；打包后执行 Key/认证头、绝对路径、媒体扩展名和高熵 secret 扫描，任何命中均阻断导出而不是仅告警。

### 12.3 可访问性和窄窗口

所有 WPF 控件提供 `AutomationProperties`、稳定 AutomationId、键盘焦点和可见焦点环；状态不能只靠颜色，拖拽、候选换图和文件选择有键盘/按钮后备。1100x760 时导航、标题、摘要、列表、底部任务栏和弹窗不遮挡；校准、修复、尺码画布可收起侧栏但不覆盖，长列表虚拟化，缩略图/行/按钮采用稳定尺寸。必须测试中文 IME、读屏、Tab 顺序、100%/125% DPI 和长路径。

### 12.4 安装、升级、回滚和发布

用户已确认 V1 采用**当前 Windows 用户范围的签名 bootstrapper**：WPF 桌面端按 `.NET 10 x64` 自包含方式安装到当前用户的应用目录，正常安装、升级和卸载尽量不要求管理员权限，不建设全机共享安装。桌面应用与 UXP `.ccx` 是独立版本、独立校验的制品，但必须由同一个安装入口编排，不能要求客户自行判断和拼装版本；bootstrapper 可按 Adobe 支持的机制调用或引导 `.ccx` 安装，并在结束前执行 plugin ID、manifest、RenderPlan/bridge 协议兼容检查。安装包不包含 Photoshop 本体、用户 PSD、源图、输出、缓存或 Key。安装/升级流程：环境检查 -> 签名桌面包按用户安装 -> 调用或引导配套 `.ccx` 安装 -> 版本兼容检查 -> 首次 bridge 能力探针 -> 可生产标记。

“尽量无管理员权限”是交付目标而不是未经验证的兼容承诺；Windows、Creative Cloud 或 Photoshop 在 `.ccx` 安装时出现的登录、确认或权限提升必须如实展示，不得绕过系统安全机制。是否能在目标客户机上全程免 UAC、`.ccx` 能否由 bootstrapper 自动拉起、失败后如何回滚桌面端与插件的配套版本，均列为发布前【待技术验证】。若 Adobe 正式机制不允许完全自动化，则使用同一安装向导中的明确人工确认步骤，并以首次 bridge 探针作为最终成功判据。

用户已确认 V1 采用封闭小范围内测：软件安装在客户自己的电脑上，由项目方现场或远程协助安装；不进入应用商店、不公开下载、不实现后台自动更新。每次试点交付提供配套的桌面安装包、UXP `.ccx`、版本兼容清单、SHA-256、安装/卸载说明、已知限制、上一稳定版本回滚包和技术支持入口。定向交付不降低客户电脑上的签名、来源可验证、数据保护和卸载保留要求。

现有 UXP 证据分层如下：验证插件使用 Manifest v5、ID `local.ecommerce.uxp-validation`、版本 `0.4.7`，已通过 UXP Developer Tool 选择 `manifest.json` 在开发者模式加载，并完成真实渲染、bridge、JPG/PSD、ICC 和恢复验证；测试电脑的 Creative Cloud 登录/邮箱验证也已排除。该证据证明执行能力，不证明正式 `.ccx` 的打包、客户机安装、升级、卸载或信任提示。生产插件不得沿用验证探针名称/ID，`network.domains: "all"` 也不得进入发布包；正式 ID/名称、最小权限、`.ccx` 私有分发和无需 Developer Tool 的客户安装路径列为发布前【待技术验证】，不再要求产品负责人凭空确认“Adobe 开发者账号”。

升级需独立维护应用版本、UXP manifest 版本、RenderPlan 协议版本和数据库 schema 版本；不兼容时暂停任务，不降级执行。V1 由项目方定向发送新版本并协助升级，不做后台静默更新；应用文件替换失败可回滚旧版本，用户数据、模板库、任务库和输出路径保留。用户已确认普通卸载只移除桌面程序和 UXP 插件，默认保留模板、任务记录、应用数据和正式输出；只有用户明确选择“同时删除本地数据”并再次确认时，才删除应用自有数据库、缓存、临时文件和内部模板副本。源 PSD、源图、市场尺码图、人工结果和正式输出永远不由卸载器自动删除。发布清单包含签名、SHA-256、SBOM、CVE 审计、支持矩阵、已知限制、变更记录和脱敏安装日志。

### 15.7 AI 分析批量与桌面预览性能补充（2026-09-09）

真实目标款复测暴露了实现层性能问题：WPF 结果列表直接绑定原图路径会按原尺寸解码；`StartAsync` 等待全部款式完成副本准备后才启动消费者。按 `ADR-023` 修正后，AI admission 与消费者并行，准备好一款即可进入有界 ready queue，provider worker 完成一款立即从 durable pending 补位。

本补充不改变 V1 运行保护参数：单请求最多 24 张、ready buffer 32、HTTP 并发 8、WIC 副本准备最多 2 路、请求体 16 MiB、adapter 超时 180 秒、重试/预算/`AiResultUnknown`/lease/checkpoint 边界均保持不变。100 款是持久化队列容量的业务压力场景，不是 100 路同时提交；队列只保存结构化元数据和应用副本引用，不保存原图字节。

WPF 批量列表、候选列表和人工学习照片预览使用有界缩略图与有限缓存，不能因列表规模持有原始 RGBA 图像。超过 24 张必须在副本准备或 HTTP 之前显示明确失败原因并保持 provider 请求数为 0。修正完成并取得约 100 款、内存和恢复证据前，`PERF-01` 仍为进行中，不能把离线测试或单款热运行外推为完整五分钟门通过。

### 15.8 真实多图请求体编码复核（2026-09-09，已修正）

真实批次复核补充了 15.7 的请求体边界证据：16 MiB 指最终序列化 JSON HTTP 请求体，不是每张图片的大小。一个 24 张真实款式批次的源文件合计 `115,669,269` 字节；旧 `wic-bounded/max1600/jpeg-q82/png/v1` profile 对 PNG 仍输出 PNG，Base64/JSON 构造后联合请求离线估算约 `51–53 MiB`，在 adapter 的 HTTP 前安全门被 `AI_PROVIDER_REQUEST_TOO_LARGE` 阻断，因而 6 个共享该联合请求的页面同时失败。

既有“24 张可进入调度”自动化只验证数量和调度，不验证真实 WIC 编码后的最终 JSON 体积。修正已采用版本化 `wic-bounded/max1600/jpeg-q82/png-opaque-jpeg/v2`：最长边 1600、JPEG q82、源 64 MiB、副本 8 MiB、100M 像素；无实际透明度的 PNG 转为 JPEG，含真实非不透明像素的 PNG 保留为 PNG。adapter 以最终 `JsonObject` 的 UTF-8 序列化字节数执行唯一请求体预检，超限返回 `AI_PROVIDER_REQUEST_TOO_LARGE`，不进入 HTTP，并投影明确的“未发送 AI 请求/减少照片后重新建立批次”动作。全新临时 runtime root 的真实 24 图离线回归为副本 `9,224,434` bytes、最终 JSON `13,113,521` bytes、24 张均 JPEG、fake HTTP 1 次，源文件 hash/长度不变。本补充不改变 16 MiB、24 张、ready 32、HTTP 8、WIC 2 路和未知结果边界；完整 `PERF-01` 仍保持进行中，不得用该回归替代正式 10 款 `machine_total`、Photoshop 或文件提交验收。

### 15.9 当前 AI 目标批次传输边界（2026-09-12，ADR-028）

15.7/15.8 的 24 张、180 秒、V2/V3 数值是当时的历史配置和证据，不代表新请求的当前默认。当前实现按请求用途分开设限：普通目标批次 `ai-analysis/v1` 最多 40 张；参考学习 `reference-learning-ai/v2` 最多 24 张。41 张目标素材或 25 张参考素材均在 provider 前拒绝，保持 HTTP=0。

新请求默认使用 `wic-bounded/max1280/jpeg-q82/png-opaque-jpeg/v4`：最长边 1280、JPEG q82；不透明 PNG 转 JPEG，真实透明 PNG 保留 PNG；V4 具有独立 fingerprint/cache 身份，源 PSD、源照片和正式输出只读不改。适配器构造最终 UTF-8 JSON 后执行 16 MiB（16×1024×1024）本地预算预检；16 MiB 是应用安全门，不是火山 API 硬限制。

单次 HTTP scope 的总墙钟为 300 秒，并采用分阶段上限：上传绝对 240 秒、上传无进度 90 秒、上传完成后响应头 120 秒、收到响应头后响应体 60 秒；每阶段同时受剩余总墙钟限制。上传未完成的超时/网络错误可按既有 scheduler 上限安全重试；上传完成后响应头或响应体失败仍为 `AiResultUnknown`，禁止自动重发。`HttpClient` 不设置早于上述边界的默认 timeout，迟到 task 由 adapter 后台观察并清理。当前值由 ADR-029 补充 ADR-028。

本补充只更新新请求的传输数值，不改变队列/并发/预算/费用、授权、缓存单调性、未知结果和 renderer-neutral RenderPlan 边界，也不回写旧请求、旧缓存、旧失败批次。完整 `PERF-01`、真实模型准确率、WPF 逐框走查和 Photoshop/文件提交仍需各自验收。
